`explain` shows, step by step, how CC Safety Net analyzes a command. Use it to learn why a command is blocked or allowed, or how a custom rule applies.

```bash
npx cc-safety-net explain "git reset --hard"
bunx cc-safety-net explain "git reset --hard"
```

## explain options

| Flag | Description |
| --- | --- |
| `--json` | Output the full analysis result as JSON |
| `--cwd <path>` | Analyze as if run from this working directory |
| `--shell <auto\|posix\|powershell>` | Read the command as this shell (default: `auto`) |
| `-h`, `--help` | Show help |

```bash
npx cc-safety-net explain "rm -rf /"
npx cc-safety-net explain --json "git checkout -- file.txt"
npx cc-safety-net explain --cwd /tmp "git status"
npx cc-safety-net explain --shell posix 'rmdir /s /q d:\'
```

See the [Explain trace reference](/reference/explain-trace) for the `--json` schema, the `ExplainResult` fields, and every `TraceStep` variant.

## Read the command as the shell your tool runs

`explain` defaults to the `auto` shell mode, which reads a command as PowerShell when it looks like PowerShell. Your agent's tool may run a different shell. Claude Code's `Bash` tool runs POSIX, so `auto` can report a verdict the hook never gave:

| Command | Result | Rule id |
| --- | --- | --- |
| `explain 'rmdir /s /q d:\'` | Blocked | `powershell.remove-item-root-or-home` |
| `explain --shell powershell 'rmdir /s /q d:\'` | Blocked | `powershell.remove-item-root-or-home` |
| `explain --shell posix 'rmdir /s /q d:\'` | Allowed | |

In bash, `rmdir` removes only empty directories, so the hook allows that call from the `Bash` tool. `--shell posix` reproduces the allow. The flag changes both how `explain` parses the command and which shell's rules apply to it, so pass the dialect of the tool whose decision you want to reproduce.

With `--shell powershell`, a command given as separate arguments is rejoined with PowerShell quoting, so an apostrophe in it is doubled instead of escaped the POSIX way. Every other dialect keeps POSIX escaping.

A value other than `auto`, `posix`, or `powershell` exits `1` with the error and the usage line:

```text
Error: --shell must be auto, posix, or powershell, got: bash
Usage: cc-safety-net explain [--json] [--cwd <path>] [--shell <auto|posix|powershell>] <command>
```

## Explain a command that starts with a dash

`--` ends option parsing, and everything after it is the command. So `explain -- --help` explains the literal command `--help` instead of printing help. Quote the command as one argument to keep shell operators such as `|` and `&&` in it.

## explain exit code

`explain` exits `0` for both blocked and allowed results, so read the `result` field instead of the exit code. It exits `1` on an option error, such as an unknown option, a `--cwd` path that does not exist, or an unknown `--shell` value, and on a command it refuses to analyze.

## Commands explain refuses to analyze

`explain` refuses a command that exceeds CC Safety Net's analysis limits, or whose syntax the parser rejects, such as `echo ${`. It exits `1` with a one-line error. With `--json`, stdout holds only an error object:

```bash
npx cc-safety-net explain --json 'echo ${'
```

```json
{"error":"Command could not be safely analyzed (strict mode). Simplify the command and retry, or ask the user to verify."}
```

When an agent runs such a command, CC Safety Net blocks it with a [fixed denial id](/reference/blocked-commands#fixed-denial-ids).
