CC Safety Net records each command decision in an audit log stored only on your machine. It never uploads the log. Each file is JSON Lines (JSONL), one JSON object per line. Read it in the [Dashboard](/guides/dashboard) or with [`logs`](/reference/cli/logs) in the terminal.

## Log layout

Records go to a per-project, per-month path:

```text
~/.cc-safety-net/logs/<encoded-cwd>/<YYYY-MM>/<YYYY-MM-DD>-<session-id>.jsonl
```

| Path part | What it is |
| --- | --- |
| `<encoded-cwd>` | The working directory with every non-alphanumeric character replaced by `-`, or `no-cwd` when there is none |
| `<session-id>` | The agent session id, with unsafe filename characters replaced |

`CC_SAFETY_NET_AUDIT_HOME` changes the home directory that contains the audit root. CC Safety Net creates directories with mode `0700` and files with mode `0600`. A failed write never changes an allow or block decision.

Flat `*.jsonl` files directly in `~/.cc-safety-net/logs/` are the legacy layout from earlier versions. `logs` still reads them and retention still deletes them; to remove them now, see [`logs --prune-legacy`](/reference/cli/logs#delete-legacy-log-files).

## Each record contains one decision

Each line records one allowed or blocked command decision: the command, the segment that drove the decision, the reason, and the rule that matched.

- CC Safety Net never reads or stores command output, model prompts, tool results, or conversation content.
- CC Safety Net always records denials.
- It records allowed decisions only for command tool calls. An allowed file edit or read produces no record.
- It also records blocks from the fail-closed path. These happen when analysis fails and CC Safety Net blocks the command because it cannot reach a verdict. The `failureStage` and `errorCode` fields mark them, and `logs --suspect` uses those fields.

## Record schema

| Field | Type | Presence | Description |
| --- | --- | --- | --- |
| `ts` | string | always | ISO 8601 timestamp of the decision |
| `id` | string | always written | 16 hex characters. This is the id `logs --id` takes |
| `v` | string | optional | The CC Safety Net version that wrote the record, or `dev` |
| `sessionId` | string | optional | The sanitized agent session id |
| `decision` | `"allow" \| "deny"` | optional, defaults to `"deny"` | The decision |
| `agent` | string | optional | The integration id, for example `claude-code` |
| `shape` | string | optional | The adapter input shape the record came from |
| `level` | string | optional | The effective safety level in force at decision time |
| `configFallback` | `true` | optional | Present when the decision ran against a fallback policy |
| `toolName` | string | optional | The tool name |
| `command` | string | always | The full command, redacted |
| `segment` | string | always | The segment that drove the decision, redacted |
| `truncated` | `true` | optional | Present only when a long field was cut |
| `reason` | string | always | The human-readable decision reason |
| `ruleId` | string | deny records | The id of the rule or [fixed denial](/reference/blocked-commands#fixed-denial-ids) that blocked the call. Absent on allow records, on the Copilot CLI deny `Failed to parse toolArgs JSON.`, and on some deny records that earlier versions wrote |
| `intent` | string | optional | The block intent classification |
| `failureStage` | string | optional | Set when the denial came from a check that failed closed |
| `errorCode` | string | optional | One of `path-canonicalization-limit`, `tool-input-limit`, `structural-shell-syntax-limit`, `unparseable-command`, `unexpected-error` |
| `cwd` | string \| `null` | optional | The working directory, redacted |

Example record:

```json
{"ts":"2025-01-15T10:30:00.000Z","id":"3fa9c2d1a70e8b42","v":"2.0.0","sessionId":"a1b2c3","decision":"deny","agent":"claude-code","level":"standard","command":"git reset --hard","segment":"git reset --hard","reason":"git reset --hard destroys all uncommitted changes permanently. Use 'git stash' first.","ruleId":"git.reset-hard","cwd":"/path/to/project"}
```

CC Safety Net cuts long `segment`, `toolName`, and `cwd` values and sets `truncated: true` on the record. It cuts a long `command` the same way, except on a record with a `failureStage`, which keeps the whole command. It never writes the flag as `false`.

### failureStage values

`failureStage` names the check that failed closed. The checks run in the order on [How it works](/guides/how-it-works#what-gets-checked-in-order).

| `failureStage` | Where the failure happened |
| --- | --- |
| `policy-protection` | Reading the tool input within its size limits, policy-file protection, or Git-metadata protection |
| `command-validation` | Validating the command: a declared command tool's working-directory argument, the limits on input length, word count, and nesting, or an empty command |
| `config-load` | Loading the policy and resolving the safety level |
| `secret-protection` | Sensitive-path protection |
| `non-command` | Handling a tool call that is not a command |
| `command-analysis` | Destructive-command analysis, including the declared-command recursion limit |

A denial from input limits, a declared command tool's check, policy-file protection, or Git-metadata protection happens before the policy loads. Its record carries no `level` and no `configFallback`.

## What is recorded: audit scope

`CC_SAFETY_NET_AUDIT_SCOPE` decides whether allowed command decisions join the denials in the log.

| Value | Effect |
| --- | --- |
| unset | The default, which behaves like `all` |
| `all` | Record both allowed and blocked command decisions |
| `blocked` | Record denials only. This setting keeps the least data |
| anything else | Record denials only, and [`doctor`](/reference/cli/doctor) reports `environment.audit-scope-invalid` |

The scope never suppresses denials. It only decides whether CC Safety Net records allowed decisions.

## Retention

| Setting | Value |
| --- | --- |
| Default retention | 30 days |
| Configurable range | 1 to 365 days |
| Config key | `audit.retention_days` in `policy.json` |

See [Audit retention](/configuration/policy#audit-retention) for how CC Safety Net handles invalid values. The same value is the maximum for `logs --since` and limits the windows the Dashboard Activity view offers.

CC Safety Net deletes expired records the next time it runs: after it writes a record, or before `logs`, `doctor`, or the Dashboard reads the log. Nothing runs on a timer, so expired records can stay on disk while CC Safety Net is idle, and `logs --id` can still find them.

<Warning>
  Shortening retention is irreversible. Lowering the value makes older records eligible for deletion on the next run, and CC Safety Net deletes them with no archive, trash, or undo. The Dashboard asks you to confirm before lowering the value.
</Warning>

## Secret redaction

CC Safety Net redacts the command, segment, tool name, and working directory before it writes the record. It replaces these recognized values with `<redacted>`:

- Environment assignments whose name contains `TOKEN`, `SECRET`, `PASSWORD`, `PASS`, `KEY`, or `CREDENTIALS`
- Database connection variables (`DATABASE_URL`, `POSTGRES_URL`, `MYSQL_URL`, `REDIS_URL`, `MONGODB_URL`, and other DSN/URL/URI/connection-string variables)
- PEM private key blocks (`-----BEGIN ... PRIVATE KEY-----`)
- Secret-bearing HTTP headers (`Authorization`, `Cookie`, `X-API-KEY`, `API-KEY`)
- URL credentials (`scheme://user:pass@host` and `scheme://token@host`) and `-u user:pass`
- Presigned-URL signature query parameters: the values of `x-amz-signature`, `x-goog-signature`, `sig`, and `signature`
- A fixed list of provider token formats (`ghp_...`, `gho_...`, `xoxb-...`, `npm_...`, `sk_live_...`, `rk_live_...`, `pypi-...`, and similar)
- JWTs (`eyJ...`) and AWS access key IDs (`AKIA...` / `ASIA...`)

<Warning>
  Redaction is bounded. It is a fixed list of patterns, not a classifier. It keeps everything else verbatim: absolute filesystem paths, project and directory names, hostnames, IP addresses, usernames, ticket ids, filenames, and any credential whose shape is not on the list. CC Safety Net does not redact the `reason` field. Treat the audit log as sensitive local data, and review any excerpt before pasting it into an issue or a chat.
</Warning>

File permissions limit who can read the log. They do not redact it or make it safe to share.
