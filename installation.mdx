Run `npx -y cc-safety-net@latest install` and pick your coding agents from the list. The installer adds CC Safety Net to each agent you pick as a plugin, extension, or hook. Some agents then need a restart or a trust confirmation. Run `npx cc-safety-net doctor` to confirm that protection is active.

## Before you install

- Install Node.js 22 or later. The commands on this page use `npx`. Node.js 18 and 20 have reached end of life, and CC Safety Net no longer supports them.
- Check that your platform is supported for your agent:

| Platform | Agents |
| --- | --- |
| Windows, macOS, and Linux | Every agent except the ones below |
| macOS and Linux only | [Hermes Agent](/installation/hermes-agent), [OpenClaw](/installation/openclaw) |
| Web profile on all three, Desktop app on macOS and Windows | [DeepSeek Harness](/installation/deepseek-harness) |

Amp's own manual documents macOS, Linux, and WSL rather than native Windows.

## Install with the interactive picker

<Steps>
  <Step title="Start the installer">
    ```bash
    npx -y cc-safety-net@latest install
    ```

    The installer lists the coding agents it finds on your machine.
  </Step>
  <Step title="Select your agents">
    Press `Space` to select an agent and `Enter` to confirm. [Target selector keys](/reference/cli/install#target-selector-keys) lists the other keys.
  </Step>
  <Step title="Finish the agent's own step">
    If your agent needs a restart or a trust confirmation before the hook runs, do that now. The "Extra step" column in [Install for one agent](#install-for-one-agent) lists these steps.
  </Step>
  <Step title="Confirm protection is active">
    ```bash
    npx cc-safety-net doctor
    ```
  </Step>
</Steps>

[`doctor`](/reference/cli/doctor) checks every supported agent and tells you how to fix anything that fails.

Keep `@latest` in the install command. npx keeps downloaded packages in a cache, and a bare `cc-safety-net` can re-run an older copy from that cache instead of the current release.

## Update CC Safety Net

```bash
npx -y cc-safety-net@latest update
```

`update` refreshes every integration already installed on your machine and never installs a new one. See [`update`](/reference/cli/update) for what it does per agent.

### Upgrade from v1 or from 2.2 and earlier

- **From v1.** Run `update` to move every installed integration to the current release. If you defined custom rules in v1's inline configuration, complete the [legacy migration](/configuration/custom-rules#migrate-legacy-configuration). Then confirm the runtime is `ready` with `npx cc-safety-net doctor`.
- **From 2.2 or earlier, with rulebooks from GitHub.** After upgrading, run [`rule sync`](/reference/cli/rule#rule-sync) once per scope. Add `--global` for user-scope sources. Until you run it, those rules are inactive, and `status` and `doctor` report the degraded sources.

## Uninstall CC Safety Net

Run the installer's uninstall picker, or pass one target flag:

```bash
npx -y cc-safety-net@latest uninstall
npx -y cc-safety-net@latest uninstall --cursor
```

Uninstall removes only what CC Safety Net manages. Each agent's page lists what its uninstall removes.

## Install the CLI globally

If you run the CLI often, install it globally. The global install adds `ccsn`, a shorter alias for the same commands:

```bash
npm install -g cc-safety-net
ccsn doctor
```

The alias comes only with the global install. `npx` runs use the full `cc-safety-net` name.

## Migrate from a legacy plugin identifier

In older releases, Claude Code and Codex used the plugin identifier `safety-net@cc-marketplace`, and GitHub Copilot CLI used `copilot-safety-net`. The normal install command for the agent removes the old plugin, so you do not need to remove it by hand. Use the current identifier, `cc-safety-net@cc-marketplace`, in new configuration.
