最小のチームセットアップは、全メンバーに CC Safety Net をインストールしてもらうことです。フックをインストールしたメンバーは、作業するすべてのリポジトリが自分のユーザーポリシーにより standard プリセットで保護されます。リポジトリ側の設定は要りません。必要なら `.cc-safety-net/` 配下にプロジェクト設定をコミットして、どのクローンでもプリセットを統一したり、カスタムルールや保護対象パスを追加したりできます。

## 全メンバーへのインストールを徹底する

各メンバーはマシンごと・エージェント CLI ごとに 1 回フックをインストールします。リポジトリごとに繰り返す必要はありません。

```bash
npx -y cc-safety-net@latest install
```

対話式セレクターがインストール済みのエージェント CLI を検出します。`--claude-code`、`--codex`、`--cursor` などのターゲットフラグを付ければ、1 つを非対話でインストールできます。`npx -y cc-safety-net install --help` ですべてのフラグを一覧できます。

### インストールの自動化

プロジェクトがすでに実行しているセットアップ手順に、インストールを組み込んでください。npm の `postinstall` スクリプト、`Makefile` や `justfile` のセットアップターゲット、dev container の `postCreateCommand`、`mise` のタスクなどです。セットアップ手順のないプロジェクトでは、ワンライナーをオンボーディング文書に載せます。

たとえば npm プロジェクトでは次のようにします。

```json
{
  "scripts": {
    "postinstall": "node -e \"process.env.CI || require('child_process').execSync('npx -y cc-safety-net install --claude-code', {stdio: 'inherit'})\""
  }
}
```

`process.env.CI` ガードにより、CI ではインストールをスキップします。CI でエージェントのフックを入れても無駄になるためです。ターゲットフラグはチームが使うものを選んでください。複数のエージェント CLI を使うチームなら、対話式のワンライナーを文書化します。

## リポジトリの保護を統一する（任意）

メンバー自身のポリシーが、standard プリセットですでに破壊的コマンドとシークレットへのアクセスをブロックしています。`.cc-safety-net/` 配下に設定をコミットするのは、特定のプリセット、カスタムのブロックルール、追加の保護対象パスをチームが求めるときだけです。コミットできるものは 2 つあります。

- **`.cc-safety-net/policy.json`**：各メンバーのユーザーポリシーの上に重なる、必要なフィールドだけを書いたプロジェクトポリシーです。安全プリセット、組み込み保護の切り替え、ルール単位のオーバーライド、追加の保護対象パスを設定します。マージの仕様は[ポリシー](/ja/configuration/policy#project-policy)を参照してください。
- **`.cc-safety-net/rules/rule.json` と同じ場所のルールブック**：プロジェクトのカスタムルールを収めます。ルールブックファイルは通常のコミット済みファイルなので、チームメイトは何も実行せずに受け取れます。形式は[カスタムルール](/ja/configuration/custom-rules)を参照してください。

<Steps>
  <Step title="プロジェクトポリシーをコミットする">
    チームで共有したいポリシーのフィールドを提案ファイルに書き、検証してから適用します。

    ```bash
    npx -y cc-safety-net policy check proposal.json
    npx -y cc-safety-net policy apply proposal.json
    ```

    `policy apply` は、ターミナルで差分を確認した後に `.cc-safety-net/policy.json` を書き込みます。詳しくは [`policy`](/ja/reference/cli/policy) を参照してください。`npx -y cc-safety-net gui` の Protections 画面でもプロジェクトポリシーの下書きを作れます。設定するのはチームで統一したいものだけにしてください。それ以外のフィールドは、引き続き各メンバーのユーザーポリシーを継承します。
  </Step>
  <Step title="プロジェクトルールを追加する">
    [公式ルールブック](/ja/configuration/rulebooks)をプロジェクトスコープに導入し、プロジェクト固有のルールがあれば作成します。

    ```bash
    npx -y cc-safety-net rule add cc-safety-net/rulebooks --only terraform aws
    ```

    `--global` を付けなければ、`rule add` はリポジトリの `.cc-safety-net/rules/` 配下にルールブックファイルを書き込みます。
  </Step>
  <Step title="コミットして検証する">
    `.cc-safety-net/` ディレクトリをコミットします。プッシュする前に、このチェックアウトで期待どおりにブロックされることを確認してください。

    ```bash
    npx -y cc-safety-net status
    npx -y cc-safety-net rule verify
    npx -y cc-safety-net explain "terraform destroy"
    ```
  </Step>
</Steps>

## メンバーから見えるもの

CC Safety Net はプロジェクトポリシーを書かれたとおりに適用し、メンバーのユーザーポリシーより緩めたフィールドをすべて報告します。[報告される緩和](/ja/configuration/policy#reported-weakenings)を参照してください。メンバー側には次の境界が保たれます。

- **ユーザーポリシーはメンバーのものです。** プロジェクトファイルはその上に重なるだけです。未設定のフィールドは継承され、メンバーはプロジェクトの基準より厳しいユーザーポリシーを使えます。
- **メンバーは緩和を拒否できます。** `CC_SAFETY_NET_PROJECT_TIGHTEN_ONLY=1` を設定したメンバーには、プロジェクトファイルのうち保護を強める設定だけが適用されます。それでも `status` と `doctor` には、各緩和が無視済みの印付きで表示されます。[プロジェクトの緩和を無視する](/ja/configuration/policy#ignore-project-weakenings)を参照してください。
- **監査はユーザースコープのままです。** プロジェクトポリシーに `audit` セクションがあっても、CC Safety Net はそれを無視して報告します。メンバーがローカルで何を記録するかを、プロジェクトは変えられません。
- **プロジェクトルールはユーザールールに干渉できません。** ユーザースコープのルールを指定したプロジェクトのオーバーライドは、CC Safety Net が無視して警告を出します。

## ポリシー変更は人間の手で

エージェントはポリシーの提案を起草して `policy check` を実行できますが、`policy apply` を実行できるのは人間だけです。[エージェントは policy apply を実行できない](/ja/reference/cli/policy#agents-cannot-run-policy-apply)を参照してください。そのため、コミットされるポリシー変更は必ず人間を経由します。通常は、`.cc-safety-net/` を変更するレビュー済みのプルリクエストという形になります。

<Tip>
コードレビューでは `.cc-safety-net/` を CI 設定と同じように扱ってください。チームメイト全員のエージェントに許される操作を変える小さなディレクトリなので、レビュアーは全行を読みます。リポジトリで `CODEOWNERS` を使っているなら、オーナーを割り当ててください。
</Tip>

## 検証を続ける

`rule verify` はコミット済みのルール設定と各ルールブックディレクトリをオフラインで検証するため、CI のステップとして実行できます。

```yaml
- run: npx -y cc-safety-net@latest rule verify
```

手編集で検証を通らなくなったルールブックや、ルールが満たさなくなったフィクスチャを、チームメイトのクローンに届く前に検出できます。メンバーは、実効ポリシーの確認に `npx -y cc-safety-net status` を、インストール全体のチェックに `npx -y cc-safety-net doctor` を実行します。
