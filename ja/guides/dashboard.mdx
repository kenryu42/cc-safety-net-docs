ダッシュボードは、このマシンで CC Safety Net が何をなぜブロックしたのかを確認し、その設定を変更できるローカルの Web ページです。`cc-safety-net gui` を実行すると開きます。判定の確認、JSON を書かずに行うポリシーの編集、プロジェクトポリシーの下書き、コーディングエージェントごとのフックのインストールができます。

元になる形式については、[ポリシー](/ja/configuration/policy)、[カスタムルール](/ja/configuration/custom-rules)、[監査ログ](/ja/reference/audit-log)を参照してください。

## ダッシュボードを起動する

```bash
cc-safety-net gui
```

このコマンドはダッシュボードの URL を出力し、既定のブラウザーで開きます。

```text
CC Safety Net policy GUI: http://127.0.0.1:52341/?token=...
```

SSH 経由やコンテナ内など、ブラウザーを開かずに URL だけを取得したい場合は `--no-open` を指定します。サーバーは `Ctrl-C` で停止するまでフォアグラウンドで動作します。フラグとエラーについては [`gui`](/ja/reference/cli/gui) を参照してください。

<span id="local-loopback-scope"></span>

### ローカルループバックに限定されている

サーバーは `127.0.0.1` だけで待ち受けるため、ネットワーク上のほかのマシンからは接続できません。起動のたびに URL に新しいトークンが埋め込まれ、トークンのないリクエストをサーバーは拒否します。以前の起動時にブックマークした URL は使えなくなるので、`cc-safety-net gui` を再実行してください。

`gui` はトークンを標準出力に出力します。そのため、`cc-safety-net gui` を自分で実行したエージェントはトークンを持っており、プロジェクトポリシーの適用を含めてダッシュボードを操作できます。ただし、エージェントが `policy.json` を直接編集する操作や `cc-safety-net policy apply` を実行する操作は、引き続き CC Safety Net が拒否します。

ページが読み取るのは、ローカルのポリシーファイルと監査ログだけです。概要画面は開いたときに、資格情報を含まないリクエストを外部へ 2 つ送ります。npm レジストリでの更新確認と、GitHub でのリポジトリの公開スター数の取得です。`GitHub でスター` は、クリックしたときだけ `gh` のログインを使います。

## 6 つの画面

画面ごとにアドレスが決まっていて、アクティビティ画面と保護画面の絞り込みもアドレスに保持されます。そのため、再読み込みしても「戻る」で戻っても復元されます。

| 画面 | 確認できること |
| --- | --- |
| **概要**（Overview） | 最近、このマシンで CC Safety Net がどう動作したか |
| **アクティビティ**（Activity） | エージェントが実行したコマンドと、それぞれの結果 |
| **保護**（Protections） | CC Safety Net に何をブロックさせるか |
| **カスタムルール**（Custom rules） | 現在適用されているカスタムルールブックのルール |
| **エージェント**（Agents） | このマシンでフックをインストール済みのコーディングエージェント |
| **設定**（Settings） | ログの保持期間、ファイルの場所、リセットの方法 |

保存済みのポリシーが次のいずれかの状態にあるときは、すべての画面の上部にバナーが表示され、状態ごとに 1 行ずつ並びます。

- `Command protection is off: built-in destructive command rules are not enforced. Catastrophic and custom rules still apply.`
- `Secret protection is off: sensitive files and deny paths are not blocked.`
- `A fallback configuration is being enforced: <reason>`

フォールバックの設定の意味と、そこから抜け出す方法は[設定の復旧](/ja/configuration/recovery#configuration-states)を参照してください。

## 概要

概要画面は直近 7 日間を集計します。保持期間が 7 日より短い場合は、保持期間全体を集計します。

**状態カード。** 画面上部のカードには、保存済みのポリシーにもとづいて次のいずれかの見出しが表示されます。

| 見出し | 表示される条件 |
| --- | --- |
| `Your policy file needs repair` | 保存済みのポリシーファイルにエラーがある |
| `Checking your agents…` | エージェントの検出が終わっていない |
| `Not protecting any agent yet` | 検出したエージェントのどれにも、有効なフックがない |
| `Partly protected` | コマンド保護かシークレット保護が無効になっている |
| `Protected` | 上記のいずれにも当てはまらない |

**Needs attention。** 対応が必要な項目があるときだけ表示される一覧です。各項目は対応する場所へのリンクです。

| 項目 | 開く画面 |
| --- | --- |
| `<Agent> is detected but its hook is disabled.` | エージェント画面 |
| `N blocks in the last N days look like a false positive.` | 誤検知の候補に絞ったアクティビティ画面 |
| `N guard errors in the last N days: commands blocked because evaluation failed, not by policy.` | エラーに絞ったアクティビティ画面 |
| `Version <version> is available.` | GitHub のリリースノート |

ガードのエラーは、CC Safety Net がコマンドのチェックを完了できなかったためにブロックしたものです。繰り返し発生する場合は[トラブルシューティング](/ja/guides/troubleshooting)を参照してください。

## アクティビティ

アクティビティ画面には、エージェントが実行したコマンドが新しい順に表示されます。画面は直近 7 日間を表示した状態で開き、監査ログの[保持期間](/ja/reference/audit-log#retention)までさかのぼれます。

シークレットのマスク処理が認識するのは既知の資格情報の形式だけなので、エントリにはパス、ホスト名、各種の名前が残ることがあります。この画面の内容を共有する前に、[シークレットのマスク処理](/ja/reference/audit-log#secret-redaction)を読んでください。

### 絞り込み

判定の絞り込みは既定で `Blocked` で、ガードのエラーも含みます。`Likely false positive` は、失敗ステージが記録された拒否か、同じセッション内で 2 回以上拒否されたコマンドがある場合に表示されます。`Search commands or rule IDs` の欄は、大文字と小文字を区別せずに、ルール ID とコマンド文字列に対して照合します。

一覧に読み込むのは判定ごとに新しい順で最大 500 件ですが、件数とタイルは常に対象期間全体を集計します。古いエントリを見るには期間を狭めてください。一部のログファイルを読み取れなかった場合はフッターにその旨が表示され、一覧と件数のどちらも不完全になります。

### エントリごとの操作

行を選ぶと、コマンド全体、理由、ルール、フォルダーを確認できます。

| 操作 | 対象 | 内容 |
| --- | --- | --- |
| **Report false positive** | ブロックされたエントリ | GitHub Issue を用意します。次の節を参照してください |
| **Block this in future** | 許可されたエントリ | `What should be blocked?` の欄にそのコマンドを入力した状態でカスタムルール画面を開きます。ルールが自動で作られるわけではありません |
| **Copy log entry** | すべてのエントリ | 監査レコードをそのまま JSON としてコピーします。[レコードのスキーマ](/ja/reference/audit-log#record-schema)を参照してください |

### 誤検知を報告する

**Report false positive** は、プロジェクトの誤検知報告フォームから公開の GitHub Issue を用意します。どの項目も事前に編集できます。

ダイアログは、プロジェクトのパスを `<project>` に、ホームディレクトリを `~` に置き換えます。それ以外のパスや名前は残るため、公開したくない内容は編集で取り除いてください。GitHub 上で自分が送信するまで、何も送信されません。

## 保護

保護画面では、CC Safety Net の組み込みの保護で何をブロックするかを選びます。対象は安全プリセット、破壊的コマンドのルール、シークレット保護のルールです。自作のルールブックはカスタムルール画面にあります。上部の `My policy` と `Project policy` で、編集するポリシーを切り替えます。

`/` を押すと、ルール名、ID、説明、保護対象のパスでルールを検索できます。`Changed from default` を選ぶと、自分または環境変数が変更したルールだけが表示されます。

### 保存済みと未保存

編集内容は、**Save** を押すまで下書きとして溜まります。**Save** はユーザーポリシーファイルを書き込みます。下書きは同じブラウザーセッション内なら再読み込みしても残ります。

保存済みのポリシーにエラーがある間は、フォームに組み込みの既定値が表示され、**Save** は無効になります。既定値でファイルを上書きしないためです。先に[修復](#repair)してください。

### プロジェクトポリシーを下書きする

`Project policy` を押すと、保護画面はプロジェクトの `policy.json` の下書きに切り替わります。このファイルは、そのフォルダーで作業する全員に、各自のポリシーの上に重ねて適用されます。下書きの対象はダッシュボードを起動したフォルダーで、`Change folder…` で別のフォルダーを選べます。

| タグ | 意味 |
| --- | --- |
| `Inherited` | プロジェクトファイルはこの設定を書かず、各メンバーが自分の値を使い続ける |
| `Project` | プロジェクトファイルがこの設定を書く。タグをクリックすると、このフィールドを設定しない状態に戻る |

コントロールを編集すると `Project` の印が付きます。印を付けたパスのリストは空の状態から始まるため、個人的なパスがリポジトリに書き込まれることはありません。

**Save** は **Review and apply** に変わります。ダイアログには、書き込み先のパス、実効ポリシーの `Setting` / `Now` / `After` の表、そして下書きが自分のポリシーより弱くする設定ごとの警告が表示されます。警告の一覧は[報告される緩和](/ja/configuration/policy#reported-weakenings)にあります。`Apply project policy` を押すまで、何も書き込まれません。

自分のポリシーファイルにエラーがある間は、`Repair your policy first` と表示されて下書きを開始できません。ユーザーの `.cc-safety-net/` があるフォルダーにも書き込めません。[ユーザー設定ディレクトリはプロジェクトではない](/ja/configuration/policy#the-user-config-directory-is-not-a-project)を参照してください。

この下書きは `cc-safety-net policy apply` と同じチェックを行います。2 つのポリシーのマージ方法は[プロジェクトポリシー](/ja/configuration/policy#project-policy)を参照してください。

### コマンドを試す

`Test a command` では、シェルコマンドを実行せずに、ブロックされるかどうかを確認できます。判定には未保存の編集内容とカスタムルールブックが使われるため、保存する前に変更を確かめられます。プロジェクトの下書き中は、自分のポリシーに下書きを重ねた状態で判定します。

ブロックされる場合は、ルール ID、理由、複合コマンドのうちブロックされた部分が表示されます。ターミナルで同じ確認をするには [`explain`](/ja/reference/cli/explain) を使います。

### 安全プリセット

**Standard**、**Strict**、**Paranoid** からプリセットを選びます。後のプリセットは前のプリセットの内容をすべて含みます。各プリセットで何が変わるかは[モード](/ja/configuration/modes)を参照してください。

環境変数が保護を強めている場合は、`An environment variable raises protection beyond these settings:` に続けてその変数が表示されます。このとき CC Safety Net は、表示中のプリセットより多くをブロックすることがあります。

折りたたまれた **Advanced settings** のカードでは、プリセットを変えずに `Fail closed`、`Paranoid rm -rf checks`、`Paranoid interpreters` をそれぞれ `From preset`、`Always on`、`Always off` に設定できます。同じカードに `Allow discarding local changes in linked git worktrees` もあります。

### コマンド保護

**Command protection** のパネルには、組み込みの破壊的コマンドのルールがカテゴリごとに並びます。`Always on` のグループは致命的な操作に対するルールで、オフにはできません。`Strict` または `Paranoid` のバッジは、そのプリセットが必要なルールを示します。

値がプリセットから来ていない場合は、注記で理由が示されます。

| 注記 | 意味 |
| --- | --- |
| `Changed by you` | 自分がこのルールを設定した。横の `Reset` でプリセットの値に戻せる |
| `<Capability> forced on in Advanced` または `<Capability> forced off in Advanced` | Advanced settings の設定がルールの値を決めている |
| `Set by environment: <variable>` | 環境変数がルールを有効にしている |
| `Needs the Strict preset` または `Needs the Paranoid preset` | 現在のプリセットにそのルールが含まれないため、オフになっている |

ブロックされたコマンドを 1 つだけ許可したい場合は、パネル全体ではなく、ここでそのルールをオフにしてください。[ブロックされたコマンドを許可する](/ja/reference/blocked-commands#allow-a-blocked-command)を参照してください。`Reset all` は、パネル内のすべてのルールをプリセットの値に戻します。

<span id="secret-protection"></span>

### シークレット保護

**Secret protection** のパネルも同じ作りで、ルールは `Sensitive file names`、`Coding agent credentials` などのカテゴリに分かれています。特定のパスを保護するルールでは、情報ボタンでそのパスを一覧できます。

`Coding agent settings` のルールは既定でオフで、`Off by default` と表示されます。1 つずつ有効にしてください。理由は [Coding CLI 設定階層](/ja/reference/secret-protection#coding-cli-config-tier-off-by-default)を参照してください。ブロックされたファイルを 1 つだけ許可するには、[ブロックされたファイルを許可する](/ja/reference/secret-protection#allow-a-blocked-file)を参照してください。

<Warning>
  コマンド保護やシークレット保護をオフにすると、再びオンにするまで、その層の設定可能なルールがすべて無効になります。ブロックを続けるのは `Always on` のコマンドルールだけです。マスタースイッチを切るより、個々のルールのオーバーライドか、より低いプリセットを選んでください。
</Warning>

<span id="exceptions-and-extra-paths"></span>

### 例外と追加のパス

**Exceptions and extra paths** のパネルには、3 つのパスのリストがあります。各項目は絶対パスか、`~/` で始まるパスで指定します。ホームディレクトリとその上位のフォルダーは拒否されます。複数行を貼り付けると、まとめて追加できます。

| リスト | ポリシーのフィールド | 効果 |
| --- | --- | --- |
| `Allow recursive deletes in` | `destructive_command_protection.allow_paths` | このパスの中での再帰削除を CC Safety Net はブロックしません。`/tmp` 配下の作業用フォルダーなどに使います。コマンド保護が無効の間は操作できません |
| `Always block access to` | `secret_protection.deny_paths` | シークレット保護が有効な間、CC Safety Net はこのパスとその配下をすべてブロックします |
| `Paths exempt from secret patterns` | `secret_protection.allow_paths` | ファイル、フォルダー、または `~/code/**/.env.local` のようにフォルダー配下のファイル名を、組み込みのファイルルールから除外します。拒否パスとコーディングエージェントの資格情報の保護は引き続き適用されます |

各リストがどんな項目を受け付けるかは、[許可パス](/ja/configuration/policy#allow-paths)、[拒否パス](/ja/configuration/policy#deny-paths)、[シークレットの許可パス](/ja/configuration/policy#secret-allow-paths)を参照してください。

### ポリシー JSON

折りたたまれた **Policy JSON** のカードは、フォームが保存するポリシーを読み取り専用で表示します。ファイルにエラーがある間はディスク上のファイルの内容そのものを、プロジェクトの下書き中は適用で書き込まれるファイルそのものを表示します。

<span id="repair"></span>

### 修復

ポリシーファイルにエラーがあると、保護画面にエラーの内容と `Repair` ボタンが表示されます。修復は有効な設定をすべて残し、無効な設定を破棄します。ファイルが JSON として読み取れない場合は、既定値に戻します。

<Warning>
  大切な設定を手書きしたファイルなら、修復する前に安全な場所へコピーしておいてください。
</Warning>

ポリシーを完全にリセットするには、[設定](#settings)の **Reset policy** を使います。

## カスタムルール

カスタムルール画面には、自分で書いたルールブックが、現在適用されている状態で読み取り専用で表示されます。CC Safety Net がダッシュボードからルールブックを書き込むことはありません。代わりに、ルールを書かせるコーディングエージェントへ渡すプロンプトを組み立てます。ルールブックの形式は[カスタムルール](/ja/configuration/custom-rules)を参照してください。

### ルールブックの一覧（読み取り専用）

各ルールには、照合するコマンド、`custom.<name>` の ID、理由、ブロックの条件となる引数が表示されます。オーバーライドで無効にしたルールは一覧に表示されません。ルールブックがない場合は、`Create a rule` か `npx -y cc-safety-net rule init` が案内されます。

### Problems

**Problems** の欄は、報告すべき内容があるときだけ表示されます。ここにエラーがある場合、CC Safety Net はそのルールブックをスキップしており、そのルールは 1 つも適用されていません。作ったルールが効かないときは、ここを確認してください。

### Create a rule（コピーのみ）

**Create a rule** は、ルールを書かせるためにコーディングエージェントへ渡すプロンプトを組み立てます。`This project` か `All projects` を選び、`What should be blocked?` に欲しいルールを書いて、**Copy prompt** を押します。

ルールが照合するのはコマンド、そのサブコマンド、正確な引数で、ファイルパスは照合しません。ファイルやフォルダーをブロックするには、[例外と追加のパス](#exceptions-and-extra-paths)の `Always block access to` に追加してください。

生成されるプロンプトは、`cc-safety-net` スキルを使うよう、スキルがない場合は `npx -y cc-safety-net rule doc` を使うようエージェントに指示します。

## エージェント

エージェント画面では、このマシン上の各コーディングエージェントについて、CC Safety Net のフックをインストールまたは削除します。ダッシュボードを使わない各エージェントのセットアップは[インストール](/ja/installation)を参照してください。

| 状態 | 意味 | 表示される操作 |
| --- | --- | --- |
| `Hook installed` | フックが設定され、有効になっている | `Uninstall` |
| `Hook disabled` | エージェントはインストールされているが、フックが無効になっている | `Enable` |
| `Status unknown: its settings file could not be read` | CC Safety Net はエージェントを見つけたが、その設定ファイルを読み取れない | `Install` |
| 表示なし | エージェントはインストールされているが、フックがない | `Install` |
| バージョンの欄に `Not detected` | CC Safety Net がこのマシンでエージェントを見つけられない | なし |

操作が失敗すると、行の下にコマンドの出力とともに `Install failed` または `Uninstall failed` が表示されます。エージェントをインストールした後や、その設定を手で編集した後は、`Refresh agents` を押してください。

<span id="settings"></span>

## 設定

**外観。** `Theme` の選択は、[言語](#dashboard-language)の選択と一緒にダッシュボードが保存します。ポリシーには含まれません。

**監査ログ。** `Keep logs for` で、監査レコードを保持する日数を 1 から 365 の範囲で設定します。変更した時点で保存されます。ポリシーの修復が必要な間、プロジェクトの下書き中、保護画面に未保存の変更がある間は、`Retention unchanged` と表示されて変更できません。[保持期間](/ja/reference/audit-log#retention)を参照してください。

<Warning>
  保持期間の短縮は元に戻せません。次回のクリーンアップで、新しい期間より古いエントリが削除されます。必要なエントリは、先にアクティビティ画面の `Copy log entry` でコピーしておいてください。
</Warning>

**ファイル。** ユーザーポリシーのパスと、プロジェクトポリシーが効いている場合はそのパスが表示されます。プロジェクトポリシーが自分の設定を緩めている場合は、変更点が 1 つずつ表示されます。これらの変更を拒否する方法は[プロジェクトの緩和を無視する](/ja/configuration/policy#ignore-project-weakenings)を参照してください。

**Danger zone。** **Reset policy** は、ポリシーファイルを既定値に置き換えます。プロジェクトの下書き中は使えません。

<Warning>
  リセットすると、保存済みの設定は破棄されます。プリセットの選択、ルールのオーバーライド、許可パス、拒否パスはすべて既定に戻り、元に戻せません。影響を受けるのはポリシーファイルだけで、カスタムルールブックには影響しません。
</Warning>

## ダッシュボードの表示言語

サイドバーの下部にある言語メニューで、ダッシュボードの表示を英語、日本語、簡体字中国語（简体中文）に切り替えられます。言語を選ぶまでは、ブラウザーの言語設定に従い、対応していない言語の場合は英語で表示します。ブロックの理由、ルール ID、サーバーのエラーは英語のままです。

選んだ言語とテーマは、`~/.cc-safety-net/` 内の `gui.json` に保存されます。`$CC_SAFETY_NET_HOME` が設定されている場合は、そのディレクトリに保存されます。どちらの選択も再起動後に引き継がれ、ポリシーには含まれません。
