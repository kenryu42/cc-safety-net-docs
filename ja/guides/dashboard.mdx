ダッシュボードは、このマシンで CC Safety Net が何をブロックしたのか、その理由は何か、何を変更できるのかを確認するためのローカルの Web ページです。`cc-safety-net gui` を実行すると開きます。判定の確認、JSON を書かずにポリシーを編集すること、プロジェクトポリシーの下書き、コーディングエージェントごとのフックのインストールができます。

元になる形式の説明は別のページにあります。`policy.json` のフィールドは[ポリシー](/ja/configuration/policy)、ルールブックの作り方は[カスタムルール](/ja/configuration/custom-rules)、レコードの形式は[監査ログ](/ja/reference/audit-log)を参照してください。

## ダッシュボードを起動する

```bash
cc-safety-net gui
```

このコマンドはダッシュボードの URL を出力し、既定のブラウザーで開きます。

```text
CC Safety Net policy GUI: http://127.0.0.1:52341/?token=...
```

SSH 経由やコンテナ内など、ブラウザーを開かずに URL だけを取得したい場合は `--no-open` を指定します。

```bash
cc-safety-net gui --no-open
```

サーバーは `Ctrl-C` で停止するまでフォアグラウンドで動作します。フラグ、引数のエラー、ブラウザーを開けなかったときの動作は [`gui`](/ja/reference/cli/gui) を参照してください。

<span id="local-loopback-scope"></span>

### ローカルループバックに限定されている

このダッシュボードはホスティングされたサービスではありません。サーバーは `127.0.0.1` だけで待ち受けるため、ネットワーク上のほかのマシンからは接続できません。起動のたびに URL に新しいトークンが埋め込まれ、トークンのないリクエストをサーバーは拒否します。以前の起動時にブックマークした URL は使えなくなるので、`cc-safety-net gui` を再実行して新しい URL を取得してください。

`gui` はトークンを標準出力に出力するため、コマンドを起動した人はトークンを読み取れます。つまり、`cc-safety-net gui` を自分で実行したエージェントはトークンを持っており、プロジェクトポリシーの適用を含めてダッシュボードを操作できます。ただし、エージェントが `policy.json` を直接編集する操作や `cc-safety-net policy apply` を実行する操作は、引き続き CC Safety Net が拒否します。

ページに表示される内容は、すべてローカルのポリシーファイルと監査ログから取得したものです。概要画面は開いたときに外部へ 2 つのリクエストを送ります。1 つは npm レジストリで更新を確認するもの、もう 1 つは GitHub からリポジトリの公開スター数を読むものです。どちらも資格情報は送りません。`Star on GitHub` は、クリックしたときだけ `gh` のログインを使います。

## 6 つの画面

サイドバーには 6 つの画面があります。画面ごとにアドレスが決まっているため、同じセッション内ならブックマークできます。アクティビティ画面と保護画面の絞り込みもアドレスに保持されるので、再読み込みしても「戻る」で戻っても復元されます。

| 画面 | 確認できること |
| --- | --- |
| **概要**（Overview） | 最近、このマシンで CC Safety Net がどう動作したか |
| **アクティビティ**（Activity） | エージェントが実行したコマンドと、それぞれの結果 |
| **保護**（Protections） | CC Safety Net に何をブロックさせるか |
| **カスタムルール**（Custom rules） | 現在適用されているカスタムルールブックのルール |
| **エージェント**（Agents） | このマシンでフックをインストール済みのコーディングエージェント |
| **設定**（Settings） | ログの保持期間、ファイルの場所、リセットの方法 |

保護が無効になっているときや、設定のエラーによってランタイムがフォールバックの設定を適用しているときは、すべての画面の上部にバナーが表示されます。状態ごとに 1 行ずつ並びます。

- `Command protection is off: built-in destructive command rules are not enforced. Catastrophic and custom rules still apply.`
- `Secret protection is off: sensitive files and deny paths are not blocked.`
- `A fallback configuration is being enforced: <reason>`

バナーが反映するのは保存済みのポリシーで、未保存の編集内容は反映されません。フォールバックの設定の意味と、そこから抜け出す方法は[設定の復旧](/ja/configuration/recovery#configuration-states)を参照してください。

## 概要

概要画面は直近 7 日間を集計します。保持期間が 7 日より短い場合は、保持期間全体を集計します。

**状態カード。** 画面上部のカードには、次のいずれかの見出しが表示されます。

| 見出し | 表示される条件 |
| --- | --- |
| `Your policy file needs repair` | 保存済みのポリシーファイルにエラーがある |
| `Checking your agents…` | エージェントの検出が終わっていない |
| `Not protecting any agent yet` | 検出したエージェントのどれにも、有効なフックがない |
| `Partly protected` | コマンド保護かシークレット保護が無効になっている |
| `Protected` | 上記のいずれにも当てはまらない |

見出しの下には、プリセット名が表示されます。プリセットを変更している場合は `, customized` が付きます。続いて、フックが有効なエージェントが並びます。フックが有効なエージェントがない場合、カードのリンクはエージェント画面を、それ以外は保護画面を指します。このカードが反映するのは保存済みのポリシーだけです。

**Needs attention。** 対応が必要な項目があるときだけ表示される一覧で、各項目は対応する場所へのリンクです。

- `<Agent> is detected but its hook is disabled.`：エージェント画面を開きます。
- `N blocks in the last N days look like a false positive.`：誤検知の候補に絞ったアクティビティ画面を開きます。
- `N guard errors in the last N days: commands blocked because evaluation failed, not by policy.`：エラーに絞ったアクティビティ画面を開きます。CC Safety Net がチェックを完了できなかったため、これらのコマンドをブロックしたものです。繰り返し発生する場合は[トラブルシューティング](/ja/guides/troubleshooting)を参照してください。
- `Version <version> is available.`：GitHub のリリースノートを開きます。

**タイル、Recent blocks、Most-triggered rules。** `Blocked` と `Commands checked` のタイルには、件数と日別のグラフが表示されます。Recent blocks には直近にブロックされたコマンド 8 件が、Most-triggered rules にはブロックの多いルール ID の上位 5 件が並びます。行を選ぶと、カスタムルール画面でそのルールが開くか、そのルール ID で検索したアクティビティ画面が開きます。

## アクティビティ

アクティビティ画面には、エージェントが実行したコマンドが新しい順に、日ごとの見出しの下に表示されます。シークレットのマスク処理が認識するのは既知の資格情報の形式だけなので、エントリにはパス、ホスト名、各種の名前が残ることがあります。この画面の内容を共有する前に、[シークレットのマスク処理](/ja/reference/audit-log#secret-redaction)を読んでください。

期間の選択肢は監査ログの保持期間までで、画面は直近 7 日間を表示した状態で開きます。より長い履歴を残す方法は[保持期間](/ja/reference/audit-log#retention)を参照してください。

### 絞り込み

- **判定**：`Blocked`（既定。ガードのエラーを含む）、`Allowed`、`All` が、それぞれ件数付きで表示されます。`Errors` は対象期間にガードのエラーがある場合に表示されます。`Likely false positive` は、失敗ステージが記録された拒否か、同じセッション内で 2 回以上拒否されたコマンドを CC Safety Net が見つけた場合に表示されます。
- **検索**：`Search commands or rule IDs` の欄は、大文字と小文字を区別せずに、ルール ID とコマンド文字列に対して照合します。
- **エージェント**：`All agents` と、エージェントごとの選択肢です。対象期間に 2 種類以上のエージェントがある場合に表示されます。
- **期間**：何日前までさかのぼるかを選びます。

既定の絞り込みで何もブロックされていない場合は、`Nothing was blocked in the last N days.` と表示され、`Show all activity` が付きます。見出しの横にある再読み込みのアイコンは、アクティビティと概要の両方を読み込み直します。

フッターには `Showing X of Y entries from the last N days.` と表示されます。一覧に読み込むのは判定ごとに新しい順で最大 500 件ですが、件数とタイルは常に対象期間全体を集計します。古いエントリを見るには期間を狭めてください。一部のログファイルを読み取れなかった場合はフッターにその旨が表示され、一覧と件数のどちらも不完全になります。

### エントリごとの操作

各行には、時刻、判定のバッジ（`Blocked`、`Allowed`、`Error`）、エージェント、コマンド、ルール ID が表示されます。行を選ぶと、コマンド全体、理由、ルール、フォルダーを確認できます。ルール ID は、保護画面またはカスタムルール画面の該当ルールへのリンクです。

- ブロックされたエントリには **Report false positive** があります。次の節を参照してください。
- 許可されたエントリには **Block this in future** があります。`What should be blocked?` の欄にそのコマンドを入力した状態でカスタムルール画面を開きます。ルールが自動で作られるわけではありません。
- すべてのエントリに **Copy log entry** があり、監査レコードをそのまま JSON としてコピーします。各フィールドは[レコードのスキーマ](/ja/reference/audit-log#record-schema)を参照してください。

### 誤検知を報告する

**Report false positive** を押すとダイアログが開き、プロジェクトの誤検知報告フォームから公開の GitHub Issue を用意します。任意の理由、タイトル、ブロックされたコマンド、JSON 形式の監査エントリのすべてを編集できます。

ダイアログは、プロジェクトのパスを `<project>` に、ホームディレクトリを `~` に置き換えます。それ以外のパスや名前は残るため、公開したくない内容は編集で取り除いてください。`Open GitHub form` を押すと、入力済みのフォームが新しいタブで開きます。GitHub 上で自分が送信するまで、何も送信されません。報告がリンクに収まらないほど長い場合は、ダイアログが項目の 1 つをクリップボードにコピーし、貼り付け先を示します。

## 保護

保護画面では、CC Safety Net に何をブロックさせるかを選びます。ここにあるのはすべて組み込みの保護で、安全プリセット、破壊的コマンドのルール、シークレット保護のルールが含まれます。自作のルールブックはカスタムルール画面にあります。上部の `My policy` と `Project policy` で、編集するポリシーを切り替えます。

### 保存済みと未保存

編集内容は、保存するまで下書きとして溜まります。保存バーには `N unsaved changes` と **Discard**、**Save** が表示され、サイドバーの保護画面には `Unsaved` の印が付きます。下書きは同じブラウザーセッション内なら再読み込みしても残り、ページを離れようとすると確認を求められます。**Discard** は確認を求めます。**Save** はユーザーポリシーファイルを書き込み、そのパスを表示します。

保存済みのポリシーにエラーがある間、ダッシュボードは保護画面を開き、フォームに組み込みの既定値を表示します。このとき **Save** は無効になり、既定値でファイルを上書きすることはありません。先に[修復](#repair)してください。

### プロジェクトポリシーを下書きする

`Project policy` を押すと、保護画面はプロジェクトの `policy.json` の下書きに切り替わります。このファイルは、そのフォルダーで作業する全員に、各自のポリシーの上に重ねて適用されます。下書きの対象はダッシュボードを起動したフォルダーで、`Change folder…` で別のフォルダーを選べます。自分のポリシーに未保存の変更がある場合は、先に破棄するかどうかを確認されます。`My policy` で元に戻ります。

各コントロールにはタグが付きます。

- `Inherited`：プロジェクトファイルはこの設定を書かず、各メンバーが自分の値を使い続けます。
- `Project`：プロジェクトファイルがこの設定を書きます。タグをクリックすると、このフィールドを設定しない状態に戻ります。

コントロールを編集すると `Project` の印が付きます。印を付けたパスのリストは空の状態から始まるため、個人的なパスがリポジトリに書き込まれることはありません。

**Save** は **Review and apply** に変わり、押すと `Apply this project policy?` が開きます。ダイアログには、書き込み先のパス、実効ポリシーの `Setting` / `Now` / `After` の表、そして下書きが自分のポリシーより弱くする設定ごとの警告が表示されます。警告の一覧は[報告される緩和](/ja/configuration/policy#reported-weakenings)にあります。`Apply project policy` を押すまで、ダッシュボードは何も書き込みません。下書き中の **Discard** は、確認のうえでプロジェクトファイルにすでにある内容へ戻します。

自分のポリシーファイルにエラーがある間は、`Repair your policy first` と表示されて下書きを開始できません。ユーザーの `.cc-safety-net/` があるフォルダーにも書き込めません。`Change folder…` でプロジェクトを選んでください。[ユーザー設定ディレクトリはプロジェクトではない](/ja/configuration/policy#the-user-config-directory-is-not-a-project)を参照してください。

2 つのポリシーのマージ方法は[プロジェクトポリシー](/ja/configuration/policy#project-policy)を参照してください。この下書きは `cc-safety-net policy apply` と同じチェックを行います。

### コマンドを試す

`Test a command` を押すとダイアログが開きます。シェルコマンドを入力して `Test` を押すと、ブロックされるかどうかを確認できます。コマンドは実行されません。判定には未保存の編集内容とカスタムルールブックが使われるため、保存する前に変更を確かめられます。プロジェクトの下書き中は、自分のポリシーに下書きを重ねた状態で判定します。

ブロックされる場合は、`Blocked` とルール ID、理由、複合コマンドのうちブロックされた部分が表示されます。ブロックされない場合は `Allowed. No rule blocks this command.` と表示され、カスタムルール画面への `Create a rule to block it` のリンクが付きます。ターミナルで同じ確認をするには [`explain`](/ja/reference/cli/explain) を使います。

### 安全プリセット

**Standard**、**Strict**、**Paranoid** の 3 つのカードからプリセットを選びます。後のプリセットは前のプリセットの内容をすべて含みます。オーバーライドがプリセットと異なる場合は `<Preset>, customized` と表示されます。各プリセットで何が変わるかは[モード](/ja/configuration/modes)を参照してください。

環境変数が保護を強めている場合は、`An environment variable raises protection beyond these settings:` に続けてその変数が表示されます。このとき CC Safety Net は、表示中のプリセットより多くをブロックすることがあります。

折りたたまれた **Advanced settings** のカードでは、プリセットを変えずに個々の機能をオンまたはオフにできます。対象は `Fail closed`、`Paranoid rm -rf checks`、`Paranoid interpreters` で、それぞれ `From preset`、`Always on`、`Always off` から選びます。同じカードに `Allow discarding local changes in linked git worktrees` もあります。

### 保護を検索する

検索欄（`Type / to search by name, path or rule ID`）は、ルール名、ID、説明、シークレットのルールが保護するパスに対して照合します。`/` を押すとこの欄にフォーカスが移ります。`Changed from default` を選ぶと、自分または環境変数が変更したルールだけが表示されます。

### コマンド保護

**Command protection** のパネルには、組み込みの破壊的コマンドのルールがあります。ヘッダーには、マスタースイッチ、`Reset all` のボタン、`N on · N off · N always on` のような概要があります。

最初は `Always on` のグループです。致命的な操作に対するルールが並び、オフにできないため、スイッチの代わりに錠前のアイコンが付きます。その後に、`Git` や `Filesystem` などカテゴリごとのグループが続きます。各ルールの行には、スイッチ、ルール名と ID、説明が表示されます。`Strict` または `Paranoid` のバッジは、そのプリセットが必要なルールを示します。情報ボタンを押すと、そのルールがブロックするコマンドの例が表示されます。

値がプリセットから来ていない場合は、注記で理由が示されます。

| 注記 | 意味 |
| --- | --- |
| `Changed by you` | 自分がこのルールを設定した。横の `Reset` でプリセットの値に戻せる |
| `<Capability> forced on in Advanced` または `<Capability> forced off in Advanced` | Advanced settings の設定がルールの値を決めている |
| `Set by environment: <variable>` | 環境変数がルールを有効にしている |
| `Needs the Strict preset` または `Needs the Paranoid preset` | 現在のプリセットにそのルールが含まれないため、オフになっている |

`Reset all` は、確認のうえでパネル内のすべてのルールをプリセットの値に戻します。ブロックされたコマンドを 1 つだけ許可したい場合は、パネル全体ではなく、ここでそのルールをオフにしてください。[ブロックされたコマンドを許可する](/ja/reference/blocked-commands#allow-a-blocked-command)を参照してください。

マスタースイッチをオフにするときは確認を求められます。オフにすると、概要が `Off. Built-in rules are not enforced; catastrophic and custom rules still apply. Your rule settings are kept.` になります。

<span id="secret-protection"></span>

### シークレット保護

**Secret protection** のパネルも同じ作りで、マスタースイッチ、`Reset all`、`N on · N off` のような概要があります。ルールは `Sensitive file names`、`Sensitive file extensions`、`Coding agent credentials` などのカテゴリに分かれています。特定のファイルパスを保護するルールには、そのパスを一覧する情報ボタンが付きます。

`Coding agent settings` のルールは既定でオフで、`Off by default` と表示されます。1 つずつ有効にしてください。理由は [Coding CLI 設定階層](/ja/reference/secret-protection#coding-cli-config-tier-off-by-default)を参照してください。ブロックされたファイルを 1 つだけ許可するには、[ブロックされたファイルを許可する](/ja/reference/secret-protection#allow-a-blocked-file)を参照してください。

マスタースイッチをオフにするときは確認を求められます。オフにすると、概要が `Off. Sensitive files and deny paths are not blocked. Your rule settings and paths are kept.` になります。

<Warning>
  コマンド保護やシークレット保護をオフにすると、再びオンにするまで、その層の設定可能なルールがすべて無効になります。ブロックを続けるのは `Always on` のコマンドルールだけです。マスタースイッチを切るより、個々のルールのオーバーライドか、より低いプリセットを選んでください。
</Warning>

<span id="exceptions-and-extra-paths"></span>

### 例外と追加のパス

**Exceptions and extra paths** のパネルには、3 つのパスのリストがあります。各項目は絶対パスか、`~/` で始まるパスで指定します。ホームディレクトリとその上位のフォルダーは拒否されます。複数行を貼り付けると、まとめて追加できます。

| リスト | ポリシーのフィールド | 効果 |
| --- | --- | --- |
| `Allow recursive deletes in` | `destructive_command_protection.allow_paths` | このパスの中での再帰削除を CC Safety Net はブロックしません。`/tmp` 配下の作業用フォルダーなどに使います。コマンド保護が無効の間は操作できません |
| `Always block access to` | `secret_protection.deny_paths` | シークレット保護が有効な間、CC Safety Net はこのパスとその配下をすべてブロックします |
| `Paths exempt from secret patterns` | `secret_protection.allow_paths` | ファイル、フォルダー、または `~/code/**/.env.local` のようにフォルダー配下のファイル名を、組み込みのファイルルールから除外します。拒否パスとコーディングエージェントの資格情報の保護は引き続き適用されます |

拒否された項目には `Not added: <paths>. <reason>`、すでにリストにある項目には `Already listed: <paths>` と表示されます。各リストが何を緩め、どんな項目を受け付けるかは、[許可パス](/ja/configuration/policy#allow-paths)、[拒否パス](/ja/configuration/policy#deny-paths)、[シークレットの許可パス](/ja/configuration/policy#secret-allow-paths)を参照してください。

### ポリシー JSON

画面のいちばん下にある **Policy JSON** のカードは、既定で折りたたまれています。ポリシーを読み取り専用で表示し、`Copy` ボタンが付きます。表示されるのは、フォームが保存するポリシー、エラーがある間はディスク上のファイルの内容そのもの、プロジェクトの下書き中は適用で書き込まれるファイルそのものです。

<span id="repair"></span>

### 修復

ポリシーファイルにエラーがあると、保護画面に `Your policy file needs repair` とエラーの内容、`Repair` ボタンが表示されます。修復は確認を求めたうえで、有効な設定をすべて残し、無効な設定を破棄します。ファイルが JSON として読み取れない場合は、既定値に戻します。

<Warning>
  修復すると無効な設定は破棄され、ファイルが JSON として読み取れない場合は既定値に戻ります。大切な設定を手書きしたファイルなら、先に安全な場所へコピーしておいてください。
</Warning>

ポリシーを完全にリセットするには、[設定](#settings)の **Reset policy** を使います。

## カスタムルール

カスタムルール画面には、自分で書いたルールブックが、現在適用されている状態で表示されます。これらのルールは組み込みの保護とは別のものです。ルールブックの形式は[カスタムルール](/ja/configuration/custom-rules)を参照してください。

<Warning>
  カスタムルール画面はルールブックのエディターではありません。CC Safety Net がダッシュボードからルールブックを書き込むことはありません。この画面は、適用されているルールを読み取り専用で表示し、ルールを書かせるためにコーディングエージェントへ渡すプロンプト文を組み立てます。
</Warning>

### ルールブックの一覧（読み取り専用）

各ルールブックには、名前、バージョン、スコープ（`All projects` または `This project`）、ルール数が表示されます。各ルールには、照合するコマンド、`custom.<name>` の ID、理由、ブロックの条件となる引数が表示されます。オーバーライドで無効にしたルールは一覧に表示されません。再読み込みのアイコンでファイルを読み込み直せます。

ルールブックがない場合は `No custom rules yet.` と表示され、`Create a rule` か `npx -y cc-safety-net rule init` が案内されます。

### Problems

**Problems** の欄は、報告すべき内容があるときだけ表示されます。ここにエラーがある場合、CC Safety Net はそのルールブックをスキップしており、そのルールは 1 つも適用されていません。作ったルールが効かないときは、ここを確認してください。

### Create a rule（コピーのみ）

**Create a rule** は、ルールを書かせるためにコーディングエージェントへ渡すプロンプトを組み立てます。できる操作は **Copy prompt** だけです。

- **Applies to**：`This project` または `All projects`。
- **Project folder**：`This project` のときに表示され、ダッシュボードを起動したフォルダーが入力されています。
- **What should be blocked?**：欲しいルールを記述します。ルールが照合するのはコマンド、そのサブコマンド、正確な引数で、ファイルパスは照合しません。ファイルやフォルダーをブロックするには、[例外と追加のパス](#exceptions-and-extra-paths)の `Always block access to` に追加してください。
- **Try**：`Suggest rules`、`Block a command`、`Verify rules` のサンプルプロンプトです。

生成されるプロンプトは、`cc-safety-net` スキルを使うよう、スキルがない場合は `npx -y cc-safety-net rule doc` を使うようエージェントに指示します。既存のルールブックの名前も含むため、エージェントは使われていない名前を選べます。コピーすると `Prompt copied` と表示されます。

## エージェント

エージェント画面では、このマシン上の各コーディングエージェントについて、CC Safety Net のフックをインストールまたは削除します。ダッシュボードを使わない各エージェントのセットアップは[インストール](/ja/installation)を参照してください。

各行には、エージェント、バージョン（見つからない場合は `Not detected`）、状態、操作が表示されます。

| 状態 | 意味 | 表示される操作 |
| --- | --- | --- |
| `Hook installed` | フックが設定され、有効になっている | `Uninstall` |
| `Hook disabled` | エージェントはインストールされているが、フックが無効になっている | `Enable` |
| `Status unknown: its settings file could not be read` | CC Safety Net はエージェントを見つけたが、その設定ファイルを読み取れない | `Install` |
| 表示なし | エージェントはインストールされているが、フックがない | `Install` |
| バージョンの欄に `Not detected` | CC Safety Net がこのマシンでエージェントを見つけられない | なし |

操作の後、コマンドの出力が行の下に表示されます。失敗した場合は `Install failed` または `Uninstall failed` と表示されます。エージェントをインストールした後や、その設定を手で編集した後は、再読み込みのアイコン（`Refresh agents`）を押してください。

<span id="settings"></span>

## 設定

**外観。** `Theme` で `Auto`、`Light`、`Dark` を選べます。この選択は[言語](#dashboard-language)の選択と一緒にダッシュボードが保存します。ポリシーには含まれません。

**監査ログ。** `Keep logs for` で、監査レコードを保持する日数を 1 から 365 の範囲で設定します。保護画面と異なり、変更した時点で保存されます。ポリシーの修復が必要な間、プロジェクトの下書き中、保護画面に未保存の変更がある間は、`Retention unchanged` と表示されて変更できません。`Log folder` には監査ログのディレクトリが `Copy` ボタン付きで表示されます。[保持期間](/ja/reference/audit-log#retention)を参照してください。

<Warning>
  保持期間の短縮は元に戻せません。次回のクリーンアップで、新しい期間より古いエントリが削除されます。ダッシュボードは確認を求め、削除の対象となるフォルダーを示します。必要なエントリは、先にアクティビティ画面の `Copy log entry` でコピーしておいてください。
</Warning>

**ファイル。** 読み取り専用の行に、ユーザーポリシーのパスが表示されます。ファイルがまだない場合は `(not created yet)` が付きます。プロジェクトポリシーが効いている場合は、そのパスも表示されます。プロジェクトポリシーが自分の設定を緩めている場合は、`The project policy changes these settings:` の下に変更点が 1 つずつ並びます。これらの変更を拒否する方法は[プロジェクトの緩和を無視する](/ja/configuration/policy#ignore-project-weakenings)を参照してください。

**Danger zone。** **Reset policy** は、確認のうえでポリシーファイルを既定値に置き換えます。プロジェクトの下書き中は使えません。

<Warning>
  リセットすると、保存済みの設定は破棄されます。プリセットの選択、ルールのオーバーライド、許可パス、拒否パスはすべて既定に戻り、元に戻せません。影響を受けるのはポリシーファイルだけで、カスタムルールブックには影響しません。
</Warning>

<span id="dashboard-language"></span>

## ダッシュボードの表示言語

サイドバーの下部（狭い画面ではページの下部）にある言語メニューで、ダッシュボードの表示を英語、日本語、簡体字中国語（简体中文）に切り替えられます。言語を選ぶまでは、ブラウザーの言語設定に従い、対応していない言語の場合は英語で表示します。ブロックの理由、ルール ID、サーバーのエラーは英語のままです。

選んだ言語とテーマは、`~/.cc-safety-net/` 内の `gui.json` に保存されます。`$CC_SAFETY_NET_HOME` が設定されている場合は、そのディレクトリに保存されます。起動のたびにポートは変わりますが、どちらの選択も再起動後に引き継がれます。これらはポリシーには含まれません。
