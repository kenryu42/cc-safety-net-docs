## CC Safety Net とは何ですか？

CC Safety Net は、Claude Code、Codex、Cursor などの AI コーディングエージェント向けの実行前フックです。コマンドやファイル操作を実行前に 1 つずつチェックし、未コミットの作業を破壊する操作やシークレットを露出させる操作をブロックします。対象は `git reset --hard`、`git push --force`、ホームディレクトリへの `rm -rf`、`.env` ファイル・SSH 鍵・クラウドの資格情報の読み取りなどです。16 のコーディングエージェントに対応しています。

## CC Safety Net が必要な理由

2026 年 10 月時点で、作業を任せたワークスペースの中で破壊的な git コマンドを決定的にブロックする主要なコーディング CLI は 1 つもありません。`git reset --hard`、`git checkout -- .`、`git clean -f`、`git stash clear`、`git push --force` は、いずれもエージェントがもともと書き込めるファイルに作用します。そのため、書き込みをプロジェクト内に限定するサンドボックスからは、何も問題が見えません。OpenAI の [Codex セキュリティドキュメント](https://learn.chatgpt.com/docs/security)も、workspace-write モードで動くコマンドについて「can still mutate state and perform destructive operations」と述べています。Claude Code の[サンドボックスドキュメント](https://code.claude.com/docs/en/sandboxing)は書き込みを作業ディレクトリに限定しますが、未コミットの作業が置かれているのはまさにその場所です。

導入する理由はほかに 3 つあります。

- **確率的なチェックの下に置く、決定的なチェック。** Anthropic は 2026 年 10 月時点で、Claude Code の [auto モード](https://www.anthropic.com/engineering/claude-code-auto-mode)の分類器について、実際の行き過ぎた操作に対する偽陰性率 17% を公表し、「not a drop-in replacement for careful human review」だとしています。フックは判断に頼らず、固定のルールを適用します。
- **設定なしで使えるシークレット保護。** Claude Code には資格情報の拒否リストが組み込まれておらず、ほかの CLI ではツールごとに自分で書く必要があります。CC Safety Net は、インストールした時点から `.env` ファイル、SSH 鍵、クラウドの資格情報をブロックします。[シークレット保護](/ja/reference/secret-protection)を参照してください。
- **16 の CLI にまたがる 1 つのポリシーと 1 つの監査証跡。** 5 つのベンダーが互換性のない 5 つの権限機構を提供しており、後から読める判定ログはどれにもありません。

`CLAUDE.md` や `AGENTS.md` の指示はエージェントを導きますが、制限を強制することはできません。指示があったにもかかわらず、あるエージェントはたった 1 つの `rm -rf ~/` で[数時間分の作業を消し去りました](https://www.reddit.com/r/ClaudeAI/comments/1pgxckk/claude_cli_deleted_my_entire_home_directory_wiped/)。Adversa の[インシデントトラッカー](https://adversa.ai/blog/ai-coding-agent-incidents)には、2025 年と 2026 年のエージェントによる破壊事例が 9 件記録されており、その約半数ではガードレールが有効でした。サンドボックスと許可リストの CVE は[保護レイヤーの比較](/ja/guides/vs-sandboxing)で扱っています。

## インターセプトする操作

CC Safety Net はコーディングエージェントに組み込まれ、エージェントのツール呼び出しがマシンに届く前に動作します。

シェルコマンドと、ファイルの書き込み・編集・検索・パッチの各操作を検査し、許可するか、理由を明示してブロックするかを決めます。ブロックは通常のツール結果として返るため、エージェントは[ブロックされた操作を使わずにタスクを続けられます](/ja/guides/how-it-works#what-a-block-looks-like)。

判定はコマンドの表記ではなく、実際の動作に基づきます。`git checkout -b feature` はブランチを作成するので許可し、`git checkout -- file` は未コミットの変更を破棄するのでブロックします。どちらも先頭の 2 語は同じです。

## よくある質問

### CC Safety Net は無料ですか？

はい。CC Safety Net は無料で、MIT ライセンスで公開されています。ソースコードは [GitHub](https://github.com/kenryu42/cc-safety-net) にあります。

### CC Safety Net は LLM を使いますか？

いいえ。すべての判定はローカルのルールベースのパーサーが行い、モデルは呼び出しません。同じコマンドには毎回同じ判定が返ります。[仕組み](/ja/guides/how-it-works#does-cc-safety-net-use-an-llm)を参照してください。

### CC Safety Net はデータをどこかに送信しますか？

いいえ。CC Safety Net にはテレメトリーがなく、判定はネットワーク通信なしにローカルで行います。ネットワークを使うのは、`npx` や `bunx` がパッケージを取得するとき、`rule add` や `rule update` が GitHub からルールブックを取得するとき、`update` が npm レジストリを確認するときだけです。[監査ログ](/ja/reference/audit-log)もマシンの外には出ません。

### CC Safety Net を入れるとエージェントは遅くなりますか？

エージェント内にプラグインとして読み込まれる連携では、ほとんど遅くなりません。`npx` 経由で実行するフックでは、ツール呼び出し 1 回ごとに数百ミリ秒かかります。それより遅い場合は、[トラブルシューティング](/ja/guides/troubleshooting)を参照してください。

### CC Safety Net は Windows で動きますか？

はい。ただし Hermes Agent と OpenClaw は macOS と Linux でしか動作しないため除きます。Amp のドキュメントが対象としているのは macOS、Linux、WSL で、ネイティブの Windows ではありません。[インストール前の確認](/ja/installation#before-you-install)を参照してください。

### CC Safety Net はサンドボックスですか？

いいえ。サンドボックスはファイルシステムとネットワークを封じ込めます。CC Safety Net は、サンドボックスがプロジェクト内では許可してしまう破壊的な操作をブロックします。両方を併用してください。CC Safety Net はバイナリの内部を検査できず、連携を迂回するコマンドもチェックできません。[保護レイヤーの比較](/ja/guides/vs-sandboxing)と[既知の制限](/ja/guides/known-limitations)を参照してください。
