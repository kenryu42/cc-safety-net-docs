CC Safety Net は、`policy.json` と環境変数から設定を読み取ります。モードのトグルには `CC_SAFETY_NET_*` というプレフィックスを使います。`CC_` プレフィックスのない古い `SAFETY_NET_*` という名前も、以降で明記した箇所では以前からのエイリアスとして使用できます。変数は、エージェントを起動する前にシェルまたはエージェントの起動環境で設定してください。

このページでは、各変数そのものと、それらが `policy.json` とどう組み合わさるかを説明します。各レベルがブロックする内容は[安全レベル](/ja/configuration/modes)を、ポリシーファイルの仕様全体は[ポリシー](/ja/configuration/policy)を参照してください。

## 安全レベル

| 変数 | 以前のエイリアス | 効果 |
| --- | --- | --- |
| `CC_SAFETY_NET_LEVEL=standard\|strict\|paranoid` | なし | 安全 preset を選択します。`policy.json` の `safety.level` で設定したレベルを引き上げることはできますが、引き下げることはできません。 |

3 つの preset は、いずれも同じ 3 つの機能（`fail_closed`、`paranoid_rm`、`paranoid_interpreters`）に展開されます。各 preset がブロックする内容と各機能の効果は、[安全レベル](/ja/configuration/modes)を参照してください。

`standard`、`strict`、`paranoid` 以外の値は無視され、`policy.json` で設定したレベルがそのまま使われます。無視された値は常に stderr に出力されます。デバッグ用のフラグは必要ありません。

```
CC Safety Net: ignored invalid CC_SAFETY_NET_LEVEL="<value>". Use standard, strict, paranoid.
```

出力される値は、先頭 40 文字までに切り詰められます。空の値は未設定として扱われ、警告も表示されません。

## 機能トグル

次の変数は、機能ごとに用意された以前からのフラグです。いずれも機能を**有効にする方向にしか働きません**。偽と解釈される値を設定しても、機能が無効になることはありません。preset より低い状態に機能を落としたい場合は、[policy.json](/ja/configuration/policy) の `safety.overrides` を使ってください。

| 変数 | 以前のエイリアス | 効果 |
| --- | --- | --- |
| `CC_SAFETY_NET_STRICT=1` | `SAFETY_NET_STRICT` | `fail_closed` 機能を強制的に有効にします。`safety.overrides.fail_closed: true` と同じです。 |
| `CC_SAFETY_NET_PARANOID=1` | `SAFETY_NET_PARANOID` | `paranoid_rm` と `paranoid_interpreters` の両方を強制的に有効にします。`fail_closed` は設定**しません**。 |
| `CC_SAFETY_NET_PARANOID_RM=1` | `SAFETY_NET_PARANOID_RM` | `paranoid_rm` を強制的に有効にします。対象がカレントディレクトリ配下にある場合でも、一時パス以外への `rm -rf` をブロックします。 |
| `CC_SAFETY_NET_PARANOID_INTERPRETERS=1` | `SAFETY_NET_PARANOID_INTERPRETERS` | `paranoid_interpreters` を強制的に有効にします。内容にかかわらず、すべてのインタープリター 1 行コードをブロックします。 |
| `CC_SAFETY_NET_WORKTREE=1` | `SAFETY_NET_WORKTREE` | 確認済みの linked worktree 内で、ローカルの変更を破棄する Git ルールを緩和します。`workflow.worktree_mode` とは論理 OR で組み合わせます。 |

真偽値のフラグは、`1` または `true`（大文字と小文字は区別しない）を設定すると真になります。`CC_SAFETY_NET_*` の名前が設定されていればそちらが優先され、プレフィックス付きの名前がない場合にかぎり `SAFETY_NET_*` のエイリアスを参照します。

## 優先順位

ポリシーと環境変数は、次の決まった順序で組み合わされます。

1. **preset。** `policy.json` の `safety.level` が、機能の既定値を決めます。このフィールドがない場合、preset は `standard` です。
2. **`CC_SAFETY_NET_LEVEL`。** 実際に適用される基本レベルは、ポリシー側と環境変数側のうち高い方です。環境変数はレベルを引き上げられますが、引き下げることはできません。
3. **`safety.overrides.*`。** 続いて、`policy.json` の明示的な機能 override が、`fail_closed`、`paranoid_rm`、`paranoid_interpreters` を上下どちらの方向にも設定します。つまり、引き上げも**引き下げ**もできます。
4. **機能トグル。** `CC_SAFETY_NET_STRICT`、`CC_SAFETY_NET_PARANOID`、`CC_SAFETY_NET_PARANOID_RM`、`CC_SAFETY_NET_PARANOID_INTERPRETERS` のフラグは最後に適用され、**単調**に働きます。いずれも機能を強制的に `true` にするだけで、機能を無効にすることはできません。
5. **worktree モード**は、`workflow.worktree_mode` と `CC_SAFETY_NET_WORKTREE` の論理 OR です。

報告される**有効なレベル**は、最終的な 3 つの機能の組み合わせから決まります。どの preset にも一致しない組み合わせ（たとえば `fail_closed` が無効で `paranoid_rm` が有効な場合）は、`custom` として報告されます。

`destructive_command_protection.overrides` のルール単位の設定は、機能から決まった状態の上にさらに適用されます。致命的な操作に対するルールは常に強制され、ここまでのどの設定でも無効にできません。

## 監査ログの記録範囲

| 変数 | 以前のエイリアス | 効果 |
| --- | --- | --- |
| `CC_SAFETY_NET_AUDIT_SCOPE=all\|blocked` | なし | 監査ログに記録するコマンド判定を選択します。既定値は `all` です。 |

- `all`（既定値であり、変数が未設定のときの動作）は、許可とブロックの両方のコマンド判定を記録します。
- `blocked` はプライバシーを最重視する設定で、拒否だけを記録します。
- この設定によって拒否の記録が省略されることは**ありません**。
- これ以外の値を指定した場合は拒否のみの記録に戻り、`doctor` が警告 `environment.audit-scope-invalid` として報告します。

許可の判定が記録されるのは、ツール呼び出しがコマンドとして処理された場合だけです。コマンド以外のツール呼び出しは、許可されても記録されません。

## デバッグ出力

| 変数 | 以前のエイリアス | 効果 |
| --- | --- | --- |
| `CC_SAFETY_NET_DEBUG=1` | なし | 解析中に例外が発生した理由や、ステータスライン用の Claude 設定ファイルの読み取りに失敗した理由などの診断メッセージを stderr に出力します。`CC_SAFETY_NET_LEVEL` が不正な場合の警告はこの変数では制御されず、常に出力されます。 |

`CC_SAFETY_NET_DEBUG` は、記録される判定の範囲を変えるものではありません。それを決めるのは `CC_SAFETY_NET_AUDIT_SCOPE` です。コマンドが許可された理由を調べるときや、バグ報告を作成するときに使ってください。設定されているかどうかは `doctor` コマンドが報告します。

## 設定ディレクトリの上書き

| 変数 | 以前のエイリアス | 効果 |
| --- | --- | --- |
| `CC_SAFETY_NET_HOME=<path>` | なし | `~/.cc-safety-net` の代わりに `<path>` を CC Safety Net のホームディレクトリとして使用します。 |

設定すると、`policy.json` は `<path>/policy.json` から、ユーザースコープの rulebook 設定は `<path>/rules/` から読み取られます。rulebook のロックファイルとキャッシュも同じ階層に置かれます。サンドボックス環境や、標準的でない `HOME` を使う構成（エージェントがシェルとは別のホームディレクトリで動作する場合など）で役立ちます。

<Note>
  `CC_SAFETY_NET_HOME` を設定しても、監査ログの場所は変わりません。監査ログのルートは別に解決されます。決まり方については[監査ログ](/ja/reference/audit-log#ログの配置)を参照してください。
</Note>

## 更新チェックを無効にする

| 変数 | 以前のエイリアス | 効果 |
| --- | --- | --- |
| `CC_SAFETY_NET_NO_UPDATE_CHECK=1` | なし | `rule doc` の実行中に走る更新チェックを無効にします。空でない値であれば何でも有効と見なされます。この変数は真偽値として解釈されないため、`0` を設定してもチェックは無効になります。 |

`rule doc` は通常、24 時間に 1 回まで新しいリリースの有無を確認します。`https://registry.npmjs.org/cc-safety-net/latest` を参照し、結果を `$HOME/.cc-safety-net/update-check.json` にキャッシュして、新しいバージョンがあれば stderr に `UPDATE_AVAILABLE:` の行を出力します。この確認は、`rule doc` の実行中に CLI が行う唯一の外部ネットワーク通信です。

`CC_SAFETY_NET_NO_UPDATE_CHECK` を設定すると、このチェックは完全にスキップされます。レジストリへの問い合わせも、キャッシュの書き込みも、`UPDATE_AVAILABLE:` の行も発生しません。`doctor` とダッシュボードが行う別の更新チェックには影響しません。

## 有効な設定を確認する

手早く確認したいときは `status` を、詳細なレポートが必要なときは `doctor` を実行します。

```bash
npx cc-safety-net status
npx cc-safety-net doctor
```

`doctor` レポートの Environment セクションには、各変数とその値、既定の動作、使用中の以前の `SAFETY_NET_*` 名が一覧表示されます。両コマンドの構文と出力の詳細は [CLI コマンド](/ja/reference/cli-commands)を、Claude Code 上で一目で状態を確認する方法は[ステータスライン](/ja/configuration/status-line)を参照してください。
