破壊的な `aws` コマンドをブロックするには、公式の `aws` ルールブックを導入します。CC Safety Net は `aws`、`terraform`、`gcloud`、`az` のそれぞれに 1 つずつルールブックを公開しており、コマンド 1 つで導入できます。

```bash
npx -y cc-safety-net rule add --only aws --global
```

ルールブックは JSON データです。CC Safety Net がルールブックを実行することはなく、ルールブックはブロックを追加するだけなので、組み込みの保護を弱めることはできません。ルールブックのファイル形式は[カスタムルール](/ja/configuration/custom-rules)で説明しています。

<Note>
公式ルールブックは `rulebook_version: 2` を使うため、CC Safety Net 2.3.0 以降が必要です。
</Note>

## カタログ

[`cc-safety-net/rulebooks`](https://github.com/cc-safety-net/rulebooks) リポジトリは、CLI ごとに 1 つのルールブックを提供しています。

| ルールブック | CLI | ブロック対象 |
|---|---|---|
| `terraform` | `terraform` | `destroy`、`apply -destroy`、`state rm`、`state push`、`workspace delete` |
| `aws` | `aws` | S3 オブジェクトとバケットの削除、`ec2 terminate-instances`、`cloudformation delete-stack`、RDS と DynamoDB の削除、`eks delete-cluster`、`kms schedule-key-deletion` |
| `gcloud` | `gcloud` | `projects delete`、`compute instances delete`、`storage rm`、Cloud SQL と GKE の削除、`kms keys versions destroy`、および alpha・beta・preview リリースチャネル |
| `azure` | `az` | `group delete`、`resource delete`、VM・AKS・ストレージ・SQL・Cosmos DB の削除、`keyvault purge` |

各ルールブックが扱うのは、それと分かる誤操作です。プロバイダーの API を網羅的にモデル化したものではありません。`aws s3 rm --dryrun`、`terraform state rm -dry-run`、`aws ec2 terminate-instances --dry-run` などの安全なプレビューは許可されたままです。各ルールブックには根拠ページがあり、各ルールがある理由、安全なプレビュー、意図的な除外、既知のギャップを記録しています：[terraform](https://github.com/cc-safety-net/rulebooks/blob/main/docs/terraform.md) · [aws](https://github.com/cc-safety-net/rulebooks/blob/main/docs/aws.md) · [gcloud](https://github.com/cc-safety-net/rulebooks/blob/main/docs/gcloud.md) · [azure](https://github.com/cc-safety-net/rulebooks/blob/main/docs/azure.md)。

## aws コマンドをすべてブロックできますか？

できません。どのルールにも `["s3", "rm"]` のような空でない [`command_path`](/ja/configuration/custom-rules#version-2-rules) が必要なので、引数にかかわらず `aws` だけで一致するルールは作れません。`aws` ルールブックがブロックするのは、カタログにある破壊的な操作です。さらにブロックしたい場合は、止めたい `aws` のコマンドパスごとに自分でルールを書いてください。

## 導入

基本はユーザースコープに導入します。`terraform` や `aws` は複数のプロジェクトで使うので、ルールも 1 つのリポジトリではなく、すべてのプロジェクトで適用されるべきです。

```bash
# Everything the repository publishes
npx -y cc-safety-net rule add cc-safety-net/rulebooks --global

# A selection
npx -y cc-safety-net rule add --only terraform aws --global

# Pin an immutable release tag instead of following the default branch
npx -y cc-safety-net rule add --ref v1.0.0 --only terraform --global
```

- `--only <rulebook...>` は、指定したルールブックを指定した順に追加します。リポジトリが公開していない名前を指定すると、追加は失敗します。
- `--ref <ref>` は、既定のブランチの代わりにブランチ、タグ、コミットを指定します。`--ref feature/rulebook-v2` のように、ref には `/` を含められます。
- 設定元を指定せずにどちらかのフラグを使うと、`cc-safety-net/rulebooks` が選ばれます。公開されているものをすべて導入するには、リポジトリ名を指定します。

`--global` を省くと、プロジェクトスコープに導入されます。このとき `rule add` はリポジトリの `.cc-safety-net/` 配下にルールブックのファイルを書き込むため、コミットすればチームメイト全員のクローンにルールが届きます。[チームセットアップ](/ja/guides/team-setup)を参照してください。

設定元の指定でルールブックを 1 つだけ追加することもできます。`rule list` が表示し、`rule remove` が受け取るのもこの形式です。

```bash
npx -y cc-safety-net rule add cc-safety-net/rulebooks#main/terraform --global
```

## 導入時に行われること

`rule add` は、選んだ各ルールブックを取得して検証し、テストフィクスチャを実行したうえで、自分のスコープの `rules/<name>/rulebook.json` にコピーします。内容の取得元のコミットも表示します。

CC Safety Net は、ツール呼び出しのたびにディスクからルールブックを読み取ります。ネットワークを使うのは `rule add` と `rule update` だけです。バックグラウンドでの取得も自動更新もないため、手元のコピーが変わるのは次のコマンドを実行したときだけです。

```bash
# Re-fetch every source and report added, removed, and modified rules
npx -y cc-safety-net rule update

# Refresh one source
npx -y cc-safety-net rule update cc-safety-net/rulebooks#main/terraform
```

ブランチの ref は、`rule update` のたびにその最新のコミットに進みます。リリースタグは変わらないため、`--ref v1.0.0` で導入した内容は、ref を切り替えるまで同じです。

## ルールのオーバーライドとルールブックの削除

ルールを 1 つ無効にしたりブロックの理由を置き換えたりするには、`rule.json` にオーバーライドを追加します。ルールブックのファイル自体は変わらないため、`rule update` とオーバーライドが競合することはありません。[ルールを 1 つ無効にする](/ja/configuration/custom-rules#turn-off-one-rule)を参照してください。ルールブックごと削除するには、次のようにします。

```bash
npx -y cc-safety-net rule remove cc-safety-net/rulebooks#main/terraform --global
```

## 任意のリポジトリから導入する

`.cc-safety-net/rules/<name>/rulebook.json` という配置でルールブックを公開している GitHub リポジトリなら、どれでも `rule add owner/repo` で導入できます。チームやベンダーも、同じ方法で独自のカタログを公開できます。

<Warning>
CC Safety Net がルールブックを実行することはなく、ルールブックはブロックを追加するだけです。ただし、ルールの理由は、コマンドがブロックされたときにエージェントが読むメッセージの一部になります。サードパーティのルールブックは追加する前に内容を確認してください。管理外のブランチを追うのではなく、自分で確認したタグやコミットを `--ref` で指定することを推奨します。
</Warning>

## ルールブックが効かないとき

`npx -y cc-safety-net rule list` は、有効なルールブックとそれぞれのルール数を表示します。`npx -y cc-safety-net explain "terraform destroy"` は、どのルールがその判定を下したかを示します。設定元が無効と表示される場合は、[ルールブックはライブファイル](/ja/configuration/custom-rules#rulebooks-are-live-files)を参照してください。
