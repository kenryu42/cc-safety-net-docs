`npx -y cc-safety-net@latest install` を実行し、一覧からコーディングエージェントを選びます。インストーラーは、選んだ各エージェントに CC Safety Net をプラグイン、拡張機能、フックのいずれかとして追加します。エージェントによっては、その後に再起動や信頼の確認が必要です。最後に `npx cc-safety-net doctor` を実行して、保護が有効になったことを確認してください。

<span id="before-you-install"></span>

## インストール前の確認

- Node.js 18 以降をインストールしてください。このページのコマンドは `npx` を使います。
- 使用するエージェントで、お使いのプラットフォームが対応しているか確認してください。

| プラットフォーム | エージェント |
| --- | --- |
| Windows、macOS、Linux | 下記以外のすべてのエージェント |
| macOS と Linux のみ | [Hermes Agent](/ja/installation/hermes-agent)、[OpenClaw](/ja/installation/openclaw) |
| web プロファイルは 3 つすべて、デスクトップアプリは macOS と Windows | [DeepSeek Harness](/ja/installation/deepseek-harness) |

Amp のマニュアルが対応対象として挙げているのは macOS、Linux、WSL で、ネイティブの Windows ではありません。

## 対話形式でインストールする

<Steps>
  <Step title="インストーラーを起動する">
    ```bash
    npx -y cc-safety-net@latest install
    ```

    マシン上で見つかったコーディングエージェントが一覧表示されます。
  </Step>
  <Step title="エージェントを選ぶ">
    `Space` でエージェントを選び、`Enter` で確定します。そのほかのキーは[ターゲットセレクターのキー](/ja/reference/cli/install#target-selector-keys)にまとめています。
  </Step>
  <Step title="エージェント側の手順を済ませる">
    フックが動作する前にエージェントの再起動や信頼の確認が必要な場合は、ここで済ませてください。必要な手順は、[エージェントごとのインストール](#install-for-one-agent)の表の「追加の手順」列に載っています。
  </Step>
  <Step title="保護が有効か確認する">
    ```bash
    npx cc-safety-net doctor
    ```
  </Step>
</Steps>

[`doctor`](/ja/reference/cli/doctor) は対応するすべてのエージェントをチェックし、失敗した項目があれば直し方を示します。

インストールコマンドの `@latest` は省略しないでください。npx はダウンロードしたパッケージをキャッシュに保存するため、バージョンを付けない `cc-safety-net` では、最新リリースではなくキャッシュに残った古いコピーが実行されることがあります。

## エージェントごとのインストール

スクリプトなどから 1 つのエージェントだけにインストールするには、下の表にあるそのエージェントのターゲットフラグを渡します。インストールで何が変わるか、そのエージェントのフックが何をチェックするか、どう削除するかは、各エージェントのページで説明しています。

| エージェント | インストールコマンド | 追加の手順 |
| --- | --- | --- |
| [Amp Code](/ja/installation/amp-code) | `npx -y cc-safety-net@latest install --amp` | Amp を再起動するか `plugins: reload` を実行 |
| [Antigravity CLI](/ja/installation/antigravity-cli) | `npx -y cc-safety-net@latest install --agy-cli` | |
| [Claude Code](/ja/installation/claude-code) | `npx -y cc-safety-net@latest install --claude-code` | |
| [Codex](/ja/installation/codex) | `npx -y cc-safety-net@latest install --codex` | `/hooks` でフックを信頼する |
| [Cursor](/ja/installation/cursor) | `npx -y cc-safety-net@latest install --cursor` | |
| [DeepSeek Harness](/ja/installation/deepseek-harness) | `npx -y cc-safety-net@latest install --deepseek-harness` | インストール前にデスクトップアプリを終了 |
| [Devin CLI](/ja/installation/devin-cli) | `npx -y cc-safety-net@latest install --devin` | |
| [Factory Droid](/ja/installation/factory-droid) | `npx -y cc-safety-net@latest install --droid` | |
| [Gemini CLI](/ja/installation/gemini-cli) | `npx -y cc-safety-net@latest install --gemini-cli` | Gemini CLI を再起動 |
| [GitHub Copilot CLI](/ja/installation/github-copilot-cli) | `npx -y cc-safety-net@latest install --copilot-cli` | Copilot CLI を再起動 |
| [Grok Build](/ja/installation/grok-build) | `npx -y cc-safety-net@latest install --grok-build` | |
| [Hermes Agent](/ja/installation/hermes-agent) | `npx -y cc-safety-net@latest install --hermes-agent` | Hermes を再起動 |
| [Kimi Code](/ja/installation/kimi-code) | `npx -y cc-safety-net@latest install --kimi-code` | グローバルフックとネイティブプラグインのどちらかを選ぶ |
| [OpenClaw](/ja/installation/openclaw) | `npx -y cc-safety-net@latest install --openclaw` | OpenClaw Gateway を再起動 |
| [OpenCode](/ja/installation/opencode) | `npx -y cc-safety-net@latest install --opencode` | OpenCode を再起動 |
| [Pi](/ja/installation/pi) | `npx -y cc-safety-net@latest install --pi` | Pi を再起動 |

インストールコマンドは何度実行しても安全です。設定済みのエージェントで再実行しても、管理対象のエントリは 1 つだけ残ります。

## CC Safety Net を更新する

```bash
npx -y cc-safety-net@latest update
```

`update` は、マシンにインストール済みの連携をすべて更新します。新しい連携をインストールすることはありません。エージェントごとの動作は [`update`](/ja/reference/cli/update) を参照してください。

### v1 または 2.2 以前からのアップグレード

- **v1 から。** `update` を実行すると、インストール済みの連携がすべて現在のリリースに移行します。v1 のインライン設定でカスタムルールを定義していた場合は、[旧形式の設定の移行](/ja/configuration/custom-rules#migrate-legacy-configuration)を済ませてください。その後、`npx cc-safety-net doctor` でランタイムが `ready` になっていることを確認します。
- **2.2 以前で、GitHub からルールブックを導入していた場合。** アップグレード後、スコープごとに [`rule sync`](/ja/reference/cli/rule#rule-sync) を 1 回実行してください。ユーザースコープの設定元には `--global` を付けます。実行するまでそのルールは無効なままで、`status` と `doctor` は degraded の設定元として報告します。

## CC Safety Net をアンインストールする

インストーラーのアンインストール用のセレクターを使うか、ターゲットフラグを 1 つ渡します。

```bash
npx -y cc-safety-net@latest uninstall
npx -y cc-safety-net@latest uninstall --cursor
```

アンインストールで削除するのは、CC Safety Net が管理しているものだけです。何が削除されるかは、各エージェントのページに記載しています。

## CLI をグローバルにインストールする

CLI を頻繁に使う場合は、グローバルにインストールしてください。グローバルインストールでは、同じコマンドを短く書けるエイリアス `ccsn` も追加されます。

```bash
npm install -g cc-safety-net
ccsn doctor
```

このエイリアスはグローバルインストールにのみ含まれます。`npx` で実行する場合は、`cc-safety-net` という完全な名前を使ってください。

<span id="migrate-from-a-legacy-plugin-identifier"></span>

## 旧プラグイン識別子からの移行

以前のリリースでは、Claude Code と Codex がプラグイン識別子 `safety-net@cc-marketplace` を、GitHub Copilot CLI が `copilot-safety-net` を使っていました。各エージェントの通常のインストールコマンドが古いプラグインを削除するため、手作業で削除する必要はありません。新しく設定を書くときは、現在の識別子 `cc-safety-net@cc-marketplace` を使ってください。
