`explain` は、CC Safety Net がコマンドを解析する過程を手順ごとに表示します。コマンドがブロックまたは許可される理由や、カスタムルールの適用のされ方を確かめるときに使います。

```bash
npx cc-safety-net explain "git reset --hard"
bunx cc-safety-net explain "git reset --hard"
```

## explain のオプション

| フラグ | 説明 |
| --- | --- |
| `--json` | 解析結果の全体を JSON として出力する |
| `--cwd <path>` | この作業ディレクトリから実行したものとして解析する |
| `--shell <auto\|posix\|powershell>` | このシェルとしてコマンドを読み取る。既定値は `auto` |
| `-h`, `--help` | ヘルプを表示する |

```bash
npx cc-safety-net explain "rm -rf /"
npx cc-safety-net explain --json "git checkout -- file.txt"
npx cc-safety-net explain --cwd /tmp "git status"
npx cc-safety-net explain --shell posix 'rmdir /s /q d:\'
```

`--json` のスキーマ、`ExplainResult` のフィールド、`TraceStep` の全種類は、[explain トレースリファレンス](/ja/reference/explain-trace)を参照してください。

## ツールが実行するシェルとしてコマンドを読み取る

`explain` の既定のシェルモードは `auto` で、PowerShell に見えるコマンドは PowerShell として読み取ります。ただし、エージェントのツールは別のシェルを実行していることがあります。Claude Code の `Bash` ツールは POSIX を実行するため、`auto` のままだとフックが出していない判定を報告することがあります。

| コマンド | 結果 | ルール ID |
| --- | --- | --- |
| `explain 'rmdir /s /q d:\'` | ブロック | `powershell.remove-item-root-or-home` |
| `explain --shell powershell 'rmdir /s /q d:\'` | ブロック | `powershell.remove-item-root-or-home` |
| `explain --shell posix 'rmdir /s /q d:\'` | 許可 | |

bash の `rmdir` は空のディレクトリしか削除しないため、`Bash` ツールからのこの呼び出しはフックでは許可されます。`--shell posix` を付ければ、その許可を再現できます。このフラグはコマンドの解析方法と適用されるシェルのルールの両方を切り替えるので、判定を再現したいツールの方言を指定してください。

`--shell powershell` では、引数を分けて渡したコマンドを PowerShell の引用規則で連結するため、その中のアポストロフィは POSIX のエスケープではなく二重化されます。それ以外の方言では POSIX のエスケープのままです。

`auto`、`posix`、`powershell` 以外の値を渡すと、エラーと使用方法の行を出力して `1` で終了します。

```text
Error: --shell must be auto, posix, or powershell, got: bash
Usage: cc-safety-net explain [--json] [--cwd <path>] [--shell <auto|posix|powershell>] <command>
```

## ダッシュで始まるコマンドを explain する

`--` でオプションの解析が終わり、その後ろはすべてコマンドとして扱われます。そのため `explain -- --help` はヘルプを出力せず、リテラルのコマンド `--help` を解析します。`|` や `&&` などのシェル演算子をコマンドに残すには、コマンド全体を 1 つの引数として引用符で囲みます。

## explain の終了コード

`explain` は、結果がブロックでも許可でも `0` で終了します。終了コードではなく `result` フィールドを読んでください。`1` で終了するのは、不明なオプション、存在しない `--cwd` パス、不明な `--shell` の値といったオプションエラーの場合と、解析を拒否したコマンドの場合です。

## explain が解析を拒否するコマンド

CC Safety Net の解析上限を超えるコマンドや、`echo ${` のようにパーサーが構文を受け付けないコマンドは、`explain` が解析を拒否します。このとき 1 行のエラーを出力して `1` で終了します。`--json` を付けると、標準出力にはエラーオブジェクトだけが出力されます。

```bash
npx cc-safety-net explain --json 'echo ${'
```

```json
{"error":"Command could not be safely analyzed (strict mode). Simplify the command and retry, or ask the user to verify."}
```

エージェントがこのようなコマンドを実行すると、CC Safety Net は[固定の拒否 ID](/ja/reference/blocked-commands#fixed-denial-ids) でブロックします。

## explain の出力を共有する

<Warning>
  explain の出力には、入力したコマンド、そのトークン、ホームディレクトリを含む絶対パスが含まれることがあります。共有する前に、[トレースを共有する前に](/ja/reference/explain-trace#before-you-share-a-trace)を確認してください。
</Warning>
