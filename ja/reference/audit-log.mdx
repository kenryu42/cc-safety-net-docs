CC Safety Net は、コマンドの判定を 1 件ずつ監査ログに記録します。ログはローカルマシンにだけ保存され、アップロードされることはありません。各ファイルは JSON Lines（JSONL）形式で、1 行に 1 つの JSON オブジェクトを記録します。[ダッシュボード](/ja/guides/dashboard)で読むか、ターミナルで [`logs`](/ja/reference/cli/logs) を使って読みます。

<span id="log-layout"></span>

## ログの配置

レコードは、プロジェクトごと、月ごとのパスに書き込まれます。

```text
~/.cc-safety-net/logs/<encoded-cwd>/<YYYY-MM>/<YYYY-MM-DD>-<session-id>.jsonl
```

| パスの要素 | 内容 |
| --- | --- |
| `<encoded-cwd>` | 作業ディレクトリの英数字以外の文字をすべて `-` に置き換えたもの。作業ディレクトリがない場合は `no-cwd` |
| `<session-id>` | エージェントのセッション ID。ファイル名に使えない文字は置き換えられる |

`CC_SAFETY_NET_AUDIT_HOME` で、監査ルートを置くホームディレクトリを変更できます。CC Safety Net はディレクトリをモード `0700`、ファイルをモード `0600` で作成します。書き込みに失敗しても、許可やブロックの判定が変わることはありません。

`~/.cc-safety-net/logs/` の直下にあるフラットな `*.jsonl` ファイルは、以前のバージョンのレガシー配置です。`logs` はこれらも読み取り、保持期間による削除の対象にもなります。今すぐ削除するには、[`logs --prune-legacy`](/ja/reference/cli/logs#delete-legacy-log-files) を参照してください。

## 各レコードには 1 つの判定が入る

各行には、許可またはブロックしたコマンドの判定が 1 件記録されます。内容は、コマンド、判定の決め手になったセグメント、理由、一致したルールです。

- CC Safety Net は、コマンドの出力、モデルへのプロンプト、ツールの結果、会話の内容を読み取ることも保存することもありません。
- 拒否は常に記録します。
- 許可の判定を記録するのは、コマンドのツール呼び出しだけです。許可されたファイルの編集や読み取りは記録されません。
- フェイルクローズのパスによるブロックも記録します。これは、解析に失敗して判定に到達できないため、CC Safety Net がコマンドをブロックした場合です。このレコードには `failureStage` と `errorCode` が設定され、`logs --suspect` はこれらのフィールドを使います。

<span id="record-schema"></span>

## レコードスキーマ

| フィールド | 型 | 有無 | 説明 |
| --- | --- | --- | --- |
| `ts` | string | 常にある | 判定の ISO 8601 タイムスタンプ |
| `id` | string | 常に書き込まれる | 16 文字の 16 進数。`logs --id` に渡す ID |
| `v` | string | 任意 | レコードを書き込んだ CC Safety Net のバージョン、または `dev` |
| `sessionId` | string | 任意 | サニタイズされたエージェントのセッション ID |
| `decision` | `"allow" \| "deny"` | 任意。既定値は `"deny"` | 判定 |
| `agent` | string | 任意 | 連携 ID。例：`claude-code` |
| `shape` | string | 任意 | レコードの元になったアダプターの入力形式 |
| `level` | string | 任意 | 判定時に有効だった安全レベル |
| `configFallback` | `true` | 任意 | フォールバックポリシーで判定した場合にある |
| `toolName` | string | 任意 | ツール名 |
| `command` | string | 常にある | コマンド全体。マスク済み |
| `segment` | string | 常にある | 判定の決め手になったセグメント。マスク済み |
| `truncated` | `true` | 任意 | 長いフィールドが切り詰められた場合にだけある |
| `reason` | string | 常にある | 人が読める判定理由 |
| `ruleId` | string | 拒否のレコード | 呼び出しをブロックしたルールまたは[固定の拒否](/ja/reference/blocked-commands#fixed-denial-ids)の ID。許可のレコード、Copilot CLI の拒否 `Failed to parse toolArgs JSON.`、以前のバージョンが書き込んだ一部の拒否のレコードにはない |
| `intent` | string | 任意 | ブロックの意図の分類 |
| `failureStage` | string | 任意 | フェイルクローズになった検査による拒否の場合に設定される |
| `errorCode` | string | 任意 | `path-canonicalization-limit`、`tool-input-limit`、`structural-shell-syntax-limit`、`unparseable-command`、`unexpected-error` のいずれか |
| `cwd` | string \| `null` | 任意 | 作業ディレクトリ。マスク済み |

レコードの例：

```json
{"ts":"2025-01-15T10:30:00.000Z","id":"3fa9c2d1a70e8b42","v":"2.0.0","sessionId":"a1b2c3","decision":"deny","agent":"claude-code","level":"standard","command":"git reset --hard","segment":"git reset --hard","reason":"git reset --hard destroys all uncommitted changes permanently. Use 'git stash' first.","ruleId":"git.reset-hard","cwd":"/path/to/project"}
```

CC Safety Net は、長い `segment`、`toolName`、`cwd` の値を切り詰め、レコードに `truncated: true` を設定します。長い `command` も同じように切り詰めますが、`failureStage` を持つレコードではコマンド全体を残します。このフラグが `false` として書き込まれることはありません。

### failureStage の値

`failureStage` は、フェイルクローズになった検査を示します。検査は[仕組み](/ja/guides/how-it-works#what-gets-checked-in-order)に示した順に実行されます。

| `failureStage` | 失敗した箇所 |
| --- | --- |
| `policy-protection` | サイズ上限内でのツール入力の読み取り、ポリシーファイルの保護、Git メタデータの保護 |
| `command-validation` | コマンドの検証。宣言したコマンド用ツールの作業ディレクトリ引数、入力の長さ・語数・ネストの上限、空のコマンド |
| `config-load` | ポリシーの読み込みと安全レベルの決定 |
| `secret-protection` | 機密パスの保護 |
| `non-command` | コマンドではないツール呼び出しの処理 |
| `command-analysis` | 破壊的コマンドの解析。宣言したコマンドの再帰上限を含む |

入力の上限、宣言したコマンド用ツールの検査、ポリシーファイルの保護、Git メタデータの保護による拒否は、ポリシーを読み込む前に発生します。そのため、これらのレコードには `level` も `configFallback` もありません。

<span id="what-is-recorded-audit-scope"></span>

## 記録内容：監査の対象範囲

`CC_SAFETY_NET_AUDIT_SCOPE` は、拒否に加えて許可されたコマンドの判定もログに記録するかを決めます。

| 値 | 効果 |
| --- | --- |
| 未設定 | 既定値。`all` と同じ動作 |
| `all` | 許可とブロックの両方のコマンド判定を記録する |
| `blocked` | 拒否だけを記録する。保存するデータが最も少ない設定 |
| それ以外 | 拒否だけを記録し、[`doctor`](/ja/reference/cli/doctor) が `environment.audit-scope-invalid` を報告する |

対象範囲の設定で拒否の記録が止まることはありません。この設定が決めるのは、許可の判定を記録するかどうかだけです。

<span id="retention"></span>

## 保持期間

| 設定 | 値 |
| --- | --- |
| 既定の保持期間 | 30 日 |
| 設定できる範囲 | 1～365 日 |
| 設定キー | `policy.json` の `audit.retention_days` |

無効な値の扱いは、[監査ログの保持期間](/ja/configuration/policy#audit-retention)を参照してください。同じ値が `logs --since` の上限になり、ダッシュボードのアクティビティ画面で選べる期間も制限します。

CC Safety Net は、次に動作したときに期限切れのレコードを削除します。具体的には、レコードを書き込んだ後と、`logs`、`doctor`、ダッシュボードがログを読み取る前です。タイマーで動く処理はないため、CC Safety Net が動いていない間は期限切れのレコードがディスクに残ることがあり、`logs --id` で見つかる場合もあります。

<Warning>
  保持期間の短縮は元に戻せません。値を小さくすると、古いレコードが次回の実行で削除対象になり、CC Safety Net はアーカイブもゴミ箱も取り消しもなしに削除します。ダッシュボードでは、値を小さくする前に確認を求めます。
</Warning>

<span id="secret-redaction"></span>

## シークレットのマスク処理

CC Safety Net は、レコードを書き込む前に、コマンド、セグメント、ツール名、作業ディレクトリをマスクします。次の値を認識すると `<redacted>` に置き換えます。

- 名前に `TOKEN`、`SECRET`、`PASSWORD`、`PASS`、`KEY`、`CREDENTIALS` を含む環境変数の代入
- データベース接続の変数（`DATABASE_URL`、`POSTGRES_URL`、`MYSQL_URL`、`REDIS_URL`、`MONGODB_URL`、およびそのほかの DSN、URL、URI、接続文字列の変数）
- PEM 形式の秘密鍵ブロック（`-----BEGIN ... PRIVATE KEY-----`）
- シークレットを含む HTTP ヘッダー（`Authorization`、`Cookie`、`X-API-KEY`、`API-KEY`）
- URL 内の資格情報（`scheme://user:pass@host` と `scheme://token@host`）と `-u user:pass`
- 署名付き URL の署名クエリパラメーター。`x-amz-signature`、`x-goog-signature`、`sig`、`signature` の値
- 決まった一覧にあるプロバイダーのトークン形式（`ghp_...`、`gho_...`、`xoxb-...`、`npm_...`、`sk_live_...`、`rk_live_...`、`pypi-...` など）
- JWT（`eyJ...`）と AWS のアクセスキー ID（`AKIA...` / `ASIA...`）

<Warning>
  マスク処理の範囲は限られています。決まったパターンの一覧で照合しているだけで、分類器ではありません。ファイルシステムの絶対パス、プロジェクト名やディレクトリ名、ホスト名、IP アドレス、ユーザー名、チケット ID、ファイル名、一覧にない形式の資格情報は、そのまま残ります。`reason` フィールドもマスクしません。監査ログは機密性のあるローカルデータとして扱い、Issue やチャットに抜粋を貼り付ける前に内容を確認してください。
</Warning>

ファイルの権限は、ログを読める人を制限するだけです。内容をマスクするわけでも、共有して安全な状態にするわけでもありません。
