CC Safety Net をインストールし、有効になっていることを確認してから、無害なコマンドがブロックされるところを見てみましょう。手順は、対応するすべてのエージェントで共通です。

<Steps>
  <Step title="エージェントに CC Safety Net をインストールする">
    エージェントごとに、プラグインマーケットプレイス、拡張機能、設定ファイル、パッケージインストールのいずれかを使います。[エージェントごとのインストール](/ja/installation#install-for-one-agent)で使用するエージェントのインストールコマンドを実行してから、このページに戻ってください。
  </Step>
  <Step title="状態を確認する">
    どの保護が有効になっているかを 1 画面で確認できます。

    ```bash
    npx cc-safety-net status
    ```

    設定が正常に読み込まれると、判定行に `ready` と表示されます。`degraded` は、CC Safety Net が設定の一部を適用できず、フォールバックで動作していることを示します。修復方法は[設定の復旧](/ja/configuration/recovery)を参照してください。`status` の表示内容の詳細は、[status コマンドのリファレンス](/ja/reference/cli/status)にあります。
  </Step>
  <Step title="doctor を実行する">
    `status` は設定内容を要約します。`doctor` は、各エージェントとの連携をエンドツーエンドでテストします。

    ```bash
    npx cc-safety-net doctor
    ```

    対応するエージェントをすべて一度に確認するため、使用中のエージェントを指定する必要はありません。ブロックが機能することを確かめるセルフテストも実行します。問題がなければ、各項目の横に緑色のチェックマークが表示されます。失敗した項目には、`doctor` が原因と対処方法を表示します。確認項目の一覧は、[doctor コマンドのリファレンス](/ja/reference/cli/doctor)にあります。
  </Step>
  <Step title="実際のブロックを確認する">
    CC Safety Net が有効な状態で、エージェントに次の無害な確認コマンドを実行させます。

    ```bash
    # This exclusion-only pathspec selects no files
    git checkout -- ':(exclude,top)**'
    ```

    このコマンドはシェルに届かず、エージェントは代わりにブロックメッセージを受け取ります。保護が有効でない場合でも、この除外専用の Git pathspec はファイルを 1 つも選択しないため、Git が追跡対象のファイルを変更することはありません。

    <pre className="cc-block-message-output"><code>{`BLOCKED by CC Safety Net

Reason: git checkout -- discards uncommitted changes permanently. Use 'git stash' first.

Command: git checkout -- ':(exclude,top)**'

If this operation is truly needed, ask the user for explicit permission and have them run the command manually.`}</code></pre>

    メッセージには、ブロックした理由と、エージェントが次に取れるより安全な操作が示されます。メッセージの構造と判定のライフサイクル全体は、[仕組み](/ja/guides/how-it-works#what-a-block-looks-like)を参照してください。
  </Step>
  <Step title="何も実行せずに理由を確認する">
    判定が予想と違うときは、`explain` を使います。コマンド文字列を実行せずに、同じエンジンで評価します。

    ```bash
    npx cc-safety-net explain "git checkout -- ':(exclude,top)**'"
    ```

    判定、一致したルール、実際に適用されている設定が表示されます。

    <Warning>
      出力にはパス、ホスト名、プロジェクト名が含まれることがあります。どこかに貼り付ける前に、[トレースを共有する前に](/ja/reference/explain-trace#before-you-share-a-trace)を読んでください。
    </Warning>
  </Step>
</Steps>
