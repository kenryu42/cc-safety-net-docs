CC Safety Net reads its settings from `policy.json`, `rule.json`, and the `CC_SAFETY_NET_*` environment variables on this page. Set a variable in your shell or your agent's launch environment before you start the agent. An environment variable can raise your safety level but never lower it.

Older `SAFETY_NET_*` names without the `CC_` prefix still work where the tables list them. For what each level blocks, see [Modes](/configuration/modes). For the policy file, see [Policy](/configuration/policy).

## Where configuration lives

| File | User scope | Project scope | With `CC_SAFETY_NET_HOME=<path>` |
| --- | --- | --- | --- |
| Policy | `~/.cc-safety-net/policy.json` | `.cc-safety-net/policy.json` | `<path>/policy.json` |
| Rule config | `~/.cc-safety-net/rules/rule.json` | `.cc-safety-net/rules/rule.json` | `<path>/rules/rule.json` |
| Rulebooks | `~/.cc-safety-net/rules/<name>/rulebook.json` | `.cc-safety-net/rules/<name>/rulebook.json` | `<path>/rules/<name>/rulebook.json` |
| Audit log | `~/.cc-safety-net/logs/` | None. The user log keeps one folder per project | Not moved |

Project paths are relative to the directory the agent session runs in. See [config working directory](/configuration/policy#what-the-config-working-directory-is).

| Variable | Legacy alias | Effect |
| --- | --- | --- |
| `CC_SAFETY_NET_HOME=<path>` | none | Use `<path>` instead of `~/.cc-safety-net` for the user-scope files in the table above |

`CC_SAFETY_NET_HOME` helps when an agent runs with a different home directory than your shell, as in a sandbox. It moves the user scope only. Project files always resolve from the project. It does not move the audit log. [Audit log](/reference/audit-log#log-layout) explains how to move that.

CC Safety Net protects only `policy.json` from the agent. `rule.json` and rulebooks are ordinary files an agent can edit.

## Safety level

| Variable | Legacy alias | Effect |
| --- | --- | --- |
| `CC_SAFETY_NET_LEVEL=standard\|strict\|paranoid` | none | Select a safety preset. Raises the level configured by `safety.level` in `policy.json`, and never lowers it. |

Each preset turns on a set of three capabilities: `fail_closed`, `paranoid_rm`, and `paranoid_interpreters`. See [Modes](/configuration/modes) for what each one blocks.

CC Safety Net ignores any other value, keeps the level from `policy.json`, and always prints this warning on stderr:

```
CC Safety Net: ignored invalid CC_SAFETY_NET_LEVEL="<value>". Use standard, strict, paranoid.
```

An empty value counts as unset and prints no warning.

## Capability toggles

These older per-capability flags only raise their capability. A falsy value does not turn a capability off. To turn a capability off below its preset, use `safety.overrides` in [policy.json](/configuration/policy#safety-level-and-capability-overrides).

| Variable | Legacy alias | Effect |
| --- | --- | --- |
| `CC_SAFETY_NET_STRICT=1` | `SAFETY_NET_STRICT` | Force the `fail_closed` capability on. Equivalent to `safety.overrides.fail_closed: true`. |
| `CC_SAFETY_NET_PARANOID=1` | `SAFETY_NET_PARANOID` | Force both `paranoid_rm` and `paranoid_interpreters` on. It does not set `fail_closed`. |
| `CC_SAFETY_NET_PARANOID_RM=1` | `SAFETY_NET_PARANOID_RM` | Force `paranoid_rm` on, which blocks non-temp `rm -r`, `rm -rf`, and `find -delete` even when the target is inside the working directory. |
| `CC_SAFETY_NET_PARANOID_INTERPRETERS=1` | `SAFETY_NET_PARANOID_INTERPRETERS` | Force `paranoid_interpreters` on, which blocks every interpreter one-liner whatever its content. |
| `CC_SAFETY_NET_WORKTREE=1` | `SAFETY_NET_WORKTREE` | Relax local-discard git rules inside a confirmed linked worktree. Either this or `workflow.worktree_mode` turns worktree mode on. |

A flag is on when set to `1` or `true`, in any case. When a `CC_SAFETY_NET_*` name is set, it wins, and CC Safety Net reads the `SAFETY_NET_*` alias only when the prefixed name is absent.

## Precedence

CC Safety Net combines policy and environment in a fixed order:

1. **Preset.** `safety.level` in `policy.json` supplies the inherited capability defaults. When the field is absent, the preset is `standard`.
2. **`CC_SAFETY_NET_LEVEL`.** The effective base level is the higher of the policy level and the environment level. The environment can raise the level but never lower it.
3. **`safety.overrides.*`.** Explicit capability overrides in `policy.json` can then set `fail_closed`, `paranoid_rm`, or `paranoid_interpreters` to `true` or `false`.
4. **Capability toggles.** CC Safety Net applies the `CC_SAFETY_NET_STRICT`, `CC_SAFETY_NET_PARANOID`, `CC_SAFETY_NET_PARANOID_RM`, and `CC_SAFETY_NET_PARANOID_INTERPRETERS` flags last. These flags are monotonic. Each one forces its capability to `true`, and none can turn a capability off.
5. **Worktree mode** is the logical OR of `workflow.worktree_mode` and `CC_SAFETY_NET_WORKTREE`.

CC Safety Net derives the reported effective level from the resulting capability values. It reports a combination that matches no preset as `custom`, for example `paranoid_rm` on with `fail_closed` off.

CC Safety Net applies per-rule entries in `destructive_command_protection.overrides` on top of the state the capabilities set. Catastrophic rules always apply, and none of the above can disable them.

## Project policy weakenings

| Variable | Legacy alias | Effect |
| --- | --- | --- |
| `CC_SAFETY_NET_PROJECT_TIGHTEN_ONLY=1` | none | Ignore the fields of a project `.cc-safety-net/policy.json` that weaken the user policy. The project file's tightenings still apply. Off by default. |

Without the switch, a project `safety.overrides` entry can turn off a capability that `CC_SAFETY_NET_LEVEL` enables, because overrides apply after the level (step 3 above). The capability toggles apply last, so a project file never turns them off. See [Ignore project weakenings](/configuration/policy#ignore-project-weakenings) for the fields the switch drops.

## Audit scope

| Variable | Legacy alias | Effect |
| --- | --- | --- |
| `CC_SAFETY_NET_AUDIT_SCOPE=all\|blocked` | none | Which command decisions reach the audit log. Defaults to `all`. `blocked` records denials only. |

The audit log always records denials. See [Audit scope](/reference/audit-log#what-is-recorded-audit-scope) for what an invalid value does.

## Debug output

| Variable | Legacy alias | Effect |
| --- | --- | --- |
| `CC_SAFETY_NET_DEBUG=1` | none | Print diagnostic messages to stderr, such as the reason an analysis exception occurred. |

Use it when you investigate why a command was allowed or when you file a bug report. It does not change what the audit log records.

## Update-check opt-out

| Variable | Legacy alias | Effect |
| --- | --- | --- |
| `CC_SAFETY_NET_NO_UPDATE_CHECK=1` | none | Skip the update check that `rule doc` runs. Any non-empty value counts, even `0`. |

It does not affect the update check that `doctor` and the dashboard run. See [`rule doc` update notice](/reference/cli/rule#rule-doc-update-notice) for the notice it prints.

## Check your active configuration

[`status`](/reference/cli/status) shows the effective level and any problems. The Environment section of [`doctor`](/reference/cli/doctor) lists each variable, its value, and any legacy `SAFETY_NET_*` name in use.
