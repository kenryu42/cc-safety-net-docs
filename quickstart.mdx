Install CC Safety Net, confirm it is active, and watch it block a harmless command. The steps are the same for every supported agent.

<Steps>
  <Step title="Install CC Safety Net for your agent">
    Each agent uses a plugin marketplace, extension, configuration file, or package install. Run the install command for your agent from [Install for one agent](/installation#install-for-one-agent), then return here.
  </Step>
  <Step title="Check the status">
    Get a one-screen summary of which protections are active:

    ```bash
    npx cc-safety-net status
    ```

    The verdict line reads `ready` when your configuration loaded cleanly. `degraded` means CC Safety Net could not apply part of your configuration and is using a fallback. See [Configuration recovery](/configuration/recovery) to repair it. For everything `status` prints, see the [status command reference](/reference/cli/status).
  </Step>
  <Step title="Run doctor">
    `status` summarizes your configuration. `doctor` tests each agent's integration end to end:

    ```bash
    npx cc-safety-net doctor
    ```

    It checks every supported agent at once, so you do not have to tell it which one you use. It also runs a self-test that confirms blocking works. A clean run prints a green checkmark next to each item. For each item that fails, `doctor` explains what went wrong and how to fix it. The full check list is in the [doctor command reference](/reference/cli/doctor).
  </Step>
  <Step title="See a real block">
    With CC Safety Net active, ask your agent to run this harmless probe:

    ```bash
    # This exclusion-only pathspec selects no files
    git checkout -- ':(exclude,top)**'
    ```

    The command never reaches your shell. Your agent gets a block message instead. If protection is inactive, the exclusion-only Git pathspec selects no files, so Git changes no tracked file.

    <pre className="cc-block-message-output"><code>{`BLOCKED by CC Safety Net

Reason: git checkout -- discards uncommitted changes permanently. Use 'git stash' first.

Command: git checkout -- ':(exclude,top)**'

If this operation is truly needed, ask the user for explicit permission and have them run the command manually.`}</code></pre>

    The message explains the block and gives the agent a safer next action. For the message structure and the rest of the decision lifecycle, see [How it works](/guides/how-it-works#what-a-block-looks-like).
  </Step>
  <Step title="Ask why, without running anything">
    If a decision surprises you, `explain` evaluates a command string through the same engine without executing it:

    ```bash
    npx cc-safety-net explain "git checkout -- ':(exclude,top)**'"
    ```

    It prints the verdict, the rule that matched, and the effective configuration.

    <Warning>
      The output can contain your paths, hostnames, and project names. Read [Before you share a trace](/reference/explain-trace#before-you-share-a-trace) before you paste it anywhere.
    </Warning>
  </Step>
</Steps>
