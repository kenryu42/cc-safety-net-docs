sidebarTitle: "Quickstart"

---

This guide takes you from installed to a real blocked command in a few minutes. The steps are agent-neutral: they are the same whichever supported agent you use.

<Steps>
  <Step title="Install CC Safety Net for your agent">
    Each integration is wired up differently underneath — a plugin marketplace, an extension, a config file, or a package install. Follow the section for your agent on the **[Installation](/installation)** page, then come back here.

    That page is the single source of truth for install and uninstall steps, so this guide does not repeat them and they cannot drift out of sync.
  </Step>
  <Step title="Check the status">
    Get a one-screen summary of what is currently enforcing:

    ```bash
    npx cc-safety-net status
    ```

    The verdict line reads `ready` when your configuration loaded cleanly. `degraded` means something in your configuration could not be applied and a fallback is in force — see [Configuration recovery](/configuration/recovery) for what is still protecting you and how to repair it. If you use Claude Code, the verdict reads `not enforcing` while the plugin is disabled.

    `status` is purely informational and always exits `0`. For everything it prints, see the [status command reference](/reference/cli-commands#status).
  </Step>
  <Step title="Run doctor">
    Where `status` summarizes your configuration, `doctor` verifies the wiring end to end:

    ```bash
    npx cc-safety-net doctor
    ```

    It checks every supported agent at once, so you do not have to tell it which one you use. It also runs a self-test that confirms blocking works. A clean run prints a green checkmark next to each item; anything that fails explains what went wrong and how to fix it. The full check list is in the [doctor command reference](/reference/cli-commands#doctor).
  </Step>
  <Step title="See a real block">
    With CC Safety Net active, ask your agent to run these two commands and watch the difference:

    ```bash
    # Blocked — discards uncommitted changes permanently
    git checkout -- README.md

    # Allowed — creates a new branch, no data loss
    git checkout -b test-branch
    ```

    The first never reaches your shell. Your agent gets a block message instead:

    <pre className="cc-block-message-output"><code>{`BLOCKED by CC Safety Net

Reason: git checkout -- discards uncommitted changes permanently. Use 'git stash' first.

Command: git checkout -- README.md

If this operation is truly needed, ask the user for explicit permission and have them run the command manually.`}</code></pre>

    Your agent typically explains what happened, suggests a safer alternative, and asks whether you want to proceed manually. The second command runs normally. For the anatomy of that message and the rest of the decision lifecycle, see [How it works](/guides/how-it-works#what-a-block-looks-like).
  </Step>
  <Step title="Ask why, without running anything">
    If a decision surprises you, `explain` evaluates a command string through the same engine without executing it:

    ```bash
    npx cc-safety-net explain "git checkout -- README.md"
    ```

    It prints the verdict, the rule that matched, and the effective configuration behind it. Use a placeholder command like the one above while you are exploring.

    <Warning>
      An explain trace echoes the command you passed, its parsed tokens, and absolute paths including your home directory. Credential-shaped values are redacted, but paths, hostnames, and project names are not — review the output before pasting it into an issue or a chat. See the [explain trace reference](/reference/explain-trace) for the full trace and its sharing caveats.
    </Warning>
  </Step>
</Steps>
