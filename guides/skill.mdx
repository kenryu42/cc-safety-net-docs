CC Safety Net ships a skill that lets your coding agent operate CC Safety Net for you. Ask it why a command was blocked, have it write a rulebook rule, or have it check your installation. It runs the `cc-safety-net` CLI, reads the output, and reports back in plain language.

The skill operates CC Safety Net. It does not enforce anything. Protection comes from the hook, which runs whether or not the skill is loaded.

## How you invoke it

The skill ships inside the Claude Code plugin and the Codex plugin, so installing either one installs the skill.

| Agent | Invocation |
| --- | --- |
| Claude Code | `/cc-safety-net:cc-safety-net`, listed under the plugin's namespace |
| Codex | Installed with the Codex plugin. Invoke it as Codex invokes skills |
| Pi and OpenCode | `/cc-safety-net`, a built-in command their integrations register |
| Antigravity CLI and Kimi Code | Add the skill with `npx skill add kenryu42/cc-safety-net`, then invoke it as the agent invokes skills |

Whatever you type after the invocation becomes the request. The examples on this page use `/cc-safety-net`:

```text
/cc-safety-net why was my last git command blocked
/cc-safety-net block terraform destroy in this project
```

The skill runs only when you invoke it. The model cannot load it on its own mid-task.

## When to reach for it

- A command was blocked with `BLOCKED by CC Safety Net` and you want the step-by-step reason.
- A block looks wrong and you want it triaged: reproduce the decision, fix the custom rule responsible, or report a built-in false positive.
- You want custom blocking rules written, edited, or migrated for you.
- You want the safety level changed, a protection toggled, or a path list adjusted.
- You want CC Safety Net installed into, updated in, or removed from another agent CLI.
- A rule you added does not fire, or you want to confirm protection is active.
- You want to know why the analyzer treats a construct a certain way, beyond what `explain` and `rule doc` show.

## What each workflow does

The skill routes your request to one of seven workflows.

**Explain a decision.** It finds the blocked command, from `logs` if needed, runs `explain` on it, and reports the rule that matched and the safer alternative its reason names. See [Explain trace](/reference/explain-trace).

**Triage a false positive.** It lists recent suspect denials with `logs --suspect --since 7`, reproduces the decision with `explain`, and finds the rule that fired. It fixes or overrides a custom rule and re-runs `explain` to confirm. For a built-in rule, it looks for the workaround the reason names, such as `rule wrapper add` for a trusted wrapper. If you ask to turn the built-in rule off, it proposes a policy override for you to apply.

**Configure rules.** It picks the scope, writes the rulebook JSON from `rule doc` output, and validates it with `rule verify`. When an [official rulebook](/configuration/rulebooks) already covers the request, it installs that instead. See [Custom rules](/configuration/custom-rules).

**Configure the policy.** It writes a proposal to an unprotected path, runs `policy check`, and shows you the diff. You run the `policy apply` command it gives you in your own terminal. See [Policy](/configuration/policy).

**Manage integrations.** It runs `doctor`, installs with an explicit target flag such as `install --claude-code`, and runs `doctor` again to confirm.

**Diagnose.** It runs `status` and `doctor`. When a custom rule does not fire, it runs `rule verify`, then `rule list`, then re-tests the command with `explain`. See [Troubleshooting](/guides/troubleshooting).

**Answer from source.** For questions the CLI output cannot settle, it reads the source of the version you have installed, never `main`, and says which version it read.

## What it will not do

- Help you get around CC Safety Net. It will not lower the level, uninstall, edit config, or propose a weaker policy to get a blocked command through, unless you ask for that outcome and understand what the block guards against.
- Write either `policy.json`. It can read them. Agents cannot run `policy apply`, and the skill will not write the file another way.
- Add a GitHub rulebook source unless you ask to install existing rulebooks.
- Run `hook`, which is the agent integration entry point.
- Run `logs --prune-legacy` without an explicit request. When you ask, it runs `--dry-run` first, because the command permanently deletes legacy logs.
- Run `rule remove --delete-source` without asking. That flag deletes the local source directory.

When you ask for the dashboard, it runs `gui --no-open` and gives you the URL instead of opening a browser from your session.
