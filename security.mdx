A command CC Safety Net failed to block is a bug for a public GitHub issue. Harmful behavior by CC Safety Net itself, such as leaking a secret, is a vulnerability to report privately. If you are not sure which you have, read [Choose a public or private report](#choose-a-public-or-private-report). To diagnose the behavior first, start at [Troubleshooting](/guides/troubleshooting).

The maintainer ships security fixes for the latest published release of `cc-safety-net` only. If you use an older version, upgrade and reproduce the issue there before you report it.

For what CC Safety Net protects and trusts, see [Security model](/guides/security-model). The canonical policy is [SECURITY.md](https://github.com/kenryu42/cc-safety-net/blob/main/SECURITY.md) in the source repository.

## Report a vulnerability privately

**Do not report security vulnerabilities in public GitHub issues.** Use GitHub private vulnerability reporting for the repository when available. If that is unavailable, email the maintainer at jliew@420024lab.com.

Include this information when it is safe to share:

- The affected `cc-safety-net` version
- Your operating system and runtime version
- The affected integration, such as Claude Code, OpenCode, Gemini CLI, GitHub Copilot CLI, Grok Build, Factory Droid, Devin CLI, or Codex
- Steps to reproduce, and the command or input that bypasses, weakens, or abuses CC Safety Net
- Any relevant output from `cc-safety-net explain` or `cc-safety-net doctor`
- Whether the issue can cause data loss, command execution, secret exposure, or another concrete security impact

Redact tokens, credentials, private repository names, and sensitive file paths before you send logs or command output. `explain` and `doctor` output keeps paths and hostnames, so read [Before you share a trace](/reference/explain-trace#before-you-share-a-trace) first.

## Choose a public or private report

Ask one question. Did the tool fail to stop a destructive command, or did the tool itself cause the harm?

A command CC Safety Net should have blocked is a bug for a public GitHub issue. The strict and paranoid threat model already assumes an attacker can make an agent emit any destructive command, so publishing "this command shape is not caught" gives an attacker nothing new. A public report gets the gap fixed faster and lets other users add a custom rule in the meantime.

If the tool itself disclosed a secret its caller did not already hold, wrote a file outside its own directory, or shipped a tampered package, report a vulnerability privately.

## What counts as a security issue

Report these privately:

- Disclosure of a secret the tool call did not supply, such as file contents or environment values the tool read, through block messages, audit logs, diagnostics, or debug output
- A false-positive report prefill that carries a path the report preview claims to have replaced
- A path traversal or filesystem issue in audit logging or configuration handling, where crafted input writes outside the intended directory
- A supply-chain or packaging issue affecting the published npm package or plugin distribution, including rulebook integrity

## What belongs in public issues instead

Use normal [GitHub issues](https://github.com/kenryu42/cc-safety-net/issues) for:

- Any bypass or fail-open that lets a destructive command execute. This includes a coverage gap for a command the rules do not block yet, a parser, tokenizer, or wrapper-analysis edge case, or an analysis error that allows a command instead of blocking it. Report the command *shape*, not a ready-to-paste weaponized prompt-injection payload.
- A redaction gap, meaning a credential form the redactor does not recognize or a field it does not cover, when the value came from the tool call itself and appears only in the denial message returned to that caller or in the local audit log
- False positives where a safe command is blocked
- Missing convenience rules or new feature requests
- Documentation bugs
- Installation problems without a security impact
- Questions about custom rules or configuration

Findings from Anthropic's OSS Scanner, including bypasses, are confidential under that service's terms. The maintainer fixes them privately and opens a public issue only after the fix is released.

Fail-open hosts such as Grok Build, Factory Droid, and Devin CLI, and other host limits CC Safety Net cannot correct, are host behavior, not coverage gaps. [Known limitations](/guides/known-limitations) lists each host's limits.

<Note>
  A destructive-command coverage gap stays public even when it looks severe. The maintainer does not reclassify it as a vulnerability. Use the private path only for the categories listed above. A command allowed under [standard mode's documented relaxations](/configuration/modes#default-mode) is not a gap. Standard is best-effort, while strict and paranoid fail closed on those forms.
</Note>

## What happens after you report

You should receive an initial response within 7 days. The maintainer will work with you to confirm the impact, identify affected versions, prepare a fix, and coordinate disclosure. Give the maintainer reasonable time to investigate before you publish details.

When the maintainer confirms a vulnerability, they publish a fix as soon as practical. The maintainer can also publish a GitHub security advisory or release note with appropriate credit unless you request otherwise. Do not disclose exploit details until a fixed version is available.
