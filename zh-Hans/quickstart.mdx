安装 CC Safety Net，确认它已生效，再看它阻止一条无害的命令。所有受支持的智能体都使用相同的步骤。

<Steps>
  <Step title="为你的智能体安装 CC Safety Net">
    不同智能体分别通过插件市场、扩展、配置文件或软件包安装。在[为单个智能体安装](/zh-Hans/installation#install-for-one-agent)中运行对应智能体的安装命令，然后回到本页。
  </Step>
  <Step title="检查状态">
    用一屏摘要查看哪些保护已生效：

    ```bash
    npx cc-safety-net status
    ```

    配置正常加载时，判定行显示 `ready`。`degraded` 表示 CC Safety Net 无法应用部分配置，当前正在使用回退配置。修复方法见[配置恢复](/zh-Hans/configuration/recovery)。`status` 输出的全部内容见 [status 命令参考](/zh-Hans/reference/cli/status)。
  </Step>
  <Step title="运行 doctor">
    `status` 汇总配置，`doctor` 则端到端地测试每个智能体的集成：

    ```bash
    npx cc-safety-net doctor
    ```

    它会一次检查所有受支持的智能体，无需告诉它你用的是哪一个。它还会运行自检，确认阻止功能正常。检查全部通过时，每一项旁边都会显示绿色对勾。对每个失败项，`doctor` 会说明出了什么问题以及如何修复。完整的检查列表见 [doctor 命令参考](/zh-Hans/reference/cli/doctor)。
  </Step>
  <Step title="查看一次真实的阻止">
    启用 CC Safety Net 后，让智能体运行这条无害的探测命令：

    ```bash
    # This exclusion-only pathspec selects no files
    git checkout -- ':(exclude,top)**'
    ```

    该命令根本不会到达 shell，智能体收到的是一条阻止消息。保护未生效时，这个只含排除项的 Git pathspec 不会选中任何文件，因此 Git 不会改动任何已跟踪的文件。

    <pre className="cc-block-message-output"><code>{`BLOCKED by CC Safety Net

Reason: git checkout -- discards uncommitted changes permanently. Use 'git stash' first.

Command: git checkout -- ':(exclude,top)**'

If this operation is truly needed, ask the user for explicit permission and have them run the command manually.`}</code></pre>

    消息会说明阻止原因，并给智能体一个更安全的后续操作。消息结构以及决策流程的其余环节见[工作原理](/zh-Hans/guides/how-it-works#what-a-block-looks-like)。
  </Step>
  <Step title="只问原因，不运行任何命令">
    如果某个决策出乎你的预期，`explain` 会用同一个引擎评估命令字符串，但不会执行它：

    ```bash
    npx cc-safety-net explain "git checkout -- ':(exclude,top)**'"
    ```

    它会输出判定、匹配到的规则以及生效的配置。

    <Warning>
      输出可能包含你的路径、主机名和项目名称。粘贴到任何地方之前，请先阅读[分享跟踪之前](/zh-Hans/reference/explain-trace#before-you-share-a-trace)。
    </Warning>
  </Step>
</Steps>
