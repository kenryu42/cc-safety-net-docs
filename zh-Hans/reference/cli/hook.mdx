`hook` 是智能体在运行工具之前调用的命令。它从 stdin 以 JSON 读取智能体的 hook 输入，需要阻止调用时，按该智能体的拒绝格式作答。智能体的插件或配置会替你接好它，通常不需要手动运行。

例如，`install --cursor` 会把下面这条命令写入 Cursor 的 hook 配置，Cursor 每次调用工具都会运行它：

```bash
npx -y cc-safety-net hook --cursor
```

## hook 集成选项

`hook` 需要正好一个集成选项，用来指明智能体。没有选项或选项多于一个时，它打印 `hook requires exactly one integration flag. Try: cc-safety-net hook --kimi-code`，显示命令帮助，并退出 `1`。

| 选项 | 智能体 | 旧版选项 |
| --- | --- | --- |
| `-ac`, `--agy-cli` | [Antigravity CLI](/zh-Hans/installation/antigravity-cli) | 无 |
| `-cc`, `--coding-cli` | [Coding CLI (Claude Code)](/zh-Hans/installation/claude-code) | `--claude-code`；顶层形式 `cc-safety-net -cc` 和 `cc-safety-net --claude-code` 也可用 |
| `-cx`, `--codex` | [Codex](/zh-Hans/installation/codex) | 无 |
| `-cu`, `--cursor` | [Cursor](/zh-Hans/installation/cursor) | 无 |
| `-dv`, `--devin` | [Devin CLI](/zh-Hans/installation/devin-cli) | 无 |
| `-fd`, `--droid` | [Factory Droid](/zh-Hans/installation/factory-droid) | 无 |
| `-gc`, `--gemini-cli` | [Gemini CLI](/zh-Hans/installation/gemini-cli) | 顶层形式 `cc-safety-net -gc` 和 `cc-safety-net --gemini-cli` |
| `-cp`, `--copilot-cli` | [GitHub Copilot CLI](/zh-Hans/installation/github-copilot-cli) | 顶层形式 `cc-safety-net -cp` 和 `cc-safety-net --copilot-cli` |
| `-gb`, `--grok-build` | [Grok Build](/zh-Hans/installation/grok-build) | 无 |
| `-ha`, `--hermes-agent` | [Hermes Agent](/zh-Hans/installation/hermes-agent) | 无 |
| `-kc`, `--kimi-code` | [Kimi Code](/zh-Hans/installation/kimi-code) | 无 |

各智能体的页面说明了它的 hook 检查什么、检查失败时会怎样。在 Claude Code 中，hook 可以改为向你确认，而不是直接阻止。参见 [Claude Code 何时改为询问而不是阻止](/zh-Hans/installation/claude-code#when-claude-code-asks-you-instead-of-blocking)。

## 没有 hook 选项的智能体

Amp Code、DeepSeek Harness、OpenClaw、OpenCode 和 Pi 没有 `hook` 选项。它们以插件或扩展的形式，在自己的进程内加载 CC Safety Net。参见[集成模型](/zh-Hans/guides/how-it-works#integration-models)。

<Note>
  没有 `hook install` 或 `hook uninstall` 子命令。请使用顶层的 [`install`](/zh-Hans/reference/cli/install) 和 [`uninstall`](/zh-Hans/reference/cli/uninstall) 命令。
</Note>
