自己执行命令的 Node.js 宿主，例如智能体、任务运行器、CI 工具链或带 shell 工具的插件宿主，可以调用 `checkCommand`，而不必安装智能体集成。该函数按当前策略检查一条 shell 命令，返回允许或拒绝，从不执行这条命令。

## 库 API 还是已安装的集成

两者运行的是同一个分析引擎，区别在于由谁负责发起调用。

| | 已安装的集成 | 进程内的 `checkCommand` |
| --- | --- | --- |
| 由谁接入 | `cc-safety-net install <target>`，每台机器执行一次 | 你自己的代码，在每一处执行命令的位置 |
| 决策在哪里发生 | hook 子进程，或智能体加载的插件 | 你的进程内，同步完成 |
| 审计记录 | 记录每次决策，可用 `logs` 和仪表板查看 | 没有。需要记录什么由宿主决定 |
| 适用对象 | 受支持的十六个智能体 | 任意 Node.js 宿主 |

如果你的用户运行的是受支持的智能体，就把安装命令给他们，见[集成模型](/zh-Hans/guides/how-it-works#integration-models)。如果命令由你的程序执行，就调用这个函数。

## 安装与导入

```bash
npm install cc-safety-net
```

```ts
import { checkCommand } from 'cc-safety-net/api';
```

需要 Node.js 22 或更高版本以及 ESM。没有 CommonJS 构建，因此 `require()` 无法加载它。请从 `cc-safety-net/api` 导入，因为包的根导出是 OpenCode 插件，而不是 `checkCommand`。

## `checkCommand`

```ts
function checkCommand(input: CheckCommandInput): CheckCommandResult;
```

调用是同步的：先读取本地策略文件、文件系统状态和 `CC_SAFETY_NET_*` 环境设置，再返回允许或拒绝。

### 输入

```ts
type CheckCommandInput = Readonly<{
  command: string;
  cwd: string;
}>;
```

| 字段 | 类型 | 描述 |
| --- | --- | --- |
| `command` | `string` | 待检查的 shell 命令文本，不能为空 |
| `cwd` | `string` | 绝对目录路径。命令中的相对目标按它解析，项目的规则配置也由它选定 |

`cwd` 必填，没有默认值。API 从不回退到 `process.cwd()`，因此命令属于哪个项目由宿主决定。

### 结果

```ts
type CheckCommandResult =
  | Readonly<{ kind: 'allow' }>
  | Readonly<{ kind: 'deny'; reason: string; ruleId: string }>;
```

| 字段 | 何时出现 | 描述 |
| --- | --- | --- |
| `kind` | 始终 | `'allow'` 或 `'deny'` |
| `reason` | 仅 deny | 向用户展示的阻止消息 |
| `ruleId` | 仅 deny | 产生该阻止的规则或固定拒绝的 ID |

决策以 `kind` 为准。`deny` 表示宿主不得执行这条命令。`reason` 是展示文本，不要解析或比较它。

每个 deny 都带有 `ruleId`。它可能是 `git.reset-hard` 这样的内置规则 ID、机密规则 ID、以 `custom.` 开头的规则 ID，或 `cwd.requested-unusable` 这类[固定拒绝 ID](/zh-Hans/reference/blocked-commands#fixed-denial-ids)。可以按它分支，对某类 deny 区别处理，例如提示用户修正工作目录。但无论 ID 是什么，deny 都会阻止命令。后续版本可能新增 ID，因此遇到不认识的 ID 时，按普通 deny 处理。所有可能的 deny 见[被阻止的命令](/zh-Hans/reference/blocked-commands)。

### 错误

`checkCommand` 会在运行时校验输入，并抛出带有以下消息之一的 `TypeError`：

| 消息 | 条件 |
| --- | --- |
| `checkCommand requires an input object with command and cwd` | `input` 不是非 null 的对象 |
| `command must be a non-empty string` | `command` 不是字符串，或只有空白字符 |
| `cwd must be an absolute directory path` | `cwd` 不是字符串、只有空白字符，或不是绝对路径 |

已知的防护失败会返回 fail-closed 的 deny，而不是抛出异常。其他错误都会抛给调用方。

<Warning>
  如果 `checkCommand` 抛出异常，不要执行这条命令。抛出异常不等于允许。
</Warning>

### 不可用的工作目录

`cwd` 必须是一个已存在、可读且可搜索的目录。否则调用会返回 `ruleId` 为 `cwd.requested-unusable` 的 deny，而不是去分析错误的项目。原因如下：

```
CC Safety Net could not use the requested working directory because it does not exist, is inaccessible, is not a directory, or uses an unsupported path form. Use an existing accessible working directory. If the requested directory is missing, create it from an accessible location before retrying the command.
```

## 一次调用读取哪份策略

一次调用读取的用户文件和项目文件与 hook 相同。项目文件严格取自 `<cwd>/.cc-safety-net/`，不会向上搜索父目录，因此请把仓库根目录作为 `cwd` 传入，否则提交到仓库的项目策略不会加载。两个范围如何合并，见[策略](/zh-Hans/configuration/policy#project-policy)。

由于 `cwd` 决定项目，同时管理多个检出的宿主只要传入各自的目录，就能为每个检出拿到正确的策略。要预先了解宿主会如何判定，请在作为 `cwd` 传入的目录中运行 `status`、`doctor` 或 `explain`。

## 跨版本的稳定性

以下几点在小版本之间保持不变：

- 输入形状 `{ command, cwd }`，以及两种结果：`allow`，和带 `reason` 与 `ruleId` 的 `deny`。
- `deny` 或抛出异常都表示不要执行该命令。
- 命令中的相对目标和项目配置按你传入的 `cwd` 解析，从不使用 `process.cwd()`。
- 一次调用不写审计记录，也不发起网络请求。见[一次调用检查什么](#what-one-call-checks)。

规则目录在任何小版本中都可能变化。新版本可能拒绝旧版本允许的命令，`reason` 的措辞也会改变。请按 `kind` 分支，把 `reason` 留给人和日志，并在 lockfile 中锁定版本。

## 示例：插件宿主

带插件系统的宿主通常有一个执行前 hook，可以否决工具调用。插件把宿主的事件映射为 `{ command, cwd }`，调用 `checkCommand`，再把 deny 转换成宿主的否决：

```ts
import { checkCommand } from 'cc-safety-net/api';

export function registerSafetyNet(host: PluginHost) {
  host.beforeToolCall((call, ctx) => {
    if (call.toolName !== 'shell') return undefined;

    if (typeof call.input.command !== 'string' || call.input.command.trim() === '') {
      return { block: true, reason: 'Malformed shell tool call.' };
    }

    try {
      const result = checkCommand({ command: call.input.command, cwd: ctx.projectRoot });
      if (result.kind === 'deny') return { block: true, reason: result.reason };
      return undefined;
    } catch (error) {
      console.error('CC Safety Net could not check the command', error);
      return { block: true, reason: 'Command check failed. The command was not executed.' };
    }
  });
}
```

- 插件只把 shell 工具调用交给 `checkCommand`。它检查的是 shell 命令文本，不检查宿主的读取、写入或搜索工具。
- `cwd` 是项目根目录的绝对路径。它决定使用哪份项目策略，`checkCommand` 也按它解析命令中 `.env` 之类的相对路径。
- 抛出异常就阻止这次调用。如果处理函数让错误继续流向执行，检查失败就会变成放行。
- 事件格式不正确时也阻止，因为没有可供分析的内容。

如果宿主的否决方式是抛出异常，就抛出拒绝消息，而不是返回它。

## 一次调用检查什么

调用会自动识别 shell 方言，并把 `cwd` 同时用作项目目录和执行目录。命令会被完整检查，包括命令对机密文件的访问。宿主自己的非 shell 文件工具，例如读取、写入、编辑和搜索，不在检查范围内。

一次调用从不执行命令、修改配置或发起网络请求。它不写审计记录，因此 `logs` 命令和仪表板都不会显示它。如果宿主不记录拒绝，就没有任何地方会留下记录。

## 环境变量

每次调用都从进程环境读取 `CC_SAFETY_NET_*` 设置，因此修改这些设置会改变后续的决策。无效的 `CC_SAFETY_NET_LEVEL` 会被忽略，并在 stderr 上报告：

```
CC Safety Net: ignored invalid CC_SAFETY_NET_LEVEL="<value>". Use standard, strict, paranoid.
```

消息中的值以 JSON 字符串形式加引号，并截断到前 40 个字符。完整列表见[环境变量](/zh-Hans/configuration/environment)。
