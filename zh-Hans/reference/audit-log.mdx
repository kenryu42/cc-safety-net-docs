CC Safety Net 把每个命令决策记入审计日志，日志只保存在你的机器上，从不上传。每个文件都是 JSON Lines（JSONL）格式，每行一个 JSON 对象。可以在[仪表板](/zh-Hans/guides/dashboard)中查看，也可以在终端里用 [`logs`](/zh-Hans/reference/cli/logs) 查看。

<span id="log-layout"></span>

## 日志布局

记录写入按项目、按月划分的路径：

```text
~/.cc-safety-net/logs/<encoded-cwd>/<YYYY-MM>/<YYYY-MM-DD>-<session-id>.jsonl
```

| 路径部分 | 含义 |
| --- | --- |
| `<encoded-cwd>` | 工作目录，其中每个非字母数字字符都替换为 `-`；没有工作目录时为 `no-cwd` |
| `<session-id>` | 智能体会话 ID，其中不能用于文件名的字符已被替换 |

`CC_SAFETY_NET_AUDIT_HOME` 可以更改审计根目录所在的主目录。CC Safety Net 以模式 `0700` 创建目录，以模式 `0600` 创建文件。写入失败绝不会改变允许或阻止的决策。

直接位于 `~/.cc-safety-net/logs/` 下的平面 `*.jsonl` 文件是早期版本的旧版布局。`logs` 仍会读取它们，保留期清理也仍会删除它们；想现在就移除，参见 [`logs --prune-legacy`](/zh-Hans/reference/cli/logs#delete-legacy-log-files)。

## 每条记录包含一个决策

每行记录一条允许或阻止的命令决策：命令、促成该决策的命令段、理由，以及匹配的规则。

- CC Safety Net 从不读取或存储命令输出、模型提示词、工具结果或对话内容。
- 拒绝始终会被记录。
- 允许的决策只针对命令类工具调用记录。被允许的文件编辑或读取不产生记录。
- fail-closed 路径上的阻止同样会被记录：分析失败、CC Safety Net 无法得出判定，于是阻止了命令。这类记录带有 `failureStage` 和 `errorCode` 字段，`logs --suspect` 正是依据这两个字段筛选的。

<span id="record-schema"></span>

## 记录 schema

| 字段 | 类型 | 是否存在 | 描述 |
| --- | --- | --- | --- |
| `ts` | string | 始终 | 决策的 ISO 8601 时间戳 |
| `id` | string | 始终写入 | 16 个十六进制字符，即 `logs --id` 接受的 ID |
| `v` | string | 可选 | 写入该记录的 CC Safety Net 版本，或 `dev` |
| `sessionId` | string | 可选 | 清理后的智能体会话 ID |
| `decision` | `"allow" \| "deny"` | 可选，默认为 `"deny"` | 决策结果 |
| `agent` | string | 可选 | 集成 ID，例如 `claude-code` |
| `shape` | string | 可选 | 该记录来自的适配器输入形态 |
| `level` | string | 可选 | 决策时生效的安全级别 |
| `configFallback` | `true` | 可选 | 决策基于回退策略做出时存在 |
| `toolName` | string | 可选 | 工具名称 |
| `command` | string | 始终 | 完整命令，已脱敏 |
| `segment` | string | 始终 | 促成决策的命令段，已脱敏 |
| `truncated` | `true` | 可选 | 仅当有较长字段被截断时存在 |
| `reason` | string | 始终 | 供人阅读的决策理由 |
| `ruleId` | string | deny 记录 | 阻止该调用的规则或[固定拒绝](/zh-Hans/reference/blocked-commands#fixed-denial-ids)的 ID。allow 记录、Copilot CLI 的 deny `Failed to parse toolArgs JSON.`，以及早期版本写入的部分 deny 记录中没有该字段 |
| `intent` | string | 可选 | 阻止意图的分类 |
| `failureStage` | string | 可选 | 拒绝来自按 fail closed 处理的检查时设置 |
| `errorCode` | string | 可选 | `path-canonicalization-limit`、`tool-input-limit`、`structural-shell-syntax-limit`、`unparseable-command`、`unexpected-error` 之一 |
| `cwd` | string \| `null` | 可选 | 工作目录，已脱敏 |

示例记录：

```json
{"ts":"2025-01-15T10:30:00.000Z","id":"3fa9c2d1a70e8b42","v":"2.0.0","sessionId":"a1b2c3","decision":"deny","agent":"claude-code","level":"standard","command":"git reset --hard","segment":"git reset --hard","reason":"git reset --hard destroys all uncommitted changes permanently. Use 'git stash' first.","ruleId":"git.reset-hard","cwd":"/path/to/project"}
```

`segment`、`toolName` 和 `cwd` 的值过长时，CC Safety Net 会截断它们，并在记录上设置 `truncated: true`。过长的 `command` 同样会被截断，只有带 `failureStage` 的记录例外，这类记录保留完整命令。该字段从不写成 `false`。

### failureStage 的取值

`failureStage` 指出按 fail closed 处理的是哪一项检查。各项检查的执行顺序见[工作原理](/zh-Hans/guides/how-it-works#what-gets-checked-in-order)。

| `failureStage` | 失败发生的位置 |
| --- | --- |
| `policy-protection` | 在大小上限内读取工具输入、策略文件保护或 Git 元数据保护 |
| `command-validation` | 校验命令：已声明命令工具的工作目录参数、输入长度、词数和嵌套深度的上限，或空命令 |
| `config-load` | 加载策略并确定安全级别 |
| `secret-protection` | 敏感路径保护 |
| `non-command` | 处理非命令类的工具调用 |
| `command-analysis` | 破坏性命令分析，包括已声明命令的递归上限 |

由输入上限、已声明命令工具的检查、策略文件保护或 Git 元数据保护产生的拒绝，发生在策略加载之前，因此记录中没有 `level`，也没有 `configFallback`。

<span id="what-is-recorded-audit-scope"></span>

## 记录的内容：审计范围

`CC_SAFETY_NET_AUDIT_SCOPE` 决定允许的命令决策是否与拒绝一起记入日志。

| 值 | 效果 |
| --- | --- |
| 未设置 | 默认值，行为与 `all` 相同 |
| `all` | 记录允许和阻止的命令决策 |
| `blocked` | 只记录拒绝。这一设置保留的数据最少 |
| 其他任何值 | 只记录拒绝，且 [`doctor`](/zh-Hans/reference/cli/doctor) 会报告 `environment.audit-scope-invalid` |

范围从不抑制拒绝记录，只决定 CC Safety Net 是否记录允许的决策。

<span id="retention"></span>

## 保留期

| 设置 | 值 |
| --- | --- |
| 默认保留期 | 30 天 |
| 可配置范围 | 1 到 365 天 |
| 配置键 | `policy.json` 中的 `audit.retention_days` |

无效值的处理方式见[审计保留](/zh-Hans/configuration/policy#audit-retention)。同一个值也是 `logs --since` 的上限，并限定仪表板活动视图可选的时间窗口。

CC Safety Net 在下一次运行时删除过期记录：写入一条记录之后，或者 `logs`、`doctor`、仪表板读取日志之前。没有任何定时任务，因此 CC Safety Net 空闲期间，过期记录可能一直留在磁盘上，`logs --id` 也仍能找到它们。

<Warning>
  缩短保留期不可撤销。调低该值后，较旧的记录会在下一次运行时符合删除条件，CC Safety Net 删除它们时没有归档、回收站，也无法撤销。仪表板在调低该值之前会要求你确认。
</Warning>

<span id="secret-redaction"></span>

## 机密脱敏

CC Safety Net 在写入记录之前，会对命令、命令段、工具名称和工作目录做脱敏，把识别出的以下值替换为 `<redacted>`：

- 名称包含 `TOKEN`、`SECRET`、`PASSWORD`、`PASS`、`KEY` 或 `CREDENTIALS` 的环境变量赋值
- 数据库连接变量（`DATABASE_URL`、`POSTGRES_URL`、`MYSQL_URL`、`REDIS_URL`、`MONGODB_URL`，以及其他 DSN/URL/URI/连接字符串变量）
- PEM 私钥块（`-----BEGIN ... PRIVATE KEY-----`）
- 携带机密的 HTTP 标头（`Authorization`、`Cookie`、`X-API-KEY`、`API-KEY`）
- URL 凭证（`scheme://user:pass@host` 和 `scheme://token@host`）以及 `-u user:pass`
- 预签名 URL 的签名查询参数，即 `x-amz-signature`、`x-goog-signature`、`sig` 和 `signature` 的值
- 一份固定的服务商令牌格式列表（`ghp_...`、`gho_...`、`xoxb-...`、`npm_...`、`sk_live_...`、`rk_live_...`、`pypi-...` 等）
- JWT（`eyJ...`）和 AWS 访问密钥 ID（`AKIA...` / `ASIA...`）

<Warning>
  脱敏的范围是有限的。它只是一份固定的模式列表，而不是分类器。其他一切都原样保留：绝对文件系统路径、项目和目录名称、主机名、IP 地址、用户名、工单 ID、文件名，以及形式不在列表中的任何凭证。CC Safety Net 不对 `reason` 字段脱敏。请把审计日志当作敏感的本地数据，把任何摘录粘贴到 issue 或聊天之前先检查一遍。
</Warning>

文件权限限制的是谁能读取日志。它不会对日志脱敏，也不会让日志变得可以安全分享。
