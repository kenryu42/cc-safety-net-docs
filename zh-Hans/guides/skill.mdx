CC Safety Net 附带一个技能（skill），让编码智能体替你操作 CC Safety Net。你可以问它某条命令为什么被阻止，让它编写 rulebook 规则，或者让它检查安装状态。它会运行 `cc-safety-net` CLI，读取输出，再用平实的语言汇报。

技能只负责操作 CC Safety Net，本身不执行任何防护。防护来自 hook，无论技能是否加载，hook 都照常运行。

<span id="how-you-invoke-it"></span>

## 如何调用

技能随 Claude Code 插件和 Codex 插件一起分发，装好其中任意一个就有了技能。

| 智能体 | 调用方式 |
| --- | --- |
| Claude Code | `/cc-safety-net:cc-safety-net`，列在插件的命名空间下 |
| Codex | 随 Codex 插件安装，按 Codex 调用技能的方式调用 |
| Pi 和 OpenCode | `/cc-safety-net`，由各自的集成注册为内置命令 |
| Antigravity CLI 和 Kimi Code | 先用 `npx skill add kenryu42/cc-safety-net` 添加技能，再按该智能体调用技能的方式调用 |

调用时写在后面的内容就是你的请求。本页的示例使用 `/cc-safety-net`：

```text
/cc-safety-net why was my last git command blocked
/cc-safety-net block terraform destroy in this project
```

技能只在你调用时运行，模型无法在任务中途自行加载它。

## 什么时候用它

- 命令因 `BLOCKED by CC Safety Net` 被阻止，你想要逐步的原因说明。
- 阻止看起来不对，需要排查：复现决策、修复出问题的自定义规则，或上报内置规则的误报。
- 想让它替你编写、修改或迁移自定义阻止规则。
- 想修改安全级别、开关某项防护，或调整路径列表。
- 想把 CC Safety Net 安装到另一个智能体 CLI，或在其中更新、移除。
- 你添加的规则没有触发，或者想确认防护仍然生效。
- 想弄清分析器为什么这样处理某个结构，而 `explain` 和 `rule doc` 的输出说明不了。

## 各个工作流做什么

技能会把请求交给七个工作流之一。

**解释决策。** 找到被阻止的命令（必要时从 `logs` 中查找），对它运行 `explain`，然后报告命中的规则，以及原因中给出的更安全的替代做法。见 [Explain 跟踪](/zh-Hans/reference/explain-trace)。

**排查误报。** 用 `logs --suspect --since 7` 列出近期可疑的拒绝，用 `explain` 复现决策，找出触发的规则。如果是自定义规则，就修改它或用覆盖项关闭它，再重新运行 `explain` 确认。如果是内置规则，就去找原因中写明的变通做法，例如对可信的包装器使用 `rule wrapper add`。你要求关闭那条内置规则时，它会提出一项策略覆盖，交给你来应用。

**配置规则。** 先确定范围，再根据 `rule doc` 的输出写出 rulebook JSON，并用 `rule verify` 校验。如果[官方 rulebook](/zh-Hans/configuration/rulebooks) 已经覆盖了你的需求，就改为安装它。见[自定义规则](/zh-Hans/configuration/custom-rules)。

**配置策略。** 把提案写到未受保护的路径，运行 `policy check`，把差异展示给你。它给出的 `policy apply` 命令由你在自己的终端里运行。见[策略](/zh-Hans/configuration/policy)。

**管理集成。** 先运行 `doctor`，安装时显式带上目标选项（例如 `install --claude-code`），完成后再运行一次 `doctor` 确认。

**诊断。** 运行 `status` 和 `doctor`。自定义规则没有触发时，依次运行 `rule verify`、`rule list`，再用 `explain` 重新测试该命令。见[故障排除](/zh-Hans/guides/troubleshooting)。

**从源码作答。** CLI 输出回答不了的问题，它会去读你所安装版本的源码（绝不读 `main`），并写明读的是哪个版本。

## 它不会做的事

- 帮你绕过 CC Safety Net。它不会为了放行一条被阻止的命令而降低级别、卸载、改配置或提出更弱的策略，除非你明确要求这个结果，并且清楚该阻止在防范什么。
- 写入任何一个 `policy.json`。它可以读取。智能体无法运行 `policy apply`，技能也不会换个方式写入文件。
- 添加 GitHub rulebook 来源，除非你要求安装现成的 rulebook。
- 运行 `hook`。那是智能体集成的入口。
- 未经明确要求就运行 `logs --prune-legacy`。你要求时，它也会先跑一次 `--dry-run`，因为这条命令会永久删除旧版日志。
- 未经确认就运行 `rule remove --delete-source`。该选项会删除本地来源目录。

需要打开仪表板时，它会运行 `gui --no-open` 并把 URL 交给你，而不是从你的会话里打开浏览器。
