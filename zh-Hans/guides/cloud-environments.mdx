云端会话跑在一台没人登录的机器上，任务结束后机器就被回收。CC Safety Net 可以通过仓库、环境的 setup 脚本 或容器镜像进入这类会话，三种方式都使用标准的包。

## 云端 VM 改变了什么

VM 是一次性的，但云端会话会 push 到你真实的远端：`git push --force` 落在队友会 pull 的分支上，`git reset --hard` 会丢掉会话里尚未提交的工作。为基础设施工作准备的环境还可能带着有效的云身份执行 `terraform destroy` 或 `aws s3 rm`，而[官方 rulebook](/zh-Hans/configuration/rulebooks) 会阻止这些命令。提交到仓库的拒绝层，在每个 clone 该仓库的会话里都会生效。

## Claude Code 云端会话与自托管环境

[Claude Code on the web](https://code.claude.com/docs/en/claude-code-on-the-web) 从提交到仓库的文件中读取设置，hook 也在其中。只要准备好两样东西，云端会话就会执行你的策略。

<Steps>
  <Step title="提交项目策略">
    提交 `.cc-safety-net/policy.json`，以及 `.cc-safety-net/rules/` 下的项目 rulebook。会话会随仓库一起 clone 它们。这与[团队配置](/zh-Hans/guides/team-setup)为开发者机器提交的配置相同。

    云端会话一开始没有属于自己的用户策略文件，项目文件没有指定的地方都使用内置默认值。请在项目文件里设置会话的预设，不要指望某位成员本地恰好在用的那个。
  </Step>
  <Step title="把 hook 装进会话">
    有两种做法，取决于环境有没有 setup 脚本。

    在环境的 [setup 脚本](https://code.claude.com/docs/en/cloud-environments) 里，或者在自托管环境所依赖的镜像里，运行常规安装：

    ```bash
    npx -y cc-safety-net@latest install --claude-code
    ```

    带上目标选项后安装是非交互的，不需要终端确认，可以在无头环境中完成。

    没有 setup 脚本 时，把 hook 条目本身作为 `.claude/settings.json` 提交：

    ```json
    {
      "hooks": {
        "PreToolUse": [
          {
            "matcher": "*",
            "hooks": [
              { "type": "command", "command": "npx -y cc-safety-net@latest hook --coding-cli" }
            ]
          }
        ]
      }
    }
    ```

    `hook --coding-cli` 是规范的 hook 入口，已安装的插件调用的也是它。这种形式每次工具调用都要启动一次 `npx`，所以环境有 setup 脚本 时优先用 setup 脚本。
  </Step>
</Steps>

两种形式都会在安装或调用时访问网络。没有网络访问的环境，需要把包预先放进镜像。

CC Safety Net 把[审计日志](/zh-Hans/reference/audit-log)写在会话的 home 目录里，日志会随 VM 一起消失。另外，hook 缺失时会话不会给出任何提示。每个环境都应确认一次：让会话执行一条策略会拒绝的命令，看它是否被阻止。`npx -y cc-safety-net@latest explain "git reset --hard"` 不执行命令，只显示当前配置给出的判定。

## Amp Orb 线程

Amp 不需要按容器操作。`npx -y cc-safety-net@latest install --amp` 会把插件发布到你的 Amp 账户，因此也覆盖在远端运行的线程，包括 Orb。插件带有一份用户策略快照，供没有策略文件的机器使用。修改用户策略后，请重新运行安装。见 [Amp Code 策略快照](/zh-Hans/installation/amp-code#amp-code-policy-snapshot)。

## devcontainer 与容器镜像

自己构建的容器，把安装放在构建期。下面这个 Dockerfile 可以直接使用：

```dockerfile
FROM node:22-slim
RUN apt-get update && apt-get install -y --no-install-recommends git ca-certificates \
    && rm -rf /var/lib/apt/lists/*
RUN npm install -g @anthropic-ai/claude-code
RUN npx -y cc-safety-net install --claude-code
```

这个顺序带出两条构建期要求：

- **必须有 `git` 和 `ca-certificates`。** Claude Code 的安装会添加插件 marketplace，这一步通过 HTTPS 执行 clone，而 slim 基础镜像两者都没有。
- **先装智能体 CLI。** 安装程序调用的是智能体自己的插件命令，先装 CC Safety Net 再装智能体的构建会失败。

在 devcontainer 里，同一条命令写成 `postCreateCommand`：

```json
{
  "postCreateCommand": "npx -y cc-safety-net@latest install --claude-code"
}
```

这里不要加[团队配置](/zh-Hans/guides/team-setup)中的 `process.env.CI` 守卫。智能体就运行在这个容器里，正需要这次安装。

## 仍然需要人批准的部分

无论在云端 VM 还是笔记本上，安装防护都可以自动化，放松防护则不行。智能体可以起草策略提案，但无法运行 `policy apply`，见[智能体不能运行 policy apply](/zh-Hans/reference/cli/policy#agents-cannot-run-policy-apply)。
