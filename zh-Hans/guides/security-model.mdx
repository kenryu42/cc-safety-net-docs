CC Safety Net 是一个尽力而为的静态执行前 hook，作用于受支持的编码智能体工具调用。它会在可识别的破坏性命令和机密读取运行之前将其拦下。它不是操作系统沙箱或权限边界，也不能保护绕过已安装集成的命令。

## CC Safety Net 保护什么

CC Safety Net 把智能体生成的每条命令都视为不可信。提示注入、上下文混淆或对抗性指令都可能让智能体发出破坏性命令，所以 hook 会在宿主运行每个受支持的工具调用之前检查它，发现阻止理由就拒绝。

调用被检查到什么程度，取决于工具：

- 集成自带的 shell 工具会按你的安全级别接受完整的命令分析。
- 在 [`command_tools`](/zh-Hans/configuration/custom-rules#community-shell-tools) 中声明的工具，只要调用带有非空字符串 `command`，就会像内置 shell 工具一样接受分析。
- 其他工具只接受策略文件、Git 元数据和敏感路径检查。CC Safety Net 绝不会把它们的文本当作 shell 命令。
- 不经过已安装集成的命令永远不会被检查。

安全级别决定分析能拦下多少。各级别的对比见[应该使用哪个安全级别？](/zh-Hans/configuration/modes#which-safety-level-should-i-use)。

<Warning>
  Standard 模式**不具备对抗级能力**。Standard 允许 `rm -rf "$target"` 这类动态 `rm -rf` 目标，strict 和 paranoid 会阻止。当命令可能来自提示注入或其他对抗性上下文时，请使用 strict 或 paranoid。
</Warning>

任何级别或策略设置都无法关闭[灾难性规则](/zh-Hans/reference/blocked-commands#catastrophic-rules)（涵盖递归删除 `/` 或用户主目录），以及对 [Git 元数据](/zh-Hans/reference/blocked-commands#git-metadata)和 [`policy.json`](/zh-Hans/reference/blocked-commands#protected-policy-json-files) 的保护。机密保护开启时，任何级别都不会放宽对已识别机密文件内容的读取，也不会放宽 `deny_paths` 中列出的路径。

## CC Safety Net 信任什么

hook 外部有三类输入可以改变它执行的内容。CC Safety Net 会先验证每一类输入，验证通过后才让它生效。

| 输入 | 由谁控制 | CC Safety Net 如何检查 |
| --- | --- | --- |
| 用户配置 | 你，通过用户级 [`policy.json` 和 `rule.json`](/zh-Hans/configuration/environment#where-configuration-lives) | 对每个文件做 schema 验证，被拒绝的文件绝不会生效 |
| 项目策略 | 任何能向仓库提交 `.cc-safety-net/policy.json` 的人 | 做 schema 验证后叠加到用户策略之上。`status` 和 `doctor` 会报告它放宽的每个字段，你也可以全部拒绝。见[项目策略](/zh-Hans/configuration/policy#project-policy) |
| Rulebook 来源 | 你落盘的 rulebook 的发布者；本地 rulebook 则是你自己 | 写入落盘副本前验证获取到的内容并运行其 fixture，之后每次加载时再次验证该文件 |

无效配置本身绝不会拒绝普通工作。CC Safety Net 会丢弃被拒绝的来源，并把运行时报告为 `degraded`。丢弃 rulebook 会移除它带来的拒绝，所以在你修复之前，原本被它阻止的命令可以再次运行。每种失败及其回退见[配置恢复](/zh-Hans/configuration/recovery)。

## 分析失败时会怎样

某次工具调用的分析无法完成时，CC Safety Net 会拒绝这次调用，而不是放行：

- 分析器出现意外错误时，返回带“failed closed”原因的拒绝。
- 格式错误的 hook 输入，以及过大或嵌套过深、无法分析的命令，在所有安全级别下（包括 standard）都会被拒绝。达到分析预算的命令会得到一条原因，提示智能体简化或拆分命令。
- Strict 和 paranoid 还会拒绝解析器读不懂的命令。Standard 会放行看似安全但无法解析的文本，但仍会扫描其中的破坏性模式。

这依赖宿主遵从拒绝结果。Grok Build、Factory Droid 和 Devin CLI 在设计上是 fail open：hook 崩溃、超时或没有输出时，调用照常运行。各宿主的行为见[已知限制](/zh-Hans/guides/known-limitations)。

<span id="what-redaction-hides-and-what-it-keeps"></span>

## 脱敏隐藏什么、保留什么

CC Safety Net 把命令文本写入审计日志或放进拒绝消息之前，会把已识别的凭证替换为 `<redacted>`。范围包括私钥、URL 凭证、携带机密的环境变量赋值和 HTTP header、预签名 URL 签名、JWT、AWS access key ID 以及已知 token 前缀。完整列表见[审计日志参考](/zh-Hans/reference/audit-log#secret-redaction)。

脱敏只匹配已知的凭证形式。绝对路径、项目和目录名、主机名、IP 地址、用户名，以及格式不在列表中的凭证都会原样保留。请避免让真实凭证经过智能体运行的命令。`explain` 和 `doctor` 的输出同样包含原始文本，分享前请先检查。见[分享跟踪之前](/zh-Hans/reference/explain-trace#before-you-share-a-trace)。

## 攻击者可能如何尝试绕过

| 攻击 | 攻击者的尝试 | 由什么拦下 |
| --- | --- | --- |
| 解析器技巧 | 用异常引号、嵌套替换或运算符歧义隐藏破坏性 payload | 解析器不展开变量，动态目标始终可见。Strict 和 paranoid 拒绝无法解析的命令，解析器错误也会拒绝该调用 |
| 包装器和解释器 | 把破坏性命令藏在 `sudo`、`env`、`bash -c`、`cmd /c`、`pwsh -c` 或解释器单行命令之后 | CC Safety Net 剥离包装器，重新分析内层命令或脚本。`cmd` 或 PowerShell 中读不懂的递归删除会被阻止。其他代理命令可声明为[透明包装器](/zh-Hans/configuration/custom-rules#transparent-wrappers) |
| 敏感文件访问 | 通过命令、文件工具、搜索或 patch 读取 `.env`、`~/.ssh/id_*` 或 `~/.aws/credentials` | [机密保护](/zh-Hans/reference/secret-protection)针对一组固定的凭证文件和你的拒绝路径覆盖这些形式。它不是通用的读取边界 |
| 恶意 rulebook | 从 GitHub 来源提供有害的 rulebook | `rule add` 和 `rule update` 把来源固定到某个 commit，拒绝重定向，并验证内容。落盘文件位于你的仓库中，可供评审。rulebook 可以添加阻止规则，但不能移除内置规则 |
| 项目策略 | 提交一个降低级别或放行敏感路径的项目 `policy.json`，影响所有 clone 该仓库的人 | 项目文件无法去掉用户的拒绝路径，也无法更改审计设置。每一处放宽都会显示在 `status`、`doctor` 和状态行中，[`CC_SAFETY_NET_PROJECT_TIGHTEN_ONLY=1`](/zh-Hans/configuration/policy#ignore-project-weakenings) 会全部拒绝。智能体既不能写入 `policy.json`，也不能运行 `cc-safety-net policy apply` |

网络攻击、针对智能体平台本身的攻击，以及在检查与运行之间替换符号链接，都超出了执行前 hook 能阻止的范围。见[超出范围的防护](/zh-Hans/guides/known-limitations#out-of-scope-protections)。
