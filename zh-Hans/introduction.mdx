## CC Safety Net 是什么？

CC Safety Net 是面向 Claude Code、Codex、Cursor 等 AI 编码智能体的执行前 hook。它在每条命令和每个文件操作运行前进行检查，阻止会破坏未提交工作或泄露机密的操作，例如 `git reset --hard`、`git push --force`、针对主目录的 `rm -rf`，以及对 `.env` 文件、SSH 密钥和云凭证的读取。它支持 16 个编码智能体。

## 为什么需要它

截至 2026 年 10 月，没有一款主流编码 CLI 会在你交给它的工作区内确定性地阻止破坏性 git 命令。`git reset --hard`、`git checkout -- .`、`git clean -f`、`git stash clear` 和 `git push --force` 操作的都是智能体本来就能写入的文件，因此把写入限制在项目内的沙箱看不出任何问题。OpenAI 的 [Codex 安全文档](https://learn.chatgpt.com/docs/security)称，workspace-write 下的命令“can still mutate state and perform destructive operations”。Claude Code 的[沙箱文档](https://code.claude.com/docs/en/sandboxing)把写入限制在工作目录内，而你未提交的工作恰恰就在那里。

运行它还有另外三个理由：

- **在概率性检查之下加一道确定性检查。** 截至 2026 年 10 月，Anthropic 公布 Claude Code [auto-mode](https://www.anthropic.com/engineering/claude-code-auto-mode) 分类器在真实过激操作上的漏报率为 17%，并称它“not a drop-in replacement for careful human review”。hook 执行的是固定规则，而不是一次主观判断。
- **无需配置的机密保护。** Claude Code 没有内置的凭证拒绝列表，其他 CLI 则要求你为每个工具单独编写。CC Safety Net 一经安装就会阻止访问 `.env` 文件、SSH 密钥和云凭证。见[机密保护](/zh-Hans/reference/secret-protection)。
- **16 个 CLI 共用一份策略和一份审计记录。** 五家厂商提供五套互不兼容的权限机制，而且都没有事后可查阅的决策日志。

`CLAUDE.md` 或 `AGENTS.md` 中的指令可以引导智能体，但无法强制实施限制。曾有智能体无视这些指令，用一条 `rm -rf ~/` [清除了数小时的工作](https://www.reddit.com/r/ClaudeAI/comments/1pgxckk/claude_cli_deleted_my_entire_home_directory_wiped/)。Adversa 的[事件追踪](https://adversa.ai/blog/ai-coding-agent-incidents)记录了 2025 和 2026 年的九起智能体破坏事件，其中约一半开启了防护措施。沙箱和允许列表的 CVE 见[保护层比较](/zh-Hans/guides/vs-sandboxing)。

## 它拦截什么

CC Safety Net 安装在编码智能体中，在智能体的工具调用到达你的机器之前运行。

它检查 shell 命令，以及文件写入、编辑、搜索和补丁操作，然后放行该操作，或者阻止它并直接说明原因。阻止结果以普通工具结果的形式返回，因此智能体可以[在不执行被阻止操作的情况下继续任务](/zh-Hans/guides/how-it-works#what-a-block-looks-like)。

CC Safety Net 依据命令的实际作用做出决策，而不是看它的字面写法。`git checkout -b feature` 会创建分支，因此被允许；`git checkout -- file` 会丢弃未提交的更改，因此被阻止。两条命令开头的两个单词完全相同。

## 常见问题

### CC Safety Net 免费吗？

免费。CC Safety Net 采用 MIT 许可证，源代码托管在 [GitHub](https://github.com/kenryu42/cc-safety-net) 上。

### CC Safety Net 使用 LLM 吗？

不使用。所有决策都由本地基于规则的解析器做出，不调用任何模型。同一条命令每次得到的决策都相同。见[工作原理](/zh-Hans/guides/how-it-works#does-cc-safety-net-use-an-llm)。

### CC Safety Net 会把我的数据发送到别处吗？

不会。CC Safety Net 没有遥测，在本地做出决策，不发起任何网络调用。只有三种情况会用到网络：`npx` 或 `bunx` 获取软件包时，`rule add` 或 `rule update` 从 GitHub 获取 rulebook 时，以及 `update` 查询 npm 注册表时。[审计日志](/zh-Hans/reference/audit-log)始终保存在你的机器上。

### CC Safety Net 会拖慢智能体吗？

以插件形式加载到智能体内部的集成几乎没有额外开销。通过 `npx` 运行的 hook 每次工具调用会增加几百毫秒。如果你的环境更慢，见[故障排除](/zh-Hans/guides/troubleshooting)。

### CC Safety Net 支持 Windows 吗？

支持。只有 Hermes Agent 和 OpenClaw 例外，它们仅能在 macOS 和 Linux 上运行。Amp 的文档只写明支持 macOS、Linux 和 WSL，没有提到原生 Windows。见[安装前须知](/zh-Hans/installation#before-you-install)。

### CC Safety Net 是沙箱吗？

不是。沙箱负责隔离文件系统和网络。沙箱允许在项目内执行的破坏性操作，CC Safety Net 会将其阻止，因此两者应同时运行。它无法查看二进制文件内部，也无法检查绕过其集成的命令。见[保护层比较](/zh-Hans/guides/vs-sandboxing)和[已知限制](/zh-Hans/guides/known-limitations)。
