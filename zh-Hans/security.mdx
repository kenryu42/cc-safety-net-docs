CC Safety Net 没能阻止的命令属于 bug，请提交公开 GitHub issue。CC Safety Net 自身造成的有害行为（例如泄漏机密）属于漏洞，请私密报告。不确定属于哪一类时，请阅读[选择公开或私密报告](#choose-a-public-or-private-report)。如需先诊断问题，请从[故障排除](/zh-Hans/guides/troubleshooting)开始。

维护者只为 `cc-safety-net` 的最新发布版本提供安全修复。如果你使用旧版本，请先升级，在新版本上复现问题后再报告。

CC Safety Net 保护什么、信任什么，见[安全模型](/zh-Hans/guides/security-model)。策略的权威版本是源代码仓库中的 [SECURITY.md](https://github.com/kenryu42/cc-safety-net/blob/main/SECURITY.md)。

## 私密报告漏洞

**不要在公开 GitHub issue 中报告安全漏洞。** 如果仓库提供了 GitHub 私密漏洞报告功能，请使用该功能。如果无法使用，请发送邮件至维护者邮箱 jliew@420024lab.com。

在可以安全分享时，请提供以下信息：

- 受影响的 `cc-safety-net` 版本
- 操作系统和运行时版本
- 受影响的集成，例如 Claude Code、OpenCode、Gemini CLI、GitHub Copilot CLI、Grok Build、Factory Droid、Devin CLI 或 Codex
- 复现步骤，以及绕过、削弱或滥用 CC Safety Net 的命令或输入
- `cc-safety-net explain` 或 `cc-safety-net doctor` 的相关输出
- 问题是否会造成数据丢失、命令执行、机密暴露或其他具体安全影响

发送日志或命令输出前，请先对其中的 token、凭证、私有仓库名称和敏感文件路径脱敏。`explain` 和 `doctor` 的输出会保留路径和主机名，请先阅读[分享跟踪之前](/zh-Hans/reference/explain-trace#before-you-share-a-trace)。

## 选择公开或私密报告

只需回答一个问题：工具只是没能阻止破坏性命令，还是工具自身造成了危害？

CC Safety Net 本应阻止却没有阻止的命令，属于 bug，请提交公开 GitHub issue。strict 和 paranoid 的威胁模型本就假定攻击者能让智能体发出任何破坏性命令，所以公开“这种命令形式没被拦下”不会给攻击者带来任何新东西。公开报告能让缺口更快修复，其他用户也能先用自定义规则应对。

如果工具自身泄漏了调用方原本并不掌握的机密、在自身目录之外写入文件，或发布了被篡改的软件包，请私密报告漏洞。

## 哪些问题属于安全问题

请私密报告以下问题：

- 通过阻止消息、审计日志、诊断或调试输出，泄漏并非由工具调用提供的机密，例如工具读取到的文件内容或环境变量值
- 误报报告的预填内容中带有报告预览声称已替换的路径
- 审计日志或配置处理中的路径遍历或文件系统问题，即构造的输入会写入预期目录之外
- 影响已发布 npm 软件包或插件分发的供应链或打包问题，包括 rulebook 完整性

## 哪些问题应提交公开 issue

以下问题请使用普通 [GitHub issues](https://github.com/kenryu42/cc-safety-net/issues)：

- 任何让破坏性命令得以执行的绕过或 fail open，包括覆盖缺口（规则尚未阻止的命令）、解析器、分词器或包装器分析的边缘情况，以及让命令通过而不是被阻止的分析错误。请报告命令*形式*，不要提供可直接粘贴使用的武器化提示注入 payload。
- 脱敏遗漏，即脱敏器无法识别的凭证形式或未覆盖的字段，前提是该值来自工具调用本身，且只出现在返回给该调用方的拒绝消息或本地审计日志中
- 安全命令被阻止的误报
- 缺少便利规则或新功能需求
- 文档错误
- 没有安全影响的安装问题
- 关于自定义规则或配置的问题

Anthropic OSS Scanner 报告的问题（包括绕过）按该服务的条款属于保密内容。维护者会私下修复，等修复发布之后才提交公开 issue。

Grok Build、Factory Droid 和 Devin CLI 等 fail open 的宿主，以及 CC Safety Net 无法弥补的其他宿主限制，属于宿主行为，不是覆盖缺口。各宿主的限制见[已知限制](/zh-Hans/guides/known-limitations)。

<Note>
  即使破坏性命令覆盖缺口看起来很严重，也仍应公开报告，维护者不会把它重新归类为漏洞。私密渠道只用于上面列出的类别。在 [standard 模式有文档说明的放宽范围](/zh-Hans/configuration/modes#default-mode)内允许的命令不属于缺口。standard 只提供尽力保护，strict 和 paranoid 才会对这些形式 fail closed。
</Note>

## 报告后的处理

你应在 7 天内收到初始响应。维护者会与你一起确认影响、确定受影响的版本、准备修复并协调披露。公布详细信息前，请给维护者合理的调查时间。

确认漏洞后，维护者会尽快发布修复。除非你另有要求，维护者也可能发布 GitHub 安全公告或发布说明，并给予适当署名。修复版本发布之前，请不要披露利用细节。
