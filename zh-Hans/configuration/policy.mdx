`policy.json` 是 CC Safety Net 的用户级设置文件。它用于选择安全预设、开关内置保护、添加受保护路径，以及设置审计记录的保留时间。

它与 `rule.json` 和 rulebook 分开。后两者用于定义自定义阻止规则，schema 见[自定义规则](/zh-Hans/configuration/custom-rules)。

## 策略文件位置

| 情形 | 路径 |
| --- | --- |
| 默认 | `~/.cc-safety-net/policy.json` |
| 已设置 `CC_SAFETY_NET_HOME` | `$CC_SAFETY_NET_HOME/policy.json` |

设置 `CC_SAFETY_NET_HOME` 后，该文件**直接**位于该目录下，与 `rules/` 同级。覆盖变量本身参见[环境](/zh-Hans/configuration/environment)。

策略文件只有一个。**不存在项目范围的 `policy.json`**。运行时只读取上述路径，因此项目无法降低或提高你的策略。

仪表板写入该文件时，会以 `0700` 创建目录、以 `0600` 创建文件。

## 策略文件保护

规范的用户 `policy.json` 在**每个**运行时状态（`ready` 或 `degraded`）下都是受保护路径。策略文件保护在加载配置快照之前运行，因此损坏的配置无法削弱它。以下操作一律硬停止：

- 通过任何工具对该文件的写入、编辑和修补
- 以该文件作为操作数的 Shell 命令
- 指向该文件的写入重定向
- 对其所在目录或任何上级目录的递归 `rm`
- 触及该文件的 `find … -delete` 和 `find … -exec rm`
- 以该文件、其所在目录或上级目录为源的 `mv`

读取仍然允许。只读命令允许列表包括 `[`、`cat`、`file`、`grep`、`head`、`jq`、`less`、`ls`、`more`、`rg`、`sed`、`stat`、`tail`、`test` 和 `wc`。`sed` 仅限未使用 `-i` 或 `--in-place` 就地编辑的情况。Grep、Glob 等只读工具不受此限制。

<Warning>
智能体无法写入此文件，因此请改为让它把改动*展示*给你。策略修改由你自己在编辑器中应用，或通过仪表板应用。
</Warning>

## 编辑策略文件

选择以下选项之一：

- **使用仪表板。**运行 `cc-safety-net gui`。仪表板会以正确的权限写入文件，并且能修复校验不通过的文件。文件存在错误期间，表单显示的是完整的默认值，而不是文件中那些有效的值。在修复文件之前无法保存。修复会保留每一项可识别的有效设置，并丢弃无效字段。如果不想要这种修复行为，请手动编辑文件，并用 `status` 检查。
- **直接编辑 JSON。** 在编辑器中打开文件手动修改。运行时会在下一次工具调用时读取改动，无需重启任何东西。

手动编辑后，确认结果：

```bash
npx cc-safety-net status
```

判定为 `degraded`，说明文件中有字段被拒绝。`npx cc-safety-net doctor` 会指出具体字段。运行时**从不**自行重写 `policy.json`。在你手动修复或使用仪表板修复前，无效文件会原样保留。

## 完整的策略示例

包含每个字段及其默认值：

```json
{
  "version": 1,
  "safety": {
    "level": "standard",
    "overrides": {}
  },
  "workflow": {
    "worktree_mode": false
  },
  "destructive_command_protection": {
    "enabled": true,
    "overrides": {},
    "allow_paths": []
  },
  "secret_protection": {
    "enabled": true,
    "overrides": {},
    "deny_paths": [],
    "allow_paths": []
  },
  "audit": {
    "retention_days": 30
  }
}
```

只有 `version` 是必填的。其余字段都可以省略，省略时采用上面显示的默认值。如果该文件根本不存在，CC Safety Net 就按这些默认值运行，并保持 `ready`。

根对象是**严格**的：无法识别的顶级键会报错，`safety`、`workflow`、`destructive_command_protection`、`secret_protection` 或 `audit` 内无法识别的键同样如此。

## Schema 参考

<ParamField body="version" type="integer" required>
Schema 版本。必须为 `1`。这是唯一的必填字段；值缺失或错误时的诊断信息是 `version must be 1`。
</ParamField>

<ParamField body="safety.level" type="string" default="standard">
安全预设。取 `"standard"`、`"strict"` 或 `"paranoid"` 之一。每个预设都提供一组继承而来的能力默认值：`strict` 启用 `fail_closed`；`paranoid` 启用 `fail_closed`、`paranoid_rm` 和 `paranoid_interpreters`。各项能力具体改变了什么，参见[模式](/zh-Hans/configuration/modes)。
</ParamField>

<ParamField body="safety.overrides.fail_closed" type="boolean">
无论预设如何，都显式设置 fail-closed 能力，可调高也可调低。省略该键则从预设继承。
</ParamField>

<ParamField body="safety.overrides.paranoid_rm" type="boolean">
显式设置偏执 `rm` 能力，可调高也可调低。省略该键则从预设继承。
</ParamField>

<ParamField body="safety.overrides.paranoid_interpreters" type="boolean">
显式设置偏执解释器能力，可调高也可调低。省略该键则从预设继承。
</ParamField>

<ParamField body="workflow.worktree_mode" type="boolean" default="false">
在**已确认**的 linked worktree 内放宽本地丢弃类 git 规则。检测采用 fail-closed：如果无法明确判定工作目录位于 linked worktree 中，仍然沿用更严格的默认规则。哪些规则会放宽、哪些永不放宽，确切列表参见[模式](/zh-Hans/configuration/modes)。
</ParamField>

<ParamField body="destructive_command_protection.enabled" type="boolean" default="true">
已注册破坏性命令规则的总开关。设为 `false` 会短路所有已注册规则，但灾难性规则除外。灾难性规则始终强制执行。
</ParamField>

<ParamField body="destructive_command_protection.overrides" type="object" default="{}">
按已注册破坏性命令规则 id 设置的单项规则状态，值为 `"on"` 或 `"off"`。它叠加在能力推导出的状态之上，因此 `"on"` 可以启用预设未开启的规则，`"off"` 可以关闭预设开启的规则。
</ParamField>

<ParamField body="destructive_command_protection.allow_paths" type="string[]" default="[]">
免于破坏性命令规则约束的路径。条目必须是绝对路径，或以 `~/` 开头。
</ParamField>

<ParamField body="secret_protection.enabled" type="boolean" default="true">
机密保护总开关。设为 `false` 会跳过整个机密阶段，包括你配置的 `deny_paths`。
</ParamField>

<ParamField body="secret_protection.overrides" type="object" default="{}">
按已注册机密保护规则 id 设置的单项规则状态，值为 `"on"` 或 `"off"`。启用机密保护时，大多数机密规则默认开启，因此通常使用 `"off"`。[编码 CLI 配置层](#默认情况下关闭的规则)默认关闭，显式写 `"on"` 才能启用其中的规则。
</ParamField>

<ParamField body="secret_protection.deny_paths" type="string[]" default="[]">
在内置敏感路径之外，额外作为机密加以保护的路径。验证规则见[拒绝路径](#拒绝路径)。
</ParamField>

<ParamField body="secret_protection.allow_paths" type="string[]" default="[]">
从内置机密模式规则中豁免的精确文件或目录树。配置的拒绝路径和编码 CLI 保护仍然适用。验证规则和优先顺序见[机密允许路径](#机密允许路径)。
</ParamField>

<ParamField body="audit.retention_days" type="integer" default="30">
清理删除前保留的审计历史天数。必须是 `1` 到 `365` 之间的整数。
</ParamField>

## 安全级别和能力覆盖

`safety.level` 选择预设，然后由 `safety.overrides` 显式设置各个能力。只有这里可以**降低**能力，环境标志只能提高能力。

```json
{
  "version": 1,
  "safety": {
    "level": "paranoid",
    "overrides": {
      "paranoid_interpreters": false
    }
  }
}
```

该示例采用 `paranoid` 预设，但关闭了对所有解释器单行命令的一律阻止。最终的能力组合不匹配任何预设时，有效级别会报告为 `custom`。

<Note>
环境可以提高策略的级别、强制开启某些能力，但反过来不行。`policy.json` 与环境之间的完整优先顺序参见[环境](/zh-Hans/configuration/environment)，其中包括 `worktree_mode` 的逻辑 OR 组合和旧版 `SAFETY_NET_*` 别名。
</Note>

## 破坏性命令保护

`destructive_command_protection.overrides` 通过 id 指定内置规则，例如：

```json
{
  "version": 1,
  "destructive_command_protection": {
    "overrides": {
      "git.push-force": "off",
      "rm.recursive-force-paranoid": "on"
    }
  }
}
```

未注册的 id 会被拒绝，报 `unknown destructive command rule id "<id>"`；除 `"on"` 或 `"off"` 之外的任何值都会被拒绝，报 `destructive_command_protection.overrides.<id> must be "on" or "off"`。

**灾难性规则始终强制执行，用户不可配置。** 它们忽略 `enabled: false`，也忽略 `"off"` 覆盖。这些规则涵盖删除 `/` 或主目录、删除 Git 元数据，以及它们在 PowerShell 和 `find` 下的等价形式。各规则强制执行的具体行为参见[被阻止的命令](/zh-Hans/reference/blocked-commands)。

### 允许路径

`destructive_command_protection.allow_paths` 将特定位置排除在破坏性命令规则之外。验证比拒绝路径更严格：

| 条目 | 结果 |
| --- | --- |
| 非字符串，或去除空白后为空的字符串 | 无效：`must be a non-empty path string` |
| 相对路径 | 无效：`must be an absolute path or start with ~/` |
| 恰好就是主目录 | 无效：`cannot be the home directory` |
| 包含主目录的路径，例如 `/` | 无效：`cannot contain the home directory` |
| 其他任何绝对路径或以 `~/` 开头的路径 | 有效 |

## 机密保护

机密保护会阻止读写含凭证的文件。本节说明配置约定。内置规则的完整目录，包括每个 id、受保护路径和豁免，见[机密保护参考](/zh-Hans/reference/secret-protection)。

`secret_protection.overrides` 通过 id 指定单条内置规则，值为 `"on"` 或 `"off"`。`"off"` 关闭默认开启的规则；`"on"` 用于选择启用默认关闭层中的规则：

```json
{
  "version": 1,
  "secret_protection": {
    "overrides": {
      "secret.ext-pattern.kdbx": "off",
      "secret.cli.claude-code.config": "on"
    },
    "deny_paths": ["config/secrets", "~/work/vault"],
    "allow_paths": [".env.test", "fixtures/credentials"]
  }
}
```

未注册的 id 会被拒绝，报 `unknown secret protection rule id "<id>"`；其他任何值都会被拒绝，报 `secret_protection.overrides.<id> must be "on" or "off"`。

### 默认情况下关闭的规则

只要启用了机密保护，大多数内置机密规则都处于开启状态。有一层例外：**编码 CLI 配置**规则，它涵盖受支持的编码智能体的设置文件和 MCP 配置文件。这些文件可能内嵌凭证，但智能体也会把编辑它们当作日常工作，因此该层默认关闭，需要你逐条用显式的 `"on"` 覆盖来选择启用。启用某条配置规则后，它会保护该智能体的用户级配置文件，同时也会保护任意仓库根目录下按名称匹配的项目级文件，例如任何 `.mcp.json`。

十个默认关闭的 id、它们默认开启的 **编码 CLI 凭证** 对应规则，以及每条规则保护的确切路径，都列在[机密保护参考](/zh-Hans/reference/secret-protection#编码-cli-配置层（默认关闭）)中。

### 拒绝路径

`secret_protection.deny_paths` 在内置敏感路径之上添加你自己的受保护位置。拒绝路径会**先于**内置规则检查，一旦命中即为硬停止，归因于规则 id `secret.deny-path`。

验证：

| 条目 | 结果 |
| --- | --- |
| 非字符串，或去除空白后为空的字符串 | 无效：`must be a non-empty path string` |
| 相对路径，例如 `config/secrets` 或 `./secrets` | **有效**：每个会话都按配置工作目录解析 |
| 单独的 `~`、`$HOME` 或 `${HOME}` | 无效：主目录本身会被拒绝 |
| `~/…`、`$HOME/…` | 展开后有效，除非解析到主目录或其上级 |
| 恰好解析为主目录的路径 | 无效：`cannot be the home directory or a path above it (this would block every command the agent runs)` |
| 解析为主目录上级的路径，例如 `/`、`/Users` 或 `/home` | 无效：同一条消息 |
| 其他任何绝对路径 | 有效 |

相对条目会按各会话的工作目录解析，因为保存策略时无法确定会话目录。主目录、主目录的上级路径和 `/` 会被拒绝。这些路径会阻止主目录下几乎所有工作区中的命令。

**有效的拒绝路径保护什么：**路径本身**及其所有后代**。比较之前，目标按执行工作目录规范化，每个配置的路径按配置工作目录规范化。

有两个限制值得了解：

- 拒绝路径仅在 `secret_protection.enabled` 为 `true` 时生效。设为 `false` 会连同机密阶段的其他一切一起关闭它们。
- `secret.deny-path` 不是已注册的机密规则 id，因此 `secret_protection.overrides` 无法禁用它。只有 `secret_protection.enabled: false` 可以。

### 机密允许路径

`secret_protection.allow_paths` 把精确的文件或目录及其所有后代从内置的 basename、主目录、密钥变体和扩展名规则中豁免出来。它适用于你有意管理的文件，例如仓库中的 `.env.test`，或包含形似凭证但并非机密的文件名的 fixture 目录。

优先顺序是固定的：

1. 配置的拒绝路径始终优先。如果同一目标同时出现在两个列表中，结果是 `secret.deny-path`。
2. 编码 CLI 凭证和配置规则（`secret.cli.*`）始终优先。允许路径无法暴露智能体自身的凭证或配置。
3. 命中允许路径会抑制该目标上的其他任何内置机密规则。

验证：

| 条目 | 结果 |
| --- | --- |
| 非字符串，或去除空白后为空的字符串 | 无效：`must be a non-empty path string` |
| 相对路径，例如 `.env.test` 或 `fixtures/credentials` | **有效**：每个会话都按配置工作目录解析 |
| 包含 `*` 或 `?` 的条目 | 无效：`cannot contain glob characters (* or ?); list the exact file or directory` |
| 单独的 `~`、`$HOME` 或 `${HOME}`，或主目录之上的路径 | 无效：`cannot cover the home directory or a path above it (this would disable secret protection everywhere)` |
| `~/.cc-safety-net` 或其下的任何路径 | 无效：`cannot cover the guard's own configuration` |
| 其他任何字面绝对路径、`~/…`、`$HOME/…` 或 `${HOME}/…` 路径 | 有效 |

条目是字面路径，而不是 glob 模式。目标按执行工作目录解析，相对的允许条目按配置工作目录解析。在进行相同或后代比较前，两边都会跟随现有符号链接，因此允许根目录也涵盖通过符号链接到达的目标。

运行时会在解析后再次检查安全边界。解析结果为主目录或主目录上级的条目会被忽略。位于生效的防护配置根目录之下的目标永远不会被豁免，包括 `CC_SAFETY_NET_HOME` 改变了该根目录时，以及主目录或 `~/.cc-safety-net` 是符号链接时。

## 审计保留

`audit.retention_days` 控制审计记录在保留期清理将其删除之前能保留多久。默认值为 **30 天**，接受的范围是 **1 到 365**。

```json
{
  "version": 1,
  "audit": {
    "retention_days": 90
  }
}
```

清理是机会性的：每个 UTC 日对每个审计根目录最多遍历一次，在审计写入之后、审计读取之前进行。它从不抛出异常，也不跟随符号链接。记录 schema 和采集的内容参见[审计日志](/zh-Hans/reference/audit-log)。

<Note>
保留期独立于策略的其余部分解析。清理扫描直接从文件中读取这一字段，因此即使策略的其他部分验证失败，清理仍会照常进行。缺失、非整数或不可用的值会回落至 30；低于 `1` 的值被限制到 `1`，高于 `365` 的值被限制到 `365`。

因此，超出范围的值会同时引发两件事：schema **拒绝**它们，使运行时降级；而清理扫描把它们**限制**在范围内。`"retention_days": 1000` 既会作为诊断出现，又会按 365 天清理。
</Note>

## 无效策略的行为

无效的 `policy.json` 永远不会阻止正常工作。它会把运行时置为 `degraded` 并改用回退值。

| 文件状态 | 运行时行为 |
| --- | --- |
| 可读但无效 | 逐字段挽救文件内容。每个已识别的有效部分继续生效。其余部分使用保护性默认值。 |
| 空、无法解析或不是 JSON 对象 | 整个文件都使用内置的保护性默认值。 |
| 缺失 | 使用内置默认值，且不产生诊断。运行时保持 `ready`。 |

回退过程优先保留保护，因此损坏的文件通常会产生比原配置*更多*的拒绝：

| 字段 | 无效时 |
| --- | --- |
| `version` | 重写为 `1` |
| `safety.level` | 回落至 `standard` |
| `safety.overrides.*` | 丢弃无效的键，该能力因而从预设继承 |
| `workflow.worktree_mode` | 回落至 `false` |
| `destructive_command_protection.enabled` | 回落至 `true`：保护**开启** |
| `destructive_command_protection.overrides` | 无效条目被丢弃；非对象变为 `{}` |
| `destructive_command_protection.allow_paths` | 无效条目被丢弃；非数组变为 `[]`：不存在任何豁免 |
| `secret_protection.enabled` | 回落至 `true`：保护**开启** |
| `secret_protection.overrides` | 无效条目被丢弃；非对象变为 `{}` |
| `secret_protection.deny_paths` | 无效条目被丢弃；非数组变为 `[]` |
| `secret_protection.allow_paths` | 无效条目被丢弃；非数组变为 `[]`：没有任何机密豁免 |
| `audit.retention_days` | 限制在范围内，无法使用时取 `30` |

<Warning>
无效条目会被**丢弃，而不是修复**。拼错的拒绝路径不再保护对应位置。无效的 `safety.level` 会回退到 `standard`。这两种失效都不会直接提示你。每次手动编辑后，请运行 `npx cc-safety-net status`。
</Warning>
