要阻止破坏性的 `aws` 命令，请安装官方的 `aws` rulebook。CC Safety Net 为 `aws`、`terraform`、`gcloud` 和 `az` 各发布了一个 rulebook，一条命令即可安装：

```bash
npx -y cc-safety-net rule add --only aws --global
```

Rulebook 是 JSON 数据。CC Safety Net 从不执行它们，而且它们只会新增阻止，因此无法削弱内置保护。Rulebook 的文件格式见[自定义规则](/zh-Hans/configuration/custom-rules)。

<Note>
官方 rulebook 使用 `rulebook_version: 2`，需要 CC Safety Net 2.3.0 或更高版本。
</Note>

## 目录

[`cc-safety-net/rulebooks`](https://github.com/cc-safety-net/rulebooks) 仓库为每个 CLI 提供一个 rulebook：

| Rulebook | CLI | 阻止内容 |
|---|---|---|
| `terraform` | `terraform` | `destroy`、`apply -destroy`、`state rm`、`state push`、`workspace delete` |
| `aws` | `aws` | S3 对象与存储桶删除、`ec2 terminate-instances`、`cloudformation delete-stack`、RDS 与 DynamoDB 删除、`eks delete-cluster`、`kms schedule-key-deletion` |
| `gcloud` | `gcloud` | `projects delete`、`compute instances delete`、`storage rm`、Cloud SQL 与 GKE 删除、`kms keys versions destroy`，以及 alpha、beta、preview 发布通道 |
| `azure` | `az` | `group delete`、`resource delete`，VM、AKS、存储、SQL 与 Cosmos DB 删除，`keyvault purge` |

每个 rulebook 覆盖的是可识别的误操作，而不是对云服务商 API 的完整建模。`aws s3 rm --dryrun`、`terraform state rm -dry-run`、`aws ec2 terminate-instances --dry-run` 等安全预览仍然允许。每个 rulebook 都有一份依据文档，记录每条规则存在的原因、安全预览、有意排除的范围和已知缺口：[terraform](https://github.com/cc-safety-net/rulebooks/blob/main/docs/terraform.md) · [aws](https://github.com/cc-safety-net/rulebooks/blob/main/docs/aws.md) · [gcloud](https://github.com/cc-safety-net/rulebooks/blob/main/docs/gcloud.md) · [azure](https://github.com/cc-safety-net/rulebooks/blob/main/docs/azure.md)。

## 能阻止所有 aws 命令吗？

不能。每条规则都需要一个非空的 [`command_path`](/zh-Hans/configuration/custom-rules#version-2-rules)，例如 `["s3", "rm"]`，因此没有规则能匹配带任意参数的 `aws` 本身。`aws` rulebook 阻止的是目录中列出的破坏性操作。要阻止更多命令，请为每个想拦下的 `aws` 命令路径自己写一条规则。

## 安装

优先使用用户范围。`terraform` 和 `aws` 会跨项目使用，规则应当在每个项目中生效，而不是只在某个仓库中生效：

```bash
# Everything the repository publishes
npx -y cc-safety-net rule add cc-safety-net/rulebooks --global

# A selection
npx -y cc-safety-net rule add --only terraform aws --global

# Pin an immutable release tag instead of following the default branch
npx -y cc-safety-net rule add --ref v1.0.0 --only terraform --global
```

- `--only <rulebook...>` 按你列出的顺序添加指定的 rulebook。指定了仓库未发布的名称时，添加会失败。
- `--ref <ref>` 指定分支、标签或提交，而不使用默认分支。ref 可以包含 `/`，例如 `--ref feature/rulebook-v2`。
- 不写来源时，带上其中任一个选项都会选中 `cc-safety-net/rulebooks`。要安装它发布的全部 rulebook，请写出仓库名。

省略 `--global` 即安装到项目范围。此时 `rule add` 会把 rulebook 文件写入仓库的 `.cc-safety-net/` 下，提交后规则会随每位队友的克隆生效。参见[团队配置](/zh-Hans/guides/team-setup)。

也可以按来源规范形式添加单个 rulebook，`rule list` 显示的和 `rule remove` 接受的都是这种形式：

```bash
npx -y cc-safety-net rule add cc-safety-net/rulebooks#main/terraform --global
```

## 安装做了什么

`rule add` 获取选中的每个 rulebook，校验它并运行其中的测试 fixture，然后复制到你的范围内，路径为 `rules/<name>/rulebook.json`。它会打印内容来自哪个提交。

CC Safety Net 在每次工具调用时从磁盘读取 rulebook。只有 `rule add` 和 `rule update` 会访问网络。没有后台拉取，也没有自动更新，因此只有在你运行以下命令时副本才会变化：

```bash
# Re-fetch every source and report added, removed, and modified rules
npx -y cc-safety-net rule update

# Refresh one source
npx -y cc-safety-net rule update cc-safety-net/rulebooks#main/terraform
```

`rule update` 会让分支 ref 跟到最新提交。发布标签从不变化，因此在你切换 ref 之前，`--ref v1.0.0` 安装的内容保持不变。

## 覆盖或移除

要关闭单条规则或替换其阻止原因，请在 `rule.json` 中添加覆盖。Rulebook 文件保持不变，因此 `rule update` 不会与你的覆盖冲突。参见[关闭单条规则](/zh-Hans/configuration/custom-rules#turn-off-one-rule)。要整个移除一个 rulebook：

```bash
npx -y cc-safety-net rule remove cc-safety-net/rulebooks#main/terraform --global
```

## 从任意仓库安装

任何在 `.cc-safety-net/rules/<name>/rulebook.json` 下发布 rulebook 的 GitHub 仓库都可以用 `rule add owner/repo` 安装，因此团队或供应商也能用同样的方式发布自己的目录。

<Warning>
CC Safety Net 从不执行 rulebook，rulebook 也只会新增阻止。但命令被阻止时，其中的原因会成为智能体读到的消息的一部分。添加第三方 rulebook 前请先审查内容，并优先用 `--ref` 固定到你检查过的标签或提交，而不是跟随不受你控制的分支。
</Warning>

## rulebook 不生效时

`npx -y cc-safety-net rule list` 显示每个生效的 rulebook 及其规则数量，`npx -y cc-safety-net explain "terraform destroy"` 可以把一次决策追溯到做出它的规则。如果某个来源显示为未生效，参见 [rulebook 是实时文件](/zh-Hans/configuration/custom-rules#rulebooks-are-live-files)。
