运行 `npx -y cc-safety-net@latest install --agy-cli`。它把 CC Safety Net 安装为原生 Antigravity 插件，插件自带 `PreToolUse` hook 和 `/cc-safety-net` 技能。该 hook 检查 `run_command` 中的 shell 命令，以及通过 `manage_task` 发送给正在运行任务的输入。然后运行 `npx cc-safety-net doctor`，确认 hook 已生效。

## 在 Antigravity CLI 中安装 CC Safety Net

<Steps>
  <Step title="运行安装程序">
    ```bash
    npx -y cc-safety-net@latest install --agy-cli
    ```
  </Step>
  <Step title="确认 hook 已生效">
    ```bash
    npx cc-safety-net doctor
    ```
  </Step>
</Steps>

安装会运行 `agy plugin install`，因此 `agy` 命令必须在 `PATH` 上。否则[目标列表](/zh-Hans/reference/cli/install#selecting-a-target)会把 Antigravity CLI 置灰，并标为 `CLI not installed`。

插件就位后，`doctor` 输出中 Antigravity CLI 一行显示 `Detected` 和 `Configured`。如果 `~/.gemini/config/config.json` 禁用了该插件，或者 hook 定义带有 `enabled: false`，则显示 `Detected` 和 `Not configured`。

插件自带 `/cc-safety-net` 技能，安装时一并装入。见 [/cc-safety-net 技能](/zh-Hans/guides/skill#how-you-invoke-it)。

<span id="what-the-antigravity-cli-install-changes"></span>

## Antigravity CLI 安装会改动什么

安装运行 `agy plugin install https://github.com/kenryu42/cc-safety-net/tree/plugin`。Antigravity 把插件放在 `~/.gemini/config/plugins/cc-safety-net`。插件的 `hooks.json` 注册一个 `PreToolUse` hook，在插件目录中以 30 秒超时运行 `node ./dist/bin/cc-safety-net.js hook --agy-cli`，因此每次工具调用都不会触发 `npx` 下载。

如果 `~/.gemini/config/config.json` 禁用了该插件，安装还会运行 `agy plugin enable cc-safety-net`。重新运行安装会把插件替换为当前版本。

<span id="migrate-from-the-legacy-antigravity-cli-hook"></span>

## 从旧版 Antigravity CLI hook 迁移

2.9.0 之前的版本会在 `~/.gemini/config/hooks.json` 中写入一个运行 `npx -y cc-safety-net hook --agy-cli` 的托管条目。插件安装成功后，安装会删除该条目，并打印 `Removed the legacy Antigravity CLI hook from <path>`。文件中的其他 hook 保持不变。

插件安装失败时，该条目会保留，旧 hook 仍会检查你的命令，而安装以 `1` 退出。[`update`](/zh-Hans/reference/cli/update) 执行同样的迁移。

<span id="what-the-antigravity-cli-hook-checks"></span>

## Antigravity CLI hook 检查什么

- hook 把 `run_command` 调用作为 shell 命令分析。
- `Action` 为 `send_input` 且 `Input` 为非空字符串的 `manage_task` 调用，hook 也会分析。这段文本会发送给已在运行的任务。hook 把 `Input` 作为 shell 命令分析，并检测其 shell 方言。
- 其他 `manage_task` 操作被视为不运行命令的工具调用。

## Antigravity CLI 检查失败时会怎样

hook 失败时，Antigravity CLI 会阻止该工具调用。崩溃或非零退出、超时（30 秒），以及输出不是有效 JSON，都会让调用停止。这是本项目 2026 年 10 月在 macOS 上的 Antigravity CLI 1.4.5 中观察到的行为，Antigravity 并未把它作为约定公布。

## 从 Antigravity CLI 卸载 CC Safety Net

```bash
npx -y cc-safety-net@latest uninstall --agy-cli
```

插件目录存在时，卸载会运行 `agy plugin uninstall cc-safety-net`，再删除旧版安装留在 `~/.gemini/config/hooks.json` 中的托管条目。该文件的其他内容保持不变。

<span id="troubleshoot-antigravity-cli"></span>

## Antigravity CLI 故障排除

- **`doctor` 报告 `Error (Antigravity CLI): Failed to parse Antigravity hooks config <path>: <reason>`。** `<path>` 指向的文件，即插件的 `hooks.json` 或 `~/.gemini/config/hooks.json`，不是有效的 JSON，因此 `doctor` 把 Antigravity CLI 计为未配置，并以 `1` 退出。修正 JSON 后重新安装。见 [hook 配置解析错误](/zh-Hans/reference/cli/doctor#hook-config-parse-errors)。
- **安装成功后 `doctor` 仍显示 `Not configured`。** `~/.gemini/config/config.json` 禁用了该插件。运行 `agy plugin enable cc-safety-net`，或者重新安装，安装会把它启用。
- **你手动编辑过插件。** `doctor` 不对 Antigravity CLI 运行[漂移检查](/zh-Hans/reference/cli/doctor#managed-hook-drift)，因此 hook 被改动时不会发出警告。重新运行安装即可替换插件。
