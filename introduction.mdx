AI coding agents are powerful, and that power cuts both ways. A single misguided command like `rm -rf ~/` or `git checkout -- .` can wipe hours of uncommitted work in milliseconds. This isn't hypothetical: a [well-documented Reddit incident](https://www.reddit.com/r/ClaudeAI/comments/1pgxckk/claude_cli_deleted_my_entire_home_directory_wiped/) showed Claude CLI silently deleting an entire home directory.

Adding soft instructions to a `CLAUDE.md` or `AGENTS.md` file helps, but those are guidelines the agent can misinterpret or overlook. CC Safety Net is a hard technical constraint instead of a request.

## What it intercepts

CC Safety Net installs into your coding agent and runs before the agent's tool call reaches your machine. It receives the operation the agent is about to perform — a shell command, or a file write, edit, search, or patch — analyzes what that operation would actually do, and then either lets it through or blocks it with a plain-language reason the agent can act on.

The decision is based on intent, not on spelling. `git checkout -b feature` creates a branch and is allowed; `git checkout -- file` discards uncommitted changes and is blocked. Both start with the same two words.

How the interception is wired differs by agent — some run CC Safety Net as a short-lived subprocess, others load it in-process — but you do not configure any of that yourself. The installer sets up the right form for the agent you choose. For the full lifecycle of one tool call, see [How it works](/guides/how-it-works).

## What it does not replace

CC Safety Net complements your agent's own permission rules and its native sandboxing; it does not stand in for either. Deny rules give you quick, user-configurable blocks. Sandboxing gives OS-level filesystem and network containment. CC Safety Net covers the known-destructive git and filesystem operations that a sandbox still permits inside your project and that pattern matching can be tricked into allowing. Running all three together is the intended setup — see [CC Safety Net vs. sandboxing](/guides/vs-sandboxing).

It is also not a complete guarantee. CC Safety Net is a static pre-execution policy gate, so it cannot see inside arbitrary binaries and offers no protection for commands that bypass an installed integration. Read [Known limitations](/guides/known-limitations) before you rely on it.
